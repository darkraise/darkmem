# UI end-to-end audit, 2026-10-05

A full pass over the darkmem web UI on a local stack: setup and sign-in, every route, and the behaviour behind each page, with a screenshot for every finding. 93 findings: 90 are fixed or removed on this branch in 80 commits, each re-checked against the running build with an after-screenshot. None is left open: the 26 that the first round left open were resolved in a second round and verified the same way. The rest are by design or retracted.

**93 findings:** 83 fixed, 7 removed (controls that did nothing), 0 open, 3 by design or retracted. Every finding links its screenshots; images live in [`2026-10-05-ui-e2e-audit/`](2026-10-05-ui-e2e-audit/).

## How it was tested

- **Stack.** FastAPI (one uvicorn worker) on 127.0.0.1:8000 against a local Postgres 16 with pgvector, the vite dev server on 127.0.0.1:3636, and a deterministic OpenAI-compatible mock LLM on 127.0.0.1:11434 serving extraction, classification, 1024-dim embeddings and chat. Production was not touched.
- **Data.** The setup wizard was driven through the UI from an empty database. Then 19 memories across three projects, 3 documents and a work-log workstream were seeded over REST, and two repositories were added: this checkout and a 4-file repo.
- **Crawl.** All 36 routes at 1440×900 on the empty vault, and the 16 routes that show data again once seeded, recording page errors, console errors and failed requests per route.
- **Behaviour.** Four Playwright testers in parallel, one per area: memories and knowledge; documents, notes and work log; chat, code, jobs, activity and usage; settings. Light and dark themes, 390 and 768 px widths, keyboard paths and touch emulation. Every finding is backed by a screenshot the tester looked at.
- **After.** Three verifiers re-ran each finding's steps against the fixed build and captured after-shots. What they found in passing was fixed and shot the same way.
- **Second round.** The 26 items left open were resolved in five parallel lanes (settings and MCP; documents and notes; memories and dashboard; chat; code), merged, and verified again by three agents on the running build. Two gaps they found (S6 in one dialog, O14's row progress) were fixed and re-shot.
- **Limits.** The mock LLM says nothing about ranking quality. Outbound services (Telegram, git remotes, cloud backups) were tested only on their failure paths. M2 needs more than 500 memories, so it is covered by a unit test rather than a screen.

## Verification

- **Backend:** full pytest suite on the final commit: 8,052 passed, 24 skipped, 2 failed; the two were a test counting another test's journal row, fixed in the test and re-run with the 1,724 tests around them, all passing.
- **Frontend:** `tsc -b` clean; vitest 284 files, 2,178 tests passed on the merge, plus the tests added after it; `vite build` succeeds.
- **Final crawl** of 35 routes on the fixed build: 0 page errors, 0 failed requests, 0 console errors. Code Graph is excluded because it stalls on the large repository (O21).
- **Indexing:** a full reindex of the darkmem repository, which failed before O1, finishes: 3,996 files and 17,051 symbols.
- **Not run:** `scripts/gate.sh` as a whole and the repository's own Playwright suite. Two of its specs were edited (`activity-pipeline.spec.ts`, `demo-makes-no-api-calls.spec.ts`) for the removed Activity → Jobs tab.

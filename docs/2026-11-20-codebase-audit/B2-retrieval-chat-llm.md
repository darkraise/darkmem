# B2 — retrieval, chat and the LLM layer

Reviewer findings for the 2026-11-20 audit, as returned. Summary first where the reviewer gave one, then one entry per finding. Index and verification status: `docs/2026-11-20-codebase-audit.md`.

**Counts:** 0 critical, 0 high, 7 medium, 15 low.

**Three most important findings:**
1. **Embedder outage takes down search** (`hybrid_search.py:186-189`, `:231-234`, `pipeline.py:1377-1389`). The query embed runs before the guarded arms, so when Ollama is down every memory-search door fails. The keyword arm, which would still work, never runs.
2. **Chat and knowledge_search ignore three flags memory search honours** (`layer_composition.py:1429-1435`, `:961`, `:319-333`). These are `hybrid_search_enabled`, `reranker_enabled` and the confidence/importance weights on memory rows. Flipping any of them silently splits the doors.
3. **Chat history keeps the wrong end** (`chat.py:802-815`). When the budget runs out, the oldest turns are kept and the newest dropped.

**Dispatch questions:**
- **Inert arms:** `ppr_snapshot` and `relation_embedding_refresh` run hourly without checking their flags, serving only the zero-weight arms (about 1,050 app lines, 1,572 test lines). CLAUDE.md says the dual-level channel is unbuilt, but it is built. `community_injection_enabled` is a UI switch nothing reads.
- **Not inert:** community detection feeds the live Topics tab, so it stays.
- **RRF:** implemented once in `rank_fusion.rrf_fuse`, plus a hand-written copy in `code_query.py` (two places).
- **`layer_composition.py`:** its size is mostly justified. The dead part is the reranker path and a second compose pass run on every request for it.
- **Leases:** correct under cancellation, but one shared HTTP client for the process would remove them entirely.
- **Chat disconnect:** no lease or session leak. Each answer does hold an open transaction for the whole stream, and the usage row for a disconnected stream is probably lost.
- **str vs UUID ids:** no drift at any fusion boundary I traced.

# B3a — fact vault and verification ladder

Reviewer findings for the 2026-11-20 audit, as returned. Summary first where the reviewer gave one, then one entry per finding. Index and verification status: `docs/2026-11-20-codebase-audit.md`.

**Counts:** 0 critical, 1 high, 7 medium, 11 low, plus 4 cost ledgers for the owner (the LLM contradiction scan, the disarmed single-valued arm, the threshold floors/licences/clamps, and the claim-gate fact suppression).

**Top three findings:**
1. **High (plausible): a memory can stay counted as a source after it stops asserting the fact.** The fact-lift job checks the memory's graph under the fact lock only (`backend/app/services/fact_lift.py:511-569`, holding everything until the tick commits). The re-extraction pipeline reads that memory's sources with no lock before withdrawing (`backend/app/services/fact_provenance.py:194-199,277-307`). If the two overlap, the fact keeps a source the new graph no longer supports, and no job removes it. That inflates the distinct-origin count and can wrongly promote a fact.
2. **Medium: the contradiction scan is stuck.** While the judge refuses, it never advances its watermark (`backend/app/services/contradiction_scan.py:847-858`). Every 6 hours it re-reads the same 20 events and writes duplicate "no contradiction" rows to the append-only journal. Even if the judge were qualified, it could handle at most 80 events a day.
3. **Medium: the knowledge-fact `stated_expiry` column has no writer.** The expiry arm runs every 2 minutes and never matches anything (`backend/app/services/verification_recompute.py:696-746`). Separately, `backend/app/services/triple_embeddings.py` (461 lines plus a 647-line test) has no production caller.

**Also medium:**
- The slow reconciliation pass re-journals the same blocked hold on every visit. On a small vault that floods the journal and pushes the original dispute out of the fact's 50-row history (`backend/app/repositories/knowledge_triples.py:1030`).
- The 2-minute recompute's event query has no usable index (`backend/app/services/verification_recompute.py:486-524`).
- Background jobs hold fact row locks for the whole tick, so memory deletes and re-extraction can block or deadlock.

**Sound:** origin counting is consistent everywhere, the strict journal writes are atomic on every path, and the fact-lift vs entity-merge race cannot create a duplicate open fact because the unique index refuses it.

- **B3a-1** (high, bug, plausible).

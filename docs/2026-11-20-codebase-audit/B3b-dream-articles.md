# B3b — dream jobs, articles, review queues, research

Reviewer findings for the 2026-11-20 audit, as returned. Summary first where the reviewer gave one, then one entry per finding. Index and verification status: `docs/2026-11-20-codebase-audit.md`.

**Counts:** 1 high, 6 medium, 13 low.

**Most important findings:**
1. **High — the article synthesis job stops working after one pass.** Its project cursor never wraps back to the start: `article_synthesis.py:933` starts from the previous cursor and `dream_jobs.py:583` saves it unchanged. After the last project, every daily tick visits nothing, new articles and re-synthesis both stop, and the job still reports `ok` while logging nothing. Topic detection's runner has the wrap; this one doesn't, and no test covers it.
2. **Medium — the dream digest's "undoable" flag is wrong for derivation edges.** `dream_digest.py:407-420` rebuilds each action's payload without `pass_key`, so the shared check in `dream_undo.py:520` compares against the near-duplicate block. The UI shows the wrong Undo state, and some clicks get a 409.
3. **Medium — memory_dream re-judges the same pairs every rotation and never remembers a "distinct" verdict** (`memory_dream.py:529-549`, `:1954-1964`). The same top-scoring pairs fill the 25-call budget each time, so lower-scored real duplicates never reach the model.

**Other medium findings:**
- Refine replaces caller-supplied tags (including `project/…`) with the model's list, with no length check (`memory_dream.py:1186`).
- CLAUDE.md says no article may be served as grounded, but the article surfaces gate on `article_claim_gate`, which opens on the minted entailment record (`articles_read.py:158`).
- Article facts and hashes are matched by subject name only, while eligibility is per name and type, so same-name subjects of two types get articles built from one pooled fact set (`article_synthesis.py:211`).

**Answers to your questions:**
- **Jobs doing real work:** fact_lift, verification_recompute, memory_dream and topic_detection. contradiction_scan makes no model calls and repeats the same database work every 6 hours. article_synthesis is inert after its first pass.
- **auto_research** is reachable only through the MCP `research_run` tool. **research_rerun** is live from REST and the Settings UI.
- **The three queue modules** are not one job done three ways: review_ranking is review_queue's single-consumer ordering helper, and the hygiene queue works on memories, not facts.
- **dream_undo all-or-nothing** holds today, but only because its one caller (the HTTP door) rolls back on any error. One savepoint inside `undo()` would remove that obligation from callers.

**Not verified:** production database state for findings 1, 4 and 5 is unknown, because I had no shell access.

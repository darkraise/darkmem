## Findings log

### U1 — Login (`/login`)
- [A] Password input still has no `autocomplete="current-password"` (unchanged from 2026-04-10; Chrome warning repeats twice on render). File: `frontend/src/routes/_guest/login.tsx`.
- [U][B] Empty submit is not blocked. Clicking `Sign In` with both fields empty fires `POST /api/v1/auth/login` with `{"password": ""}` and gets 401, then the UI shows `Invalid password`. That error is both misleading (the problem is not an invalid value, it's a missing one) and noisy (a 401 appears in the devtools console every time). Fix options: add `required` to the input, or early-return client-side with a distinct "Password is required" message.
- [A] The "Invalid password" error paragraph has no `role="alert"` or `aria-live` — screen readers won't announce login failures. The text color is `rgb(239, 67, 67)` at 14 px regular weight, so it's visually red but lacks an alert icon and `font-weight` bump.
- [U] The initial `GET /api/v1/auth/me` always logs a red `401` in the browser console as expected behavior — same finding as the previous run. Either swallow the 401 in the auth-probe path or use a dedicated endpoint that can return 200 with `{authenticated: false}`.
- [D] Header (post-login) still has two circular avatar-like buttons `A` (left of theme) and `U` (right of notifications). Unchanged from 2026-04-10.
- [PASS] Success: `e2e-admin-pw` → redirect to `/` under 500 ms, dashboard renders.
- [PASS] Improvement from last run: the dashboard Recent Memories list now shows **actual content** instead of just the tag `e2e` — previous run flagged blank titles. **Fixed.**

### U2 — Setup (`/setup`)
- [B] **Setup route is reachable on an already-initialized server.** `GET /setup` renders the full form (password + confirm) with no guard. Submitting any password produces the correct `400 Admin password already set` from the backend, but the UI should redirect to `/login` on load instead of letting the user interact with a form that will always fail. Fix: `beforeLoad` on the `/setup` route should check `auth/status` and redirect when `initialized=true`.
- [A] Both password inputs on the setup page also lack `autocomplete="new-password"` (two Chrome warnings on render).
- [U] The 400 shows as red console error again (same pattern as U1's 401 noise).
- [D] Setup error paragraph `Admin password already set` uses the same unstyled-ish red paragraph as U1 (no `role="alert"`, no icon).

### U3 — Global chrome
- [B][D] **Header `A` and `U` avatar buttons are duplicates — both open the same Profile/Settings/Log out menu.** Left-`A` shows an additional "Admin" header row in the menu, right-`U` does not — so they also disagree on content. This is the concrete explanation for the long-standing "two avatar glyphs" observation: one of them should be removed. Fix: either remove the right `U` button entirely, or give one the role of an app/org switcher and the other the role of a user menu with clearly distinct iconography.
- [A] **Command palette (`⌘K`) dialog fails two shadcn a11y checks on every open.** Console errors: `DialogContent requires a DialogTitle for the component to be accessible for screen reader users` and `Missing Description or aria-describedby={undefined} for {DialogContent}`. Both are runtime-level React errors that ship to production users who leave DevTools open. Fix: add a `<DialogTitle>` (can be visually hidden via `VisuallyHidden`) and either `<DialogDescription>` or an `aria-describedby`.
- [U] The command palette (`⌘K`) only shows **Navigation** (13 static entries — one per route). Typing free text like `postgres` does not produce any memory/entity results. Either document this limitation ("⌘K is a nav-only command menu") in the placeholder, or extend it to include a live memory-search section. Placeholder currently reads `Type a command or search...` which over-promises.
- [PASS] `⌘K` opens the palette; Escape closes it; focus returns to the document; keyboard-reachable from the Search button in the header.
- [PASS] Sidebar structure matches the code: 4 groups (`Overview`, `Visualization`, `Code Intelligence`, `System`), 13 links total, active state changes as you navigate.
- [PASS] Theme customizer opens as a popover with `Mode` (Light/Dark/System), `Background` (Solid/Gradient), `Accent Color` (17 colors), `Surface Color` (18 colors), `Surface Style` (Default/Glassmorphism). Switching Light → Dark repaints the entire app including the sidebar, stat cards, charts — no orphan panels. Screenshot: `dashboard-dark.png`.
- [U] The theme customizer does **not** expose the 3 layout modes (`sidebar`, `top-nav`, `stacked`) that `_authenticated.tsx` actually supports via `useLayoutStore`. The layout variants are present in the code but unreachable from the UI. Either expose them in the customizer or delete the dead code.
- [U] **Session was lost when the browser navigated from `about:blank` back to `/`.** The auth store state apparently only lives in memory, not sessionStorage, and any navigation through `about:blank` (which Escape did, unexpectedly) logs the user out. Minor, but worth noting.
- [PASS] Left-`A` "App" label in the sidebar top-left is a decorative brand chip and is **not** the same element as the right header buttons.

darkmem · design doc 14 · visual sub-phase

Making the knowledge vault tell the truth about itself

These mockups realize the honesty-label design language of doc 14 over the screen inventory of doc 13. Every surface here obeys one thesis: an agent or a person reading a fact should see exactly how well-supported it is — never more. The system's ceiling is corroborated ("asserted by K distinct origins"); only a human's mark reaches confirmed; and the word verified appears nowhere. Rendered on the shipped darkraise-ui@3.1.1 token system: indigo accent, slate surface, dark by default.

A

The honesty-label vocabulary

The whole language is a handful of primitives. Two axes stay orthogonal on purpose: the layer chip says what kind of thing a row is (memory, fact, article); the verification badge says how well-supported it is. A fact is L2 and corroborated — never one dressed up as the other.

Status colour roles

Four roles, each mapped onto an existing theme token — never a literal colour. Amber (--chart-4) is reserved for caution and never used for a score arm.

neutral muted
supported accent
caution --chart-4
conflict destructive

No fifth "success green" role exists — green-as-good is the visual synonym of "true," and no rung earns it.

Layer chips

Surface-toned, monospace key, no accent, no status colour. Quiet metadata that classifies without judging — always before the badge, so a row reads "what kind → how supported."

L0 memory L2 fact L3 article

Expansion names the layer in words — "fact — Layer 2 of the vault" — and never says "verified," even here.

Verification badges — the ladder

One composed component, four rung treatments. Colour never carries meaning alone: every badge pairs its token with a semantic icon and a text label, WCAG-AA in both themes. The expansion is doc 12's badge.claim string, shown verbatim or not at all.

candidate raw extracted signal — not yet corroborated; served only when nothing verified fits.
corroborated asserted by 3 distinct origins of kinds [mcp, api], no known contradiction, as of 2026-07-20.
human-ratified asserted by 3 distinct origins of kinds [mcp, api], no known contradiction, as of 2026-07-20, human-ratified.
disputed disputed: 2 origins assert X, 1 origin asserts not-X, as of 2026-07-22.
The human-ratified badge is the only rung a human can mint, so its icon is a person-with-check — a human figure, never a padlock or a bare checkmark. A plain checkmark appears nowhere in the ladder.

Overlay chips

Labels, not rungs. They append after the badge — amber, dashed — and never recolour or replace it, because the backend has not demoted the row.

corroborated under-sourced stale

under-sourced → "origin count dropped below N; will demote if not re-corroborated." stale → "synthesised before the latest verified change."

Lifecycle labels (L0 memory)

Episodic recall is not a claim, so memory rows carry no verification badge — they wear a lifecycle label instead.

L0 memory active
L0 memory superseded → lineage

A terminal superseded article uses this same caution treatment — replacing the rung badge, with a link to the superseding article — rather than becoming a fifth rung.

C

"Why retrieved" — the trace ledger

The trace renders doc 07's payload field-for-field: a ledger, not a story. Every ranking arm is a token-coloured bar with its raw value beside it; a dormant arm shows as inactive, never omitted and never faked as a zero. The caution amber is deliberately absent here — an arm bar can never be mistaken for a warning.

Ledger, not narrative.

No generated "this matched because…" sentence that could drift from the numbers — the panel shows the numbers.

D

Auditing the count · holding a dispute

The badge claims "K distinct origins" — the sources panel is where a person checks that claim, origin by origin. When two sides genuinely conflict, the fact is served disputed, both sides at equal visual weight; the system never picks a winner for you.

Each origin is one row of the count — COUNT(DISTINCT origin_key), never a row count. The human origin is the review decision itself.

Code origins are commit-addressed.

A code@commit mark makes a born-corroborated code fact checkable against the exact revision.

Both sides, equal weight.

A disputed fact is never silently dropped or auto-resolved — it renders the conflict for a human to adjudicate.

E

Review triage — the single human door

Ratification to confirmed is the one power a machine never holds — it lives only on the authenticated UI, never on the unauthenticated MCP surface. The queue is consequence-ranked (retrieval frequency × subject salience), never FIFO, and it is an override the human works, never a gate the system waits on.

One door for confirmed power.

Ratify has no MCP twin — the LAN agent surface must never mint the human's imprimatur. The UI is the door that carries it.

Consequence-ranked, not FIFO.

The facts an agent actually reads most, on the highest-salience subjects, rise first — triage effort follows impact.

Never a read-path gate.

An item stays served-and-labelled in retrieval whatever its queue state; the queue is an override, not a bottleneck.

F

Activity — the durable event stream

Every lifecycle transition journals one append-only events row. The contribution calendar buckets them per UTC day; the timeline is one object's full history. No heavy per-client tables — an event row and, for pushes, a render-watermark config row.

UTC-day buckets.

The calendar index is an immutable AT TIME ZONE 'UTC' cast; the client renders in the viewer's zone knowing the boundary.

Append-only, no POST /events.

A forbid-trigger blocks update/delete; services emit rows. The read API is strictly GET.

Consolidation is observable.

The dream digest surfaces what the background run changed — verification moves, re-syntheses, new disputes — never a silent mutation.

G

Four honest screen states

Every surface designs all four states up front. The rule that matters most is the last one: a monitor for a table that does not yet write shows a labelled staged state — never a fake-populated panel and never one that reads as broken.

empty
No clients connected yet

Connect Claude Code, Cursor, or Codex to start auto-injecting verified context.

loading
error / degraded
Keyword channel is down — showing semantic results only

A degraded channel is a caution banner over surviving results — never an empty list that reads as "nothing found."

staged (invariant 23) backend not yet writing
Dream-run monitor

Ships when the consolidation job family lands. Rendering an empty panel now would claim a capability that isn't built — so it announces itself as staged instead.

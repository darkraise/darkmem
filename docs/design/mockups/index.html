3 — Motion & accessibility (doc 14 §7, §8)

Motion — a closed list of signal uses, nothing decorative
  • Live-feed row entrance (a new event arriving)
  • Pipeline stepper's phase advance
  • Badge rung-change transition — a single subtle emphasis pulse when a fact's rung changes under a live update (pulse-glow keyframe)
  • The existing particle/aurora backdrop, reserved for the unauthenticated threshold surfaces (login / setup)
Accessibility — part of the encoding, not a pass afterwards
  • Colour never carries meaning alone — every state pairs a token colour with an icon and a text label; fill style + border style + icon differ pairwise even with colour removed
  • Contrast of label text against its chip background meets WCAG AA at text-sm in both modes — checkable once per theme via the token mapping, not per screen
  • Badges are focusable; the expansion opens on focus as well as hover (Popover for the full origin list — a tooltip cannot hold interactive content)
  • Counts are always printed beside a bar or ramp cell, never shading alone (calendar heatmap, trace-panel arms)
  • All motion honours prefers-reduced-motion
Every non-motion, non-a11y note above is restated inline on the vocabulary examples below rather than collected separately — an annotation next to a treatment is what makes the rule checkable against the pixels, not a rule stated once and trusted to hold.

The project switcher and the context chip are two distinct controls, never one. Registration & safety

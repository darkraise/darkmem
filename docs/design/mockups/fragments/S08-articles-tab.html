S08 — Knowledge: Articles tab, populated (hero, both themes)

Exactly one live article per (project, subject_key). The partial-unique constraint (WHERE status <> 'superseded', doc 04 §8.8) means this list can never show two current drafts competing for the same subject — a subject either has one live row here, sitting in the ladder's corroborated/confirmed rungs, or no row at all. A subject's history is not deleted, only chained: each live row's prior versions stay reachable through its superseded_by lineage (doc 09 §4.4), not by cluttering the list with duplicate rows per subject — see the second row's lineage link below.
Row composition. Each row reuses the shared verification badge and layer chip verbatim from C01/C02 (never re-derived), adds the subject + a short excerpt of the synthesised prose (new S08 layout — full grounded prose with inline claim citations is S09's surface, not rendered here), and the claim-support coverage readout — the article's confidence, labelled by what it actually measures (entailed claims / total claims, doc 09 §4.3), never a vague unlabelled score. A row whose supporting verified fact set changed since synthesis carries the stale overlay (.overlay-stale, appended after the badge, never replacing it — third row below).
What never appears in this list. A disputed or ungrounded article (review_state='open') is withheld from this corroborated view entirely and routed to Knowledge → Review instead (doc 09 §4.3/§4.4) — this list only ever shows rows that cleared the claim-support coverage threshold.

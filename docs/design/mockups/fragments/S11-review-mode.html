S11 — Knowledge → Review mode (populated, hero)

Review mode is one of two modes of one shared shell. /knowledge/review is a single triage surface with a mode toggle — Review (this board) adjudicates truth, Hygiene (S12) curates housekeeping — not two routes; they read different backend review_state/status sets but are the same human activity, "triage a queue with actions" (doc 13 §6.2, doc 08 §6). Review mode renders review_state='open' rows: disputed facts shown with both conflicting sides, no picked winner, under-sourced facts held in demotion hysteresis, and ungrounded/low-confidence articles. The queue is consequence-ranked, never FIFO — retrieval frequency and subject salience order it, shown on each row rather than implied (doc 14 §6) — and every item stays served labelled in retrieval regardless of its queue state; review is a human override the queue holds open, never a gate the read path waits on (doc 08 §6). Both themes shown as the hero.

S11 — Ratify to human-ratified (AlertDialog, the strongest confirmation)

Ratify-to-confirmed is the single most consequential button in the product — the machine's ceiling is corroborated; only a human ratifying reaches confirmed, and that ratification writes a human-kind fact_source (who / when / what-was-shown), so a later re-extraction that withdraws every memory source still leaves this one and the fact survives (doc 08 §4.4). It therefore gets the language's strongest treatment: a solid accent button, the person-check glyph, and an AlertDialog restating the consequence before it commits (doc 14 §6). This action is authenticated REST/UI only — POST /api/v1/knowledge/facts/{id}/ratify (or /knowledge/articles/{id}/ratify) — and is never exposed over the unauthenticated MCP surface (doc 12 §3, doc 08 §4.4): no MCP tool can reach confirmed. Rendered once, default theme, since the shared toggle guarantees parity.

S11 — Review mode (empty, healthy)

Honesty rule: this empty state is reassurance, not absence. An empty review queue means the queue is caught up, not that nothing was ever disputed — the copy says so plainly (doc 13 §6.2, doc 14 §5). The mode toggle stays visible: the shell itself is not empty, only this mode's queue is.

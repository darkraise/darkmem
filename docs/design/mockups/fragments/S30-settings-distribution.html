S30 — Settings · Distribution

The Distribution tab of Settings (doc 13 §6.5, doc 15): connect status per client (Claude Code, Cursor, Codex CLI, Cline), per-target managed-block configuration (the marker-bounded block written into each tool's native session-context file, doc 15 §3.2), the inject content policy and token budget (what gets injected and under what config-row budget, doc 15 §3.4), the curb control (the human sees and curbs push — never a silent context swap, doc 01 F10), the inject log (the durable event_type=inject record, doc 15 §7), the render watermark (a config row, not a table, doc 04 §7), and labels-survive-injection visibility — a corroborated fact is pushed into a tool's context still labelled corroborated, a superseded memory still labelled superseded. Almost everything this board renders is target-new (doc 15 §1's scaffolding-honesty note): the pull door (memory_search over /mcp) exists today, but DistributionService, auto-inject, and the managed-block writer are all target work.

Distribution — empty (no clients connected)

Honesty rule: empty says why, and offers the fix. A fresh install has run no onboarding command yet, so no client's MCP config has been written and no push has ever fired — the empty state names that cause and surfaces the exact one-command fix (doc 15 §5) rather than a bare blank.

Distribution — error

Honesty rule: error ≠ empty list. When the render-watermark config rows or the events read behind the inject log fails, the board raises a named error rather than returning zero rows indistinguishable from the genuine no-clients empty state (invariant 14) — retry stays offered, and each connected client's own push keeps running server-side even while this board cannot display it (the same "the mechanism is unaffected by the display failing" framing S21 uses for the job registry).

Inject content policy & token budget

L2 · fact → L3 · article → L0 · summary → fill truth-first until the budget is spent, then stop (top-K, stated in the block header — not silent degradation)
inject_token_budget 2,000 tokens config row, per-target tunable — Codex CLI overrides to 1,200 below
refresh cadence session-start one F3 read + one idempotent write per session; watch mode is a deferred, config-gated Phase-4 enhancement
cold-start fallback candidates, labelled served only when nothing corroborated/confirmed fits the budget yet
codex-cli override inject_token_budget = 1,200 tokens a smaller per-target budget, tuned for AGENTS.md's terser convention — the adapter registry and the budget are both config rows, never hard-coded (convention 9)

inject_curbed is a target-new addition to doc 04 §8.1's closed event_type vocabulary — edited into the taxonomy before any code writes it, never bypassed with a free-form value (doc 15 §7). Each row records that the server selected and returned N items for a target; it is not a receipt that the client's file was actually written — an honest limit of the pull-then-write model, stated rather than implied away.

Neither item is relabelled on the way into the tool: a corroborated fact keeps its full badge claim, and a superseded memory keeps its amber lifecycle label rather than being silently promoted to active or dropped (doc 13 §6.5, doc 15 §3.4, invariant 14). The .badge/.layer-chip markup here is composed verbatim from C01/C02, not re-derived.

Render watermark — a config row, not a table

distribution:watermark:claude-code
{ items: 8, delivered: 2026-07-24T14:12:03Z, project: darkmem }
distribution:watermark:cursor
{ items: 6, delivered: 2026-07-24T14:10:41Z, project: darkmem }
distribution:watermark:codex-cli
{ items: 0, delivered: 2026-07-24T13:58:12Z, project: darkmem, note: curbed }
One config row per target (doc 04 §7) — no per-client heavy table, no queue, no broker (invariant 1). Used only for idempotent diffing on the next inject cycle and to render "last injected T, N items" here; it is the server's best knowledge of the last delivered set, not a proof the file was rewritten (doc 15 §7).

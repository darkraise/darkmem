S25 — Settings · Flags

The feature-flags/tunables tab of the flattened Settings IA (doc 13 §7): the seven rank_fusion_factor / RRF-list / context-boost w_* ranking-arm weights (doc 04 §9, doc 07 §3/§6/§11), the three graph-augmentation *_enabled flags (doc 07 §4/§11), the corroboration N promotion gate with its diversity/time rule (doc 08 §4.1), and a job-cadence summary (doc 02 §5.3). Every value here is a config row read through get_feature_flags_dict's merge-over-coded-defaults (5-second TTL single-flight cache) — nothing on this screen is computed, only read and written.

Flags — populated (hero, both themes)

Invariant 23, read into this screen: a w_* arm defaulting to 0 renders inactive — the built-but-unspent signal, never omitted, never implied to be "off entirely." Raising it above zero is a deliberate, measured activation, tuned against the retrieval harness (doc 17, convention 9), never flipped by intuition and never a silent default. Below, w_conf (via confidence_rank_gamma) and w_dual are shown active (measured, non-zero) on this instance, while w_importance, w_heat, w_recency, and w_ppr remain inactive at their coded default of 0 — the same live instance and weights snapshot as the S03 "why retrieved" trace, so this screen is the editing surface for exactly the arms that trace panel renders as dormant vs spent.

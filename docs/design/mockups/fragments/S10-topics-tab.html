No verification badge on this tab (doc 09 §3.3). A community and a pin suggestion are organizational views of what memory contains — the same footing as memory_overview — never a verified claim, so neither card below composes .badge or .layer-chip; those belong to the Facts/Articles tabs (doc 13 §5.1/§5.2).
Community ids churn — nominations reference by label, never by id (doc 09 §3.4, doc 06 §7). memory_communities is delete-and-rewritten on every detection run, so a community id cached from a previous page load can point at nothing on the next. Every card below — and every events row an accept/dismiss journals — keys on the stable dominant-entity label ("Hybrid search & RRF weighting" below), never on the row's current id.
Accept pins a subject; it never auto-creates an article (doc 09 §3.4/§4.1). Accept writes a pinned subject only, making it eligible for synthesis on the next salience/synthesis pass — the article itself still has to be grounded from verified facts. Dismiss is recorded against the subject so later detection diffs suppress the suggestion, not merely hidden client-side. A nomination only fires once its subject already anchors a floor of non-disputed corroborated/confirmed facts — a human is never asked to pin a subject that could not yet be grounded.

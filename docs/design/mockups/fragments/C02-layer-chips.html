C02 — Layer chip reference: L0 · L2 · L3, and the L1 that never renders

Formalises doc 14 §3.3's layer chip as its own reusable reference. The layer chip is an orthogonal axis, styled orthogonally from the verification badge — surface-toned .layer-chip using only --card/--border tokens, monospace layer key, no accent, no status colour — so "L2" is never misread as a trust level. It always precedes the verification badge in a row's label cluster (doc 13 §4's layer row field: L0 / L2 / L3, L1 never directly served).
L0 · memory Used by: Memories search & detail, Chat context panel, the retrieval trace's per-row cluster, and the nested row under a fact it supports (see below). token role: surface-toned --card / --border — no accent, no status colour expansion — "memory — Layer 0 of the vault"
L2 · fact Used by: Knowledge → Facts tab & detail, the Review tab (disputed / under-sourced facts), and search / retrieval trace rows. token role: surface-toned --card / --border — no accent, no status colour expansion — "fact — Layer 2 of the vault"
L3 · article Used by: Knowledge → Articles tab & detail, and search / retrieval trace rows. token role: surface-toned --card / --border — no accent, no status colour expansion — "article — Layer 3 of the vault"
L0 · memory Used by: Memories search & detail, Chat context panel, the retrieval trace's per-row cluster, and the nested row under a fact it supports (see below). token role: surface-toned --card / --border — no accent, no status colour expansion — "memory — Layer 0 of the vault"

A layer chip classifies, never asserts standing (doc 14 §3.3): an L2 fact may still be a candidate on the verification ladder, or a disputed one — the layer says "what kind of thing," the badge says "how well supported," and the reading order in a label cluster is always layer chip first, badge second.
L1 · candidate graph Not a live chip variant — L1 is never directly served. The row-level layer field (doc 13 §4) only ever takes L0 / L2 / L3; there is no served row for a layer chip to label L1 with. L1 is the pre-corroboration extraction graph, and it is rendered elsewhere — as node/edge structure in the Memory Graph explorer — never as a labelled row in a result list or trace panel. no expansion string — there is nothing to classify a served row as, because no served row is ever L1
Rendered here as a dashed, ghosted placeholder deliberately unlike the three live chips above, so a reviewer sees what is absent from a row's label cluster rather than assuming L1 was forgotten.

L0 · memory "set COOKIE_SECURE=false for plain-HTTP LAN deploys" — memory, 2026-06-09 grouping.relation = "supports fact F"
The grouping-under-fact collapse (doc 13 §4, doc 07 §5): a memory that supports a fact renders nested under it, indented, rather than as a third unrelated hit beside it — so a memory, the fact it supports, and an article citing that fact never read as three unrelated rows. The relation string travels verbatim from grouping.relation; note the L0 memory row carries no badge (a memory's verification_status is always null — it has a lifecycle label instead, not a rung), while the L2 fact it supports carries the full ladder.

S01 — Dashboard

The daily home screen (doc 13 §4): the contribution calendar (a GitHub-style UTC-day heatmap whose intensity ramp derives from --primary, doc 14 §6/§9), the live feed (the transient /ws stream), four stat tiles, and cold-start hints. The second stat tile counts the vault's corroborated rung by name — never labelled "verified" — per the global constraint on avoiding a status claim. Four states below: empty (fresh install), loading, error (retry + last-known counts), and populated (the hero, both themes).

Dashboard — empty (fresh install)

Honesty rule: empty is a fresh install, not a broken grid. The calendar still renders its full UTC-day grid — every cell honestly at level 0 — rather than collapsing to a blank panel; a first-capture call-to-action sits alongside it so a new install reads as "young," never "broken" (doc 13 §4: "the calendar is blank and a first-capture / onboarding call-to-action shows, not a broken grid").

Dashboard — error (retry, last-known counts)

Dashboard — populated (hero, both themes)

Modules: stat tiles, the contribution calendar, and the live feed (doc 13 §4). The calendar's cells derive their fill from hsl(var(--primary) / alpha) composited over the theme's own card colour — the same alpha ramp reads pale-to-saturated in light mode and dark-to-luminous in dark mode purely from that compositing, satisfying the "mode-aware direction" requirement without a per-mode override (doc 14 §9: "a runtime lightness/alpha ramp off primary… direction mode-aware"). Every cell's title/aria-label prints its count, so intensity is never the sole carrier of the number (doc 14 §6). The second tile reads "Corroborated facts" — the vault's rung name, never "verified" — per the global constraint. The feed's third row shows a verification-transition event using the shared .badge rungs, reusing doc 14 §3's merge/person-check glyphs rather than inventing a new one.

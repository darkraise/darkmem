Grouped, reversible ledger entries (doc 14 §6, doc 08 §7). Each row carries its action-type chip, its object link, a compact before→after rendering for status/pointer changes, and its undo affordance. The register is deliberately calm — neutral chips for routine dream actions; the caution role (amber) appears only on a row that touched a disputed object or demoted a rung, never on the group as a whole, since one group can mix routine and caution-worthy entries. Undo is a standard outline button, not destructive-red — every inverse is a journaled restore, not a deletion — and undo is an authenticated curation action (doc 08 §7, doc 12), same auth boundary as ratify.
Seven action types, five summary tiles. The cycle-summary strip above them matches doc 13 §6.3's five named counts exactly (superseded / refined / promoted–demoted / disputed / edges derived) — ratification is counted within the promoted figure (a human ratifying is a promotion to confirmed) but still gets its own group below, since its inverse differs: withdrawing a human-kind fact_source, not restoring a prior verification_status. Invalidation and re-synthesis are rarer this cycle (one each) and don't earn a dedicated summary tile, but every action type still gets its own grouped section and undo, per doc 08 §7's table of seven reversible actions.

S23 — Undo a batch (AlertDialog, since it spans many objects)

Per-batch undo confirms through AlertDialog; per-action undo does not (doc 14 §6). A single action's undo is a low-consequence, fully-reversible restore of one object, so the outline button commits directly. A batch spans many objects at once, so it gets the stronger confirmation treatment — listing exactly what will be restored — before it commits. Undo remains a standard outline/primary treatment, not destructive-red: every inverse here is a journaled restore, never a deletion (doc 08 §7). Rendered once, default theme, since the shared toggle guarantees parity.

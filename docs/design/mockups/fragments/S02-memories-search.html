S02 — Memories: populated (hero, both themes)

The two scope controls are distinct, never conflated (Global Constraints; doc 13 §3). The project scope pill mirrors the global project switcher — it sets project in every query key on this screen (invariant 14's isolation boundary). The context chip is a separate, optional control declaring the session applies_when (doc 07 §6) — it boosts/labels/ conflict-excludes rows, it does not scope which project's rows are visible. Conflating the two would silently exclude dev-only facts the moment someone switched to a project named "production."
The "supports fact F" nesting (doc 07 §5, doc 13 §4). A memory that is a source of a returned fact renders nested and indented under that fact, not as a third unrelated row — this is what "never triple-counted" means in practice. A disputed fact collapses to its badge plus a one-line both-sides summary in list context (doc 14 §3.5); the full split panel lives on the fact's own detail view (S07). An article's confidence is labelled claim-support coverage (doc 13 §5.2), never a vague score. Per-row "why retrieved" score breakdowns are S03's surface, not rendered here.

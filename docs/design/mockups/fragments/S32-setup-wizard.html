S32 — Auth: trust-on-first-use setup wizard

The _guest-layout counterpart to S31's login board (doc 13 §2/§3): a four-step wizard — password → LLM → repo path → finish — served at /setup and gated end-to-end by require_uninitialized. Every wizard endpoint (including the two filesystem-browse endpoints step 3 uses) 403s the moment the admin_password_hash config row exists (doc 18 §3): the first party to finish the wizard on a fresh box owns it, and there is no pre-shared SETUP_SECRET to reintroduce — that secret-distribution problem was judged strictly worse than the bounded TOFU race it would close. The board renders the ceremonial register doc 14 §2 reserves for unauthenticated threshold surfaces — a glass card over a static stand-in for the particle/ aurora backdrop — matching S31's register rather than the app's calm instrumental default.

S32 — step 1 of 4: admin password (hero, both themes)

Trust-on-first-use, not a shared secret. /api/v1/setup/* is gated only by require_uninitialized; there is no pre-shared setup key to distribute before the box has an owner. The password the visitor sets here is the claim — whoever completes this step first owns the box, and the wizard closes to every later visitor (S32-error below). Rendered as the hero in both themes; the remaining three steps and the loading/error states render once, in the default theme, since the shared toggle in mockup.css/theme.css already guarantees theme parity.

S32 — state: error (setup window already closed)

Honesty rule: the TOFU race is named, never disguised as a generic failure. Every /api/v1/setup/* call — including this one — 403s the instant the admin_password_hash config row exists (doc 18 §3's "setup takeover" row): the LAN boundary plus the minutes between first boot and wizard completion bound the race window, and once someone closes it the wizard has nothing left to offer a later visitor except a pointer to /login. This is not a network/server error — the request succeeded and was correctly refused.

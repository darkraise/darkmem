S17 — Memory Graph: empty, no graph yet

Scope of this fragment. Realises doc 13 §4.1's Memory Graph inventory (the entity-graph explorer, exists today at /unified-graph): the force / tree / community layout switcher, search over entities & relations, and the community navigator. It renders the L1 candidate graph — the pre-corroboration entities and relations a memory's extraction phase writes (doc 13 §4, C02) — plus the emergent topics a Leiden clustering pass detects over that graph (doc 06 §7). A community is never rendered as a node in this canvas (invariant 5); the populated board below shows how the navigator keeps that distinction visible.
Critical — built-but-unspent (invariant 23, doc 13 §4.1, doc 07 §4). This explorer is a browsing surface only. The PPR ranked-list signal, the dual-level relation channel, and community-report injection — the three ways doc 07 §4 describes "spending" this graph on retrieval — are target-new: every gating flag (ppr_enabled, dual_level_enabled, community_injection_enabled) defaults off, so Memories search stays byte-equivalent to today's vector+FTS hybrid regardless of what anyone browses here. Opening, clustering, or searching this graph does not change what search returns — that wiring is doc 07 §4's target, not shipped behaviour, and this board must not read as if it already is.
Honesty rule — empty says why (doc 14 §5). A project with no captured memories has no extracted entities or relations, so there is nothing to lay out and nothing for the clustering pass to group. The chrome — search field, layout switcher, community navigator — stays visible and inert rather than vanishing, so the screen reads as "not fed yet," never as broken.

S17 — Memory Graph: populated (hero, both themes)

Critical — browsing this graph is not what ranks search today (invariant 23, doc 07 §4). Every node, edge, and halo below is real, rendered L1/topic structure — but clicking through it, running a search in the box above, or switching layouts changes only what this screen shows, never what Memories search returns. PPR seeding, the dual-level relation channel, and community-report injection are the target-new mechanisms that would spend this graph on ranking (doc 07 §4); until an operator turns on ppr_enabled / dual_level_enabled / community_injection_enabled, this explorer stays a read-only window onto structure retrieval does not yet consult.
Communities render as halos, never as nodes (invariant 5). The three tinted, dashed ellipses behind the clusters are the topic communities the navigator lists at right — background context for a set of entities, not an extra node a user could click as if it were itself an extracted entity. Each halo's token colour matches its navigator row's swatch so the two views read as one structure, while a node's fill colour is a completely separate axis (entity type) — colour never carries a single meaning alone (doc 14 §3).
L1 carries no verification rung. These are pre-corroboration entities/relations straight from extraction (doc 13 §4, C02's "L1 is never directly served" note) — nodes here intentionally carry no candidate/corroborated/disputed rung badge; that ladder applies to L2 facts, which the Knowledge vault renders, not to this raw graph.

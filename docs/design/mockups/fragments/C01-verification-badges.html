C01 — Verification badge matrix

The most-reused honesty component. Realises doc 14 §3.1 (status colour roles), §3.2 (the verification-badge ladder), §3.3 (layer chip, used here only as context), and §3.4 (overlay chips). This is the exact .badge / .overlay-* / .badge-code markup that every other board rendering an L2 fact or L3 article (S05 supersession lineage, S06/S07 Knowledge, S09 articles, S11 review mode, the trace panel in S03) composes verbatim rather than re-deriving. One matrix board, all variants side by side, in both themes.

1 — The four ladder rungs

candidate served labelled, below the ladder's supported rungs — "extracted signal, not yet corroborated — served labelled"
corroborated asserted by 3 distinct origins of kinds [code, memory], no known contradiction, as of 2026-07-20
K (here 3) binds to COUNT(DISTINCT origin_key) from fact_sources — never a row count. Two agents re-saving the same claim, or one repo re-derived across many commits, are one origin, not two; when origin identity is unknown the count undercounts rather than manufacturing agreement.
disputed: 2 origins assert X, 1 origin asserts not-X, as of T
disputed asserts X — the reranker is enabled by default in production 2 origins · kinds [memory, code]
vs
disputed asserts not-X — the reranker is opt-in per profile, disabled by default 1 origin · kind [human]
human-ratified asserted by 4 distinct origins of kinds [memory, code, human], no known contradiction, as of 2026-07-20, human-ratified — ratified by q.tran, 2026-07-21
Visible chip text is the rung name; confirmed always renders as "human-ratified" — never the word "verified", and never "confirmed" as visible text — with the claim string carrying the trailing ", human-ratified" suffix. Disputed shows both sides at strictly equal weight, earlier-asserted side first, no comparative bar, no picked winner (doc 14 §3.5).

2 — Overlay chips: riding a still-corroborated row, never a fifth rung

corroborated under-sourced origin count dropped below N; will demote if not re-corroborated
corroborated stale synthesised before the latest verified change
Both overlays append after the badge and never recolour, restyle, or replace it — the row is still corroborated, claim string intact, while the demotion hysteresis runs. The CHECK constraint stays exactly candidate | corroborated | disputed | confirmed; under-sourced and stale are label overlays on that rung, never a fifth ladder value (doc 14 §3.4).

Two non-rung treatments, both caution-role (--warning token — the same family as the overlay chips and the app's existing lifecycle amber, migrated off its hardcoded amber-500 literal per doc 14 §3.1): an L0 memory carries no verification badge, ever, only its lifecycle label; a terminal-superseded L3 article shows a badge that replaces the rung rather than decorating it, reachable via the lineage link. The CHECK constraint stays exactly candidate | corroborated | disputed | confirmed either way — neither treatment is a fifth rung (doc 14 §3.2).

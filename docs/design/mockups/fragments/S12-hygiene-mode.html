S12 — Knowledge: Hygiene mode, populated (hero, both themes)

Consequence-ranked, served-labelled, never a gate (doc 13 §6.2, doc 08 §6). Like Review, this queue is ranked by retrieval frequency and subject salience, never FIFO or insertion order — each row's muted why ranked here line makes that ranking visible instead of implied (doc 14 §6). Sitting in this queue changes nothing about how a row serves: a low-confidence memory keeps returning from search exactly as it does today, and a superseded chain keeps rendering its lineage link — hygiene is housekeeping the human works, never a bottleneck the read path waits on.
Four categories map onto the four named bulk actions (doc 08 §6, doc 08 §9). Candidate duplicates (associative-edge pairs dreaming flagged without a correction, doc 08 §9) get confirm dedup or, when one memory actually corrects the other rather than merely restating it, supersede instead — dreaming never hard-merges or deletes a memory itself. Low-confidence memories get set a TTL or prune; expiring-soon rows get extend the TTL or let expire — a row already on its way out is reprieved or allowed to lapse, never bulk-pruned outright. Superseded lineage gets prune to compact old chain links — pruning a memory another row still points superseded_by at first demotes that dependent to deprecated with the pointer cleared, so the chk_superseded_has_pointer constraint holds throughout the batch rather than aborting it.

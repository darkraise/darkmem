S19 — Activity: live feed

The Activity screen's live view (doc 13 §2.1/§6.1): the transient /ws stream while this view stays open, rendered as an ordered feed list, plus the dispute-toast still-frame — the one transient toast that carries honesty content, a fact.verified dispute alert (doc 13 §2.1, spec §6). The toast's motion (slide-in, auto-dismiss timer) is explicitly out of scope for this deliverable; only the frozen frame is authored. Four states below for the feed itself: empty, loading, error, populated (hero, both themes); the still-frame is a fifth, dedicated board.

Activity — live feed — empty

Honesty rule: empty says why, scoped to what a transient stream can honestly claim. This is not the vault's cold-start register (doc 13 §5.1) — the project may have years of history. The feed only ever shows what has streamed over /ws since this view mounted, so its empty copy says exactly that: nothing has arrived in this open session, not "no activity ever" (doc 14 §5's three registers, applied to a fourth, session-scoped case this screen introduces).

Activity — live feed — loading

Loading is the initial /ws handshake, not a spinner replacing the page (doc 14 §5): skeleton rows mirror the exact chip / badge / text / time slots the populated board below fills in, so the surface never jumps once the socket connects and the first events arrive.

Activity — live feed — error

Honesty rule: error ≠ empty list, and a lost socket is never the only record. When reconnection is exhausted, the panel raises a named disconnect with a manual retry rather than quietly reverting to an empty list — and the last-known events stay visible, dimmed, because a WebSocket message lost on disconnect must never be the sole record of what happened (doc 13 §2.1: "a WebSocket message is lost on a disconnect, so it may never be the *only* record of a lifecycle transition"). The durable events substrate backs the timeline and calendar regardless of this socket's state.

Activity — dispute-toast still-frame

The one transient toast that carries honesty content, frozen. Per the WebSocket-to-invalidation mapping (doc 13 §2.1), several events fire a toast (a finished retry batch, a terminal repo state, a finished dream cycle) but those are operational notices; the fact.verified dispute is the only one whose toast body itself states an epistemic claim, so it is the one rendered here. The toast collapses to the badge plus a one-line both-sides summary — the same collapse rule the split-panel detail view uses in list contexts (doc 14 §3.5) — so a fast-moving alert can never say something the detail view (S07/C01) later contradicts. Motion is out of scope (spec §6): the slide-in entrance, the auto-dismiss timer, and the pulse-glow emphasis this triggers on the live feed row above (doc 14 §7) are not depicted — only this single frozen frame, positioned where the toast stack renders over the open view.

Repositories — stale (fail-stale banner, T1)

Honesty rule: fail-stale, not fail-empty. A pipeline exception no longer wipes the repo graph (the old behaviour was _delete_all_repo_data on any exception, which could wipe-and-error loop). The last-good graph stays in place, labelled stale, and every code tool (code_search, code_symbol, code_context, …) keeps serving it — degraded honesty, never an emptied graph (doc 10 §3, invariant 14).
payments-service stale last-good HEAD 4b7e120
Last index failed — serving the last-good graph, marked stale Cause: an unhandled exception during phase 09 (community detection) — the Leiden partitioning step timed out. The run failed before reaching phase 14, and nothing was deleted. The graph indexed 2026-07-19 14:02 UTC (HEAD 4b7e120) is still served to every code tool, labelled stale, until the next run succeeds.
auto_sync will also retry on the next scheduled sync — the stale label clears automatically the moment a run succeeds.

Repositories — error (clone/index failure)

Honesty rule: the failure message is surfaced, not summarised away. Repeated auto_sync failures disable sync and record the raw cause in pipeline_failures (per-repo, doc 10 §3); this is distinct from the stale case above — here indexing never completed even once for the current HEAD attempt, so there is no fresher graph being withheld, only a named blocker and a manual way past it.
internal-tools-cli error auto_sync disabled

Reindex dialog — the three toggles

POST /repos/{id}/reindex accepts exactly {full, enrich_symbols, generate_wiki}, all default false (doc 10 §8). Structural indexing (the symbol/edge graph, communities, processes, chunk embeddings) always runs regardless of these toggles — they only gate the two LLM-cost-heavy phases (13, 14) and whether the diff is discarded in favour of a full rebuild.
Reindex — darkmem-core-backend current HEAD e91a3f2 · last indexed 2026-07-24 09:12 UTC
full Rebuild the entire repo graph from scratch, ignoring last_indexed_commit. Off runs the incremental diff (changed files only since the last indexed HEAD).
enrich_symbols Drain the pending-symbol LLM-summary backlog inline during this run, bounded and scoped to this repo. Off leaves symbols draining lazily via the code_enrichment background job.
generate_wiki Generate the LLM wiki over the graph after this run completes. GET /code/wiki is read-only and never triggers generation on its own — this toggle is the only way a wiki gets built.

Auto-provision registration state (F11)

Execution is entirely Tier C, never on the capture path (doc 10 §5). Capture only resolves and validates the hint against the allowlist gate (doc 18) and queues F11; the clone and first index run off the hot path. The resulting Repository row is a many-to-many project_repositories association over one shared repo — two projects referencing the same remote own the same graph, not private copies.

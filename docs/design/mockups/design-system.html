The system the interface is built from

This is darkmem's real design language: darkraise-ui@3.1.2 configured with accent indigo, surface slate, preset default, mode dark. Every token here is the exact value the package's generateTokens() emits — pulled from the installed package, not hand-picked — and the components are drawn to the shipped dr-* anatomy. Switch the mode and accent above to see the same system re-theme live.

Theme system 11 axes · 4 exposed, 5 locked

darkraise-ui themes along eleven axes. darkmem pins all of them in theme.config.ts and exposes only four to the in-app switcher; the rest are locked to keep the product visually coherent. Color tokens are computed from the accent and surface scales at runtime; the other axes are pure CSS.

Locked axes are also scrubbed from every persistence channel, so a value saved before an axis was hidden can never stick (theme.config.ts · lib/theme-persistence.ts).

Color roles semantic, not palette

Tokens are semantic roles, consumed as hsl(var(--role)). Never reach for indigo-500 or a hex — derive from the role so the accent and surface switchers keep working. The one exception: --chart-1..5 ship pre-wrapped as hsl(...).

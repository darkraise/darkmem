## 1. The §2 derivations — both verified correct, one framing defect

**(a) Mod-20 impossibility — re-derived, correct.** 0.95 = 19/20 with gcd(19,20) = 1, so
19n/20 is an integer iff n ≡ 0 (mod 20). N ≡ 0 and 55 + N ≡ 0 (mod 20) → N ≡ 0 and
N ≡ 5: no solution. Verified against the real file: contacted contradicted = 55,
never-contacted = 25, pooled = 80 (recomputed from `gold.json`, sha `800d4d91…`
confirmed).

Framing defect (Minor, M4 below): the proof's premise "pooled is 55 + N, since …
contact is a historical fact that cannot be undone" holds only for growth-only routes.
The plan's own remedy then retires contacted pairs, making pooled = C + N with C = 40.
The proof is right *as an impossibility of growth alone*; the recorded version should say
so, or the ratified record carries a proof whose stated premise the same document
violates. The full statement: growth-only is impossible; therefore some retirement is
necessary; C ≡ 0 (mod 20), N ≡ 0 (mod 20), C + N ≤ the resample cap, minimal
disturbance → C = 40, N = 40, pooled 80 unchanged.

**(b) The resample cap — verified in code, correct.** `resample_draw.draw` raises when
the contradicted census exceeds n (`RESAMPLE_N = 93`, ratified; duplicated deliberately
in `judge_qualification.py`, test-asserted equal). Growing pooled to 95 overruns it.
80 is the largest multiple of 20 ≤ 93. One nit: the T2.110 History line the plan cites —
"the one multiple of 20 in (55, 93]" — is arithmetically wrong (60 also qualifies);
harmless here since pooled stays 80, but do not propagate the phrasing into the new
ledger entry.

**However: the §2 table is only coherent under one reading of the never-contacted
boundary, and the plan's own step 8 takes the other one.** See C1. This is the plan's
central defect.

## 3. The §5 open question — the plan's recommendation is right; take option 1

**Author 66 pairs (15 contradicted + 51 companions), not 15.** The plan's base-rate
claim verifies: recall's denominator is the gold-contradicted census alone, and per-pair
judgments are independent (one call per pair; confirmed in the cache's per-pair records),
so companion count cannot move recall. Precision moves with the mass of FP
opportunities: at option 2 the subset sits at 40/125 = 32% contradicted, inflating its
precision against every prior round measured near 22.7% and against pooled — the fresh
subset would become the *easier* precision surface, which is backwards. Option 1's
arithmetic is exact, not approximate: 25/110 = 40/176 = 5/22 identically, so the plan's
"~66 / ~51" is exactly **66 and 51** — state the exact numbers. The pooled drift to
80/402 = 19.9% errs strict on a floor with large headroom (measured 0.9012 vs 0.70);
record it as the plan says. Floors survive worst-case: even if all 15 retirements hit
`l2-fact` pairs and all 66 new pairs are hand-authored, 220/402 = 54.7% ≥ 50%, and
402 ≥ 200.

**Requirement attached (I7):** option 1's 51 companions currently have *no* mechanical
derivation — no slice quota, no verdict quota. A contaminated controller free to choose
the companion composition could shift FP opportunities between slices. Derive the
51-pair composition by the same largest-remainder machinery from a stated input
population (the never-contacted subset's existing non-contradicted slice×verdict
distribution is the natural one) before any authoring dispatch.

## 4. Critical defects

`never_contacted_pairs` filters `p["id"] >= NEVER_CONTACTED_FIRST_ID`
(`judge_qualification.py:309–323`) — the subset is open-ended upward, so new pairs
eg-0352+ join it automatically and **the constant must NOT move** for §2's table

- under option 1 the gated subset holds **15** contradicted pairs — 0.95 is off a

  `test_rule_b_boundary_tracks_labelling_md_and_splits_the_real_gold` fails outright

The step must be rewritten: the constant stays `eg-0242`; only LABELLING.md's range
*text* extends its end (the pinned test recomputes `last_id` from the file and asserts
the verbatim `"{FIRST}..{last}"` string).

**But the boundary staying needs an owner ruling the plan never requests.** The
2026-08-08 re-measure ran fresh inference on **all 351 pairs** (ledger: "nothing replayed
warm"), so judge identity `fd39e7b2` has now contacted the entire file — the
"never-contacted" population no longer exists under a literal reading of Rule B, and the

weakening of ratified protocol text and therefore the **owner's call, not the plan's to
assume silently**. Add it to §3's ratification package and rename or annotate the
population honestly in LABELLING.md and the ledger. This is the round's biggest
undeclared blocker.

## 5. The §3 rule — it stops seed-level aiming, but has four holes

**I1 — Procedure-shopping.** The rule pins the seed but not the draw *procedure*. The
same seed under a different algorithm (sort order, per-stratum order, `rng.sample` vs
shuffle-and-slice, pool ordering) yields a different retired set, and the executor — the
contaminated controller — writes that code *after* knowing the seed and holding the
per-pair miss census (see I2a). Each variant is defensible in isolation; the choice among
them is exactly the aiming channel the rule exists to close. Fix: the rule (or the plan,
before step 2) must name the committed algorithm with zero degrees of freedom — reuse
`resample_draw.derive_seed`, id-sorted eligible pools per stratum, strata processed in a
stated fixed order, `rng.sample(pool, quota)` — landed in a commit *before* the draw
executes, with the drawn ids and the one-command reproduction recorded in the task
report.

**I3 — The rule text is self-contradictory and unreconciled.** It requires selection
"stratified by slice" and then forbids "slice … enter[ing] the selection"; say "beyond
the stated stratification". Worse, LABELLING.md's standing "Labelling is judge-blind"
bullet says no pair may be *retired* "on the basis of what any judge model answers" — and
this round retires pairs in a round triggered by a judge's gate failure. The defense is
real (selection is seeded and content-blind; the *trigger* is the lattice arithmetic
recorded before it bit), but the ratified text must reconcile the two clauses explicitly
or the file contradicts itself.

**I4 — The rule pins the verdict-class census but not the slice composition.** This
round's §5 restores slice proportions; the *rule* — the precedent — doesn't require it. A
future round could lawfully retire 15 value-swap and author 15 temporal-contradicted,
reshaping the census's difficulty at constant size. Write the largest-remainder
slice-quota requirement into the rule itself.

**I5 — Silent attempt-budget refresh.** `gold_touching_attempts` keys on `gold_sha256`
(ledger, T2.110 History), so the resize mints a fresh two-attempt budget as a side
effect. Unguarded, every failed gate could be followed by a census reshape that resets
its budget. Step 0's ledger entry must state the budget treatment — lineage counting, or
an explicit owner ruling that the budget is fresh — before the re-measure task exists to
exploit the ambiguity.

**I6 — No overlap disclosure.** A blind draw over the eligible 45 will retire some of
attempt 1's misses in expectation, moving the re-measure's recall for census-content
reasons rather than judge reasons. The task report must record the aggregate overlap
("k of 15 retired pairs were attempt-1 misses" — computable by the already-contaminated
controller; pair ids still withheld from every authoring surface), or the re-measure's
delta cannot be attributed.

## 2. The 1.0 — attacked first, and it holds

**The labelled-serve path exists exactly as quoted.** Doc 16 §4
(`docs/design/16-documents-and-pkm.md:129`): an answer below the bar "is returned labelled
('could not fully ground this answer') or withheld, never presented as if grounded
(invariant 14)". The bar prices the badge, not the answer — the below-bar user still
receives the answer with its citations.

**The regime arithmetic is correct — re-derived independently.** One miss at n ≤ 19 gives
coverage ≤ 18/19 ≈ 0.9474 < 0.95, so every bar in (18/19, 1.0] — the article twin's 0.95
included — is the *same predicate* below 20 sentences. Divergence begins exactly at n = 20
(19/20 = 0.95 clears 0.95, fails 1.0); at n = 40, 39/40 and 38/40 both clear 0.95 while
serving one and two unsupported sentences under the badge. The pin test carries this as
executable assertions and I confirmed them.

**The priced cost is honest arithmetic from the bar, not from a measurement.** 0.9⁴ ≈ 0.656,
0.9⁸ ≈ 0.430 — both correct from the 0.90 recall *bar*.

**Verdict on earnability, stated plainly: the badge is not made unearnable by this bar,
because below n = 20 the earn rate is bar-independent.** At n = 8, a 0.95 bar also requires
8/8 (7/8 = 0.875 < 0.95), so the earn rate under 1.0 and under the "obvious" alternative is
identical in the regime where interactive answers live. The earnability pressure is real,
but it is a property of a strict per-sentence entailment badge plus a recall-0.90 judge
floor — repairable only by a better judge, not by any coherent bar choice — and its failure
direction is a label under-served, the sanctioned direction (doc 08 §5.3's asymmetry).
Correlated judge errors (the realistic case) push real earn rates above 0.9ⁿ. The bar does
**not** need its escape hatch on day one; see Important-2 for the flip side of that fact.

**Contamination check (the disclosed temptation): clean.** The ledger holds measured
entailed-recall (156/173 ≈ 0.902, 65/72 ≈ 0.903, `gate-ledger.md:2265`); none of those
figures, nor any measured number, appears in the artifact or enters any derivation. The two
contradiction figures the spec discloses as unavoidably in context (0.945, 0.79–0.90) touch
no bar stated here. The 0.95/0.90 pair is doc 17 §6's standing rule
(`17-test-and-eval-harness.md:147`, and :151: "the rule above predates every judge run"),
so causality runs bar-before-measurement. No span-variant measurement exists anywhere in
the tree — confirmed.

**The role-bar mapping is honest.** The faithfulness consumer branches on `entailed` alone
(`grounded ⇔ entailed`, the `claim_entailment.ENTAILED` discipline); a false accept ships a
hallucination under the grounded badge (truth-critical → precision 0.95), a false refusal
costs a label (→ recall 0.90). Same direction as the entailment role and correctly *not* the
contradiction role's inversion — faithfulness is a deciding instrument, not a surfacing one.

## 4. Findings

### Important-1 — the clamp is direction-blind while claiming the direction-carried shape
`backend/app/services/faithfulness_bars.py:101-102`. `FaithfulnessBarSpec.loosens` hardcodes
`candidate < self.default` and never consults `self.conservative`; the precedent it claims
to reuse (`promotion_bars.py`'s `BarSpec.loosens`, T2.127) dispatches on the direction. The
module's own docstring cites G-C's lesson — "a direction-blind guard read [a bar's abuse] as
a tightening" — as the reason direction is carried per parameter, and then ships a
direction-blind guard. Harmless today: the enum has one member and all three bars are proven
floors (my mutants confirm the tests bite). The failure mode is a fourth bar with a genuine
ceiling direction: its author adds `Conservative.LOWER`, trusts the docstring's promise, and
the clamp silently enforces backwards — an abusive raise reads as a tightening, exactly the
laundering the module exists to stop. **Fix (one of):** dispatch `loosens` on
`conservative` mirroring `promotion_bars`, or `assert self.conservative is
Conservative.HIGHER` inside `loosens` so an unhandled direction raises instead of inverting.

### Important-2 — the spec's escape hatch cannot deliver the relief its own arithmetic prices
Spec §2, "the priced cost" and "what would have to be true… (b)". The named repair for an
unearnable badge is "a better judge or a licensed loosening… bounded at 0.95". By §2 step 3's
own regime arithmetic, a loosening to 0.95 changes the predicate **only at n ≥ 20**; for
n ≤ 19 — where the spec itself says interactive answers "live almost entirely" — 0.95 and
1.0 are the same predicate and the licence buys zero earn rate. The only repair in the
operative regime is judge recall. This does not weaken the 1.0 (it strengthens it: the cost
attributed to 1.0 is the cost of any coherent bar below n = 20), but this artifact is the one
whose prose is the only thing that can be validated, and its contingency section promises an
escape that mostly cannot engage. **Fix:** one sentence in §2(b) stating the licence path
relieves only the long regime; short-answer unearnability is repairable only by judge recall.

### Important-3 — "cannot be two values" is asserted, never enforced
Spec §3/§4 and the module docstring claim TH1.09/TH1.17 importing the defaults means "the
bars stated today and the bars enforced then cannot be two values" — but nothing mechanical
makes restatement fail. TH1.17's own task entry (`M1-measurement.md:780-789`) carries **no**
import instruction; the obligation lives in the spec, the module docstring, the progress row
and the EH1 log, none of which a Sonnet-tier runner implementer is guaranteed to read, and
`VERIFICATION_BAR_DEFAULTS` in `verification_judge.py` is the natural wrong place a wiring
task would restate 0.95/0.90. This repo's own history (invariant 23) is a catalog of prose
obligations going stale, and it already owns the mechanical pattern for exactly this — the
RRF_K AST scans that fail the build on a second constant declared outside `rank_fusion.py`.
**Fix:** a scan test asserting no numeric literal binds a `faithfulness_*_bar` key outside
`faithfulness_bars.py` (+ its tests); at minimum, the controller should add the
import-not-restate sentence to TH1.09's and TH1.17's task entries. Mitigations noted
honestly: TH1.17 is gate-feeding (adversarial review owed), and TH1.09 must import
`get_faithfulness_bars` anyway to function.

### Minor-1 — the DB-to-licence path is untested
`faithfulness_bars.py:305`: dropping `FAITHFULNESS_BAR_LICENCES_KEY` from the `_BARS_SQL`
keys survives all 32 tests. Failure direction is conservative (a real operator licence would
be invisible and the loosening clamped), but the one query that makes licences reachable at
runtime has no coverage. Add a licence row to `test_get_faithfulness_bars_reads_the_config_table`.

### Minor-2 — two constant assertions in the regime test cannot fail
`test_faithfulness_bars.py:443-446`: `assert not 9/10 >= 0.95` and `assert not 18/19 >= 0.95`
are arithmetic no code change can break. Deliberate documentation-as-assert (the same test's
last two lines do exercise the code); recorded for the final review, no action needed.

### Minor-3 — "at worst" overstates what the independence assumption bounds
Spec §2's priced cost: 0.9ⁿ is the worst case over the *recall floor* (any qualified judge
has recall ≥ 0.90) but not over error correlation — under maximal anti-correlation
P(all pass) can fall to 1 − n(1−r) (0.2 at n = 8). Realistically correlated errors push the
rate the other way, above 0.9ⁿ. One clause ("at the recall floor, under independence")
would make the sentence exact.

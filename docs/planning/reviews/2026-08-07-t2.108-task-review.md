## 2. The vacuity finding (report §7.1) — adjudicated, and it HOLDS

The executor claims the false-promotion audit's `decidable=True clears=True` is vacuous:
denominator floor met, both numerator arms inoperable. **Verified independently, all
three legs, on data:**

1. **Machine dispute via the judge:** `VerificationJudge.judge()` raises
   `JudgeNotQualifiedError` without a qualification record
   (`verification_judge.py:135-161`), and
   `app/services/verification_qualification.json` does not exist.
2. **Machine dispute via the model-free detector:** `recompute_fact` does drive the
   deterministic scan per fact (`verification_ladder.py:~1000` →
   `adjudicate_contradiction_finding`), but the scan's `arms` list is empty for every
   fact in this corpus: `SINGLE_VALUED_RELATIONS` is empty
   (`contradiction_veto.py:104`) and the stored rel_types are exactly
   {USES, DEPENDS_ON, DEPLOYED_ON, IS_A} — no REPLACES-family edge exists, confirmed by
   direct query, so the inverse-replacement arm never arms
   (`contradiction_veto.py:263-278`).
3. **Human rejection:** zero `human_verdict` events; nothing in the harness calls the
   review door.

So on this corpus-plus-environment the numerator is structurally zero **independent of
ladder behaviour**, and `audit_clears(0.0, 31)` (`promotion_bars.py:192-197`) returns
True while unable to distinguish "precision 1.0" from "no operable detector". **The
finding is correct and is a G-C bar-design defect for the gate owner**: the committed
decidability predicate gates only the denominator; the numerator's operability is
unmodelled.

Two precisions the report does not state, recorded for the ruling:

- The vacuity is a **joint** property of the bar and this corpus, not of the bar alone:
  the deterministic arm is reachable judge-free on a corpus carrying an inverse
  REPLACES-family pair with overlapping windows and an independent witness. T2.108
  *could* have made the numerator demonstrably operable.
- But no such corpus can be both operable and passing in the decidable band: with 20–99
  corroborations, a single numerator event breaches the strict 1% bar — and a *designed*
  dispute-after-corroboration would measure the corpus's designed wrongness, not the
  ladder's precision. So the executor's attribution ("a finding about the bar, not about
  the corpus") survives the attack. The gate owner's options are roughly: an operability
  predicate joined into `audit_decidable` (judge qualified, or a live deterministic-arm
  precondition, or an in-window human verdict), or an explicit vacuity annotation on any
  clear below judge qualification. That ruling is T2.40's, not this review's.

  `NOT NULL DEFAULT now()` (`0001_baseline.py:652`) and `add_source` never sets it
  (`fact_sources.py:496-511`); no code path carries assertion time into the column the
  gate reads (`max_cross_origin_gap` over `first_seen`/`last_seen`,
  `fact_sources.py:297-315`). Any corpus that reaches facts by re-running the lift lands
  all provenance inside the lift's own wall-clock window, so the ≥ 7-day gate is
  unreachable however the memories' `created_at` is backfilled. Confirmed empirically:
  without the stamp, the ten atlas claims read origins=2, span ≈ 0, `candidate`.
  *(Minor wording overbreadth: a physical `pg_restore` of a production database preserves
  the column, so "including a corpus imported from a production export" holds only for
  the re-ingest/re-lift route — which is the plausible one, since a physical restore
  brings its journal along and needs no corpus at all. See M3.)*
- **The toggle does what it claims.** `--no-capture-time-simulation` skips exactly the
  one UPDATE; reproduced: stamped 0 rows, `time_gap` bucket empty, 21 transitions.
- **Thresholds hold without it.** Reproduced: audit 21 ≥ 20; both axes keep powered
  buckets; completeness identical.
- **Legitimacy.** The UPDATE writes one column of one source kind, values deterministic
  from the committed corpus, and it is loud everywhere — function name, `SIMULATED CLOCK`
  run-header line, a committed artifact of the run without it. It does *manufacture* the
  `time_gap` bucket — that is its stated purpose — and a reader who declines the

  artifact proves. This is the driven/stubbed boundary drawn correctly: what is
  simulated is corpus chronology, not any ladder decision. Note the one thing the bucket
  therefore evidences: the ladder's date arithmetic over a declared timeline — not the
  production write-time proxy's fidelity, which no pre-cutover corpus can evidence.

## 5. Every rate is 1.000 (attack 4) — partially a second instance of §7.1, adjudicated

The dispatch asked whether probes 1–2 are vacuous-but-decidable the same way the audit
is. **Substantively yes, and the report does not frame it that way — see I1.** On this
corpus `blocked ≡ 0` is data-precluded, not merely observed: a contradiction-blocked
hold needs a veto finding (impossible per §2's legs) and a supersession-blocked hold
needs REPLACES-family content the corpus lacks. Since eligible = promoted + blocked over
journaled transitions, every rate is identically 1.000 unless shipped code manufactures
a blocked hold from nothing; the 0.5 floor (`promotion_bars.py:204-208`) cannot fail
through any ladder behaviour, and `slice_clears` reads True.

The asymmetry that keeps this from being a *full* second instance, recorded so the gate
owner weighs both correctly: probes 1–2's **decidability clause carries earned content**
— 31 promotions journaled by the production writer where T2.40 had zero, three populated
gate buckets with the designed counts, payloads validated — while the audit's
decidability clause (a denominator floor) carries none of its numerator's operability.
The floor is also documented in `promotion_bars.py` as a liveness/honesty tripwire
rather than a rate target. But a tripwire whose trip-condition is data-precluded on the
measurement corpus is untested by that corpus, and any G-C verdict quoting
`clears=True` on these buckets inherits that caveat exactly as it inherits §7.1's.

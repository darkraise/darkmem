## The judgement call: mapped rung vs dropped key

**The executor's call is right, and for a better reason than the one argued.** The
stated argument — a silent rewrite records a movement to `candidate` the ladder never
made — actually distinguishes mapped-with-marker from mapped-*without*-marker, not from
dropping the key. The stronger ground for serve-mapped: `candidate` + `label_suppressed`
is **T2.95's established wire encoding** for "a promoted rung was withheld here" — the
same pair every row's own top-level label already uses on these very bodies. Reusing it
means a consumer needs one convention to read the whole surface; dropping the key would
invent a second encoding (absence) used nowhere else, and would strip rungs from a
transition object while `outcome: "promote"` sits beside the hole. The "misreports
history" worry does not survive inspection: no audit record is altered — `/events` still
serves the true history verbatim under the ruling — and on the claim surface a `verified`
row *means* a transition by the journal's own contract, `outcome` names it, and the
marker's asymmetry (absent on the genuine `candidate` in `before`, present on the
withheld one in `after`) is precisely what keeps the two distinguishable inside one
payload, which the fix's own drives assert. A reader misled by `candidate → candidate`
would have to ignore all three signals, on a surface whose contract defines the marker.
The residual disclosure (singleton `PROMOTED_STATUSES` makes "withheld" imply
"corroborated") is identical under both designs and the ruling accepts it explicitly.

## Deferred minors (recorded, not looped on)

1. **The mapper skips non-string rungs.** `gated_journal_payload` maps
   `verification_status` only when the value is `None` or `str`
   (`claim_gates.py:293`); `{"verification_status": ["corroborated"]}` passes through
   verbatim (measured). No live writer can produce it — every journalled rung goes
   through `journalled_status` as a string — and any new journalling site must pass
   `DECLARATION_INVENTORY` review first, so this is a latent shape gap with a named
   backstop, not a leak.
2. **A stale `label_suppressed` inside a payload survives when nothing is withheld.**
   The after-the-loop guard overwrites a pre-existing marker only when the current
   status *is* withheld; with the gate open (or a non-promoted status) a
   `label_suppressed` key already present in the stored payload is copied through
   (measured). No writer journals that key today, so also latent.
3. **The reach pin's granularity is module+reader, not read-site.** A *second* ungated
   read of an already-listed reader inside an already-gated module (e.g. another
   `latest_verified_evidence` call in `review_queue` served raw) changes nothing in the
   pinned dict. The backstop is real: both claim surfaces carry whole-body
   `PROMOTED not in response.text` drives on a journalled fact, so a rung reaching
   either body fails a door drive even where the pin is blind. Worth a sentence in the
   pin's docstring some day; not worth a round.
4. Same class: `facts_read`'s `latest_verified_evidence` read (feeding `dispute_label`,
   rung-free) is marked gated=True purely because the module gates its *other* read —
   accurate at the pin's stated granularity, slightly generous below it.

## I1 — the verdict bit is trusted and nothing pins its writer

**Fix.** Two AST scans in `tests/test_contradiction_scan.py`, new group G2b, both over
`backend/app/**/*.py` with the repo's usual vacuity floor (`> 100` files):

1. `test_the_scan_module_is_the_only_emitter` — walks the parsed tree for `record_event`
   calls and resolves the `event_type` keyword. Resolution follows the constant import
   (`from app.services.events import CONTRADICTION_SCANNED`), module-level literal
   assignments, and one hop of rebinding (`KIND = CONTRADICTION_SCANNED`), so the guard is
   not defeated by the first indirection anyone would reach for. The assertion is an
   **equality** with `{"app/services/contradiction_scan.py"}`, not a subset test, so a guard
   that went blind fails as loudly as a second emitter. `event_type` is keyword-only in
   `record_event`'s signature, so there is no positional spelling to miss.
2. `test_only_the_channel_s_three_modules_name_the_verdict` — the emitter scan's blind spot
   is a module that never calls `record_event` at all and spells the type into a raw
   `INSERT INTO events`. This second scan asserts that the only files naming the event type
   in any form are the three that constitute the channel: `events.py` (declares),
   `contradiction_scan.py` (writes), `contradiction_veto.py` (reads back).

Four in-suite negative controls prove both directions every run: a bare `record_event` with
the inline literal is flagged; the laundered-constant form is flagged; an ordinary
`sources_changed` writer is **not** flagged by either scan (a guard that flagged every
`record_event` call would be unfalsifiable); and a raw `INSERT` with no `record_event`
anywhere is flagged by the reference scan alone.

**Drills.** Each mutation applied to a committed tree and restored from a private copy.

## I2 — a swallowed journal write counted as a recorded dispute

**Fix.** `contradiction_scan.py` adopts `dream_undo`'s shape. Each verdict carries a
`scan_run_id` (one uuid per run, no content), and `_journal` reads its own row back out of
`events` in the write session before that session commits, returning whether it landed. The
read is an `EXISTS` bounded by `created_at >= now - 1 day` so it prunes the monthly
partitions and rides `ix_events_object`; existence rather than a count because at most one
row can carry a `(fact, run)` pair — and because a count would need a numeric comparison,
which `test_no_numeric_comparison_can_stand_in_for_a_verdict` forbids anywhere in this
module.

A shortfall is **not** counted as `disputes_recorded` / `clears_recorded` / `facts_checked`.
It increments a new miss bucket `journal_failed`, logs at ERROR, counts the tail it never
reached into `facts_unscanned`, stops the run, and **holds the watermark** — the same
treatment the judge's refusal gets, for the same reason: a journal insert cannot fail on the
strength of one fact's content, so whatever broke it (a missing monthly partition above all)
is still broken for every remaining fact, and the drained events must stay unconsumed. The
run reports `skipped_reason="a verdict could not be journalled"`.

Two tests: `test_a_swallowed_journal_write_is_a_miss_not_a_dispute` (counters and the absent
journal row) and `test_a_lost_verdict_leaves_its_event_to_be_drained_again` (the watermark
holds, and a second run with the journal working drains the same event and records the
dispute). The swallow is simulated by monkeypatching `record_event` to a no-op, which is
precisely what its own `except` clause does.

**Drills.**

| Mutation | Result |
|---|---|
| `_journal` returns True without the read-back | **2 failed** — and the failure output *is* the reported defect: `facts_checked=1, journal_failed=0, watermark_advanced=True` with no row in `events` |
| `journal_failed` dropped from the `misses` sum | **2 failed** — `test_a_swallowed_journal_write_is_a_miss_not_a_dispute` and `test_misses_sums_every_bucket` |
| Caller ignores the return value (`verdict_lost` never set, no break) | **failed** — a dispute is recorded and the watermark advances over a verdict that never landed |

**Outcome.** The job's only output can no longer be dropped while the run reports clean, and
the events that produced it are not consumed on the way.

## I3 — the permanent dispute, and the docstring that denied it

**Ruled by the brief: the consequence stays, the docstring was the defect.**
`detect_scanned_contradiction` said "a later clean pass over the same fact is what ends a
dispute the scan opened". It now says what happens:

- the newest row wins **only in the window before the ladder applies the first verdict** —
  after that the fact is excluded from the scan's servable set by doc 08 §5.3, its later
  `sources_changed` events are drained and discarded, and no second verdict is ever written;
- the two real exits are **guard lapse** (counterpart expires, window closes, witness joins
  the subject — each re-checked on every read by the code immediately below) and **human
  ratification** (doc 08 §4.4);
- so a judge false positive whose guards keep holding is a permanent dispute until a person
  rules on it, and that permanence follows from doc 08 §5.3's exclusion — which is what
  stops the scan re-paying a model call on facts it has already ruled on — rather than from
  an oversight. A disputed fact is served labelled with both sides (doc 08 §6, invariant
  14), and the bounded false-positive rate is what the precision-first asymmetry accepts
  behind the judge's 0.95 `contradiction_precision_bar` (verified in
  `verification_judge.py:286`, not assumed).

`test_a_later_clean_verdict_ends_the_dispute` was **renamed** to
`test_a_later_clean_verdict_supersedes_an_earlier_one` and its docstring now states what the
test does not show — its fixture fact is never disputed, as the reviewer established. The
old name was the same false claim in a second place.

**Drill.** None available and none claimed: this finding is documentation, and the behaviour
it now describes is the behaviour that already shipped and is already pinned
(`test_an_unservable_fact_is_reported_apart_from_the_misses` covers the exclusion).

already exposed, and the coverage question is a measurement (T2.52's), not a counter.

was never stated, so `_SAME_ENDPOINT_SQL` now records it: the draw is deterministic, the
subject is a fact whose sources just changed so its counterparts skew older, and what the
cap drops is counted by `CandidatePool.truncated` rather than lost quietly.

**M5 — `fact_id`-less `sources_changed` events. FIXED as a loud guard; the counter
DECLINED.** Both producers (`fact_lift.py:487`, `fact_provenance.py:256` — the only two

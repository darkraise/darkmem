### Where the httpx oracle is vacuous — the disclosure mapped

The implementer's disclosure is **confirmed and its extent is now measured**. Of 209
oracle contacts, 89 are vacuous (httpx round-trips the string verbatim, so the assertion
compares an id with itself). The blind region is precisely:

1. **Everything httpx passes through unchanged**: all non-special schemes (`urn:`,
   `agent:`, dotted tokens — probed live: `urn:oid:443`, `agent:007`, `iris.beep:example`,
   `z39.50r:host/db` all round-trip verbatim), schemeless references
   (`example.test:8443/a`, `localhost:8000/x` — verbatim), and any http(s) spelling
   already httpx-normal on the varied axis (trailing slash, fragment, tracking
   parameter, `www.`, trailing host dot, doubled path slash — httpx normalises none of
   these; for those axes the seed-equivalence test, not the oracle, carries the claim).
2. **Everything httpx rejects** (`continue` in the test): out-of-range ports,
   unbalanced brackets.

The **classifier boundary — is the token before the colon a scheme or a host — lies
entirely inside region 1**: httpx round-trips both `example.test:8443/a` and
`https:example.test:8443/b` verbatim (probed), so no oracle assertion can distinguish a
right classification from a wrong one there. The dotted-token defect could only be found
by hand, exactly as disclosed. The class of defect that remains structurally invisible
to the property: any mis-handling of spellings httpx does not rewrite — opaque ids, the
scheme/host boundary for dotless tokens, and every over-merge. Named pins are the only
net under that hole, and the committed pins do cover the known members.

The load-bearing corollary the finding below turns on: a case is only *safely* excluded
from the corpus if it lies in the blind region. A case httpx **accepts and rewrites** is
inside the oracle's sighted region, and excluding it is a judgment call about producers,
not a structural necessity.

### The corpus admission rule, exclusion by exclusion

- **`%3A` in hosts — exclusion sound.** WHATWG-conformant parsers refuse a decoded `:`
  in a host, and httpx round-trips the triplet verbatim (probed: `example%3A8443.test`
  stays percent-encoded, case-lowered only), so no fetch ever produces the decoded
  counterpart. No pair, no producer.
- **Double-encoding — exclusion sound.** httpx preserves valid triplets (probed: `%61`,
  `%74` survive emission), so a fetcher never double-encodes; and a double-encoded
  spelling is a *different resource* whose merging would be wrong, not merely unneeded.
- **`file:////x` — exclusion sound.** Parsers genuinely disagree, as the generator's
  comment states — verified: httpx reads host `x` (`file://x`), five slashes fold to
  `file:///server/share`, Firefox historically read UNC. httpx cannot fetch `file:`
  URLs, so `str(response.url)` never manufactures the pair. Note the module folds
  `file:////x` to the empty-authority `/x`, disagreeing with httpx's host reading — a
  latent split against an emission no fetch can produce; acceptable, now recorded.
- **Unicode digits in non-default ports — exclusion WRONG. New Finding C below.**

## New Finding C — Important: the "unicode digits in non-default ports" exclusion hides a live split this repo's own client produces

Probed live against this environment's `httpx`:

```
raw    'https://example.test:８４４３/a'  → id 'example.test８４４３/a'
httpx  emits 'https://example.test:8443/a' → id 'example.test8443/a'   SPLIT
```

The same holds for Arabic-Indic digits (`:٨٤٤٣`). httpx **accepts** the fullwidth
spelling and **emits** the ASCII form — so the pair (raw href, `str(response.url)`) is
produced by exactly the two-gatherer scenario the oracle test's own docstring postulates,
and one page is two attributable origins: same source-kind, ≥ 7 days apart, a promotion
at N = 2. This is the identical shape to the leading-zero port split this round fixed
red-first (`:08443`, `auto_research.py:350-356`): an authored oddity in an href, made
into a splitting pair by httpx's own normalisation. The case sits **inside the oracle's
sighted region** — had the generator produced the spelling, the oracle test would be red
today — and was adjudicated out by the admission judgment "no real producer", which this
probe falsifies: the producer is the repo's own fetcher.

The module is also internally inconsistent about it: two lines above the `isascii` guard,
the default-port check `int(tail) in (80, 443)` already treats Unicode digits as numbers
— probed: `https://example.test:４４３/a` has its fullwidth port **dropped as a default**
and merges, while fullwidth `８４４３` stays verbatim and splits. The "Unicode digits are
not ports" position is contradicted by the module's own default-port arm.

**Severity: Important, by this loop's own precedent.** Rescope-2 graded the `file:`
split Important under identical mitigations (loop disarmed, no config-row writer,
promoted badges serving `candidate`), and its producer story was *weaker* — httpx cannot
fetch `file:` URLs at all, while it demonstrably fetches and normalises this one. Grading
this lower would be softening relative to the loop's own rubric. It is not Critical:
operationally inert today, and it needs a CJK- or Arabic-typeset href carrying a
non-ASCII-digit port held under two spellings across runs — rare, but real in a way the
excluded class was judged not to be.

**Repair (small and bounded):** in `_split_port` (`auto_research.py:355`), drop the
`tail.isascii()` conjunct — `tail.isdigit() and int(tail) <= 65535` already admits only
decimal-digit runs and `str(int(tail))` emits ASCII, which is httpx's own spelling; the
`urn:isbn:0451450523` guarantee is untouched (ten digits exceed 65535, fullwidth ISBNs
likewise). Then admit the spelling to the corpus: a fullwidth-port transform on the
ported seeds, red-first, plus a named pin. The exclusion list's other three members
stand.

## The scheme-family fold (933b003b included)

- **The authority-mandatory list is exactly right.** The URL standard's special schemes
  are `ftp`, `file`, `http`, `https`, `ws`, `wss`; the list
  (`auto_research.py:109`) carries the five, with `file` handled by its own branch.
  Nothing is missing per the standard (gopher left the special list years ago).
- **Schemes not on the list** keep round 3's behaviour: ≤ 1 slash folds to `//`
  (probed: `ftps:`, `git:` zero-slash spellings merge with their `//` forms), 2+ stays.
  The only divergence is a 3+-slash spelling of a non-special authority scheme
  (`git:///host/x`), which no producer emits and httpx round-trips verbatim.
- **The dotted-token rule breaks no real producer.** RFC 3986 does permit dots in
  schemes, and registered dotted schemes exist — `iris.beep`, `soap.beep`, `z39.50r/s` —
  all dead protocols no research gatherer emits; httpx round-trips them verbatim
  (probed), so even under the host reading each spelling maps consistently and no *pair*
  can split. Meanwhile the rule fixes real splits: `example.test:8443/a` now merges with
  `https://example.test:8443/a` (was id `8443/a` — the port as the host), and
  `example.test:8443` with no path (was id `8443` — the port as the *entire identity*).
- **The boundary's residue is dotless**: `localhost:8000/x` still splits from
  `http://localhost:8000/x` (ids `8000/x` vs `localhost8000/x`), and likewise any
  intranet single-label host. Pre-existing, oracle-blind (both spellings round-trip),
  and not distinguishable from a genuine `scheme:opaque` without a host allowlist —
  `mailto:`, `urn:`, `data:` live on that side. The dot is a defensible boundary;
  recorded as a deferred minor, not loop material.

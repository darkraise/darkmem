Caught by the closure as it stands:

- `import importlib as il; il.import_module(...)` — attribute match is alias-proof.
- Lazy imports inside a function body, static **and** dynamic — `ast.walk` covers bodies.
- Adjacent-literal concatenation `"app.services" ".pipeline"` — one `Constant` at parse.
- A reach through a re-exporting package `__init__` (`from app import services` with
  `from . import pipeline` in the init) — the static walk follows into the init.

Escaping, all runtime-verified as real imports of the target module:

- `from importlib import import_module as im; im("app.services.pipeline")` — the callee
  *name* no longer matches.
- `loader = importlib.import_module; loader("app.services.pipeline")` — bound-callable
  alias, same class.
- `__import__("app.services", fromlist=["pipeline"])` — the literal dynamic analog of
  `from app.services import pipeline`, which the *static* walk does follow; the loader
  route ignores `fromlist`, so the two routes disagree on this one shape.
- `importlib.import_module(name="app.services.pipeline")` — the route reads only
  `args[0]`, though its own `_loader_call_package` accepts the keyword spelling of the
  *second* argument.
- Placeholder-free f-string and `find_spec` + `module_from_spec` + `exec_module` — also
  escape; both are within shouting distance of the documented computed-name bound.
- Module-level constant then `import_module(_N)` — the documented bound itself; correctly
  out of scope, and the negative control says so.

None of these blocks the verdict. N1's reported case and rescope-1's specified fix shape
— follow `import_module`/`__import__` calls whose first argument is a literal — are
delivered, drilled, and mutation-verified; every escape above predates this fix (before

# T0.18 report — `--full` must not overwrite ledger-cited gate evidence

**Branch:** `feat/e2-lane-cj` (worktree `.worktrees/e2-lane-cj`), off `feat/e2-truth-core`.
**Commit:** `fd82fa07` — `fix(harness): refuse to overwrite a ledger-cited eval report`.

## Shape chosen: refusal, not a run-id path

The brief offered two acceptable shapes. I took the refusal route: `run_eval` now
checks, immediately before writing the dated report, whether `gate-ledger.md`'s raw
text already names the target path. If it does, it raises `RuntimeError` naming the
citing line and writes neither the report nor the JSONL eval-ledger row.

**Argument against the run-id route.** Moving the report filename to carry the run id
(`<date>-<run-id>-retrieval-eval.md`, or similar) would satisfy "cannot collide," but
it does not compose with ruling 4 the way the brief already flags: it changes the
identity of *every* report, cited or not, and the fourth Done-when clause then obliges
rewriting every existing citation in `gate-ledger.md` to the new filename in the same
commit — including the two files this task's fourth clause requires verifying
byte-identical. That is strictly more surface to get right for a problem that is only
about the *cited* subset of reports. It also changes nothing about the actual defect:
a run-id'd path stops the specific collision this task found, but the same silent
detachment could still happen to any other harness artifact keyed on a coarser name if
a future runner reuses this pattern; refusal generalizes to "check the ledger before
overwriting anything it cites," which is the actual invariant worth having. The
refusal route is also the one that leaves the uncited path completely untouched: a
same-day correction run never even evaluates the ledger-citation branch differently
than before this task, because `_refuse_if_cited` only fires when the target path
already exists **and** is named in `gate-ledger.md`'s text — an uncited report matches
neither the citation half nor changes its own identity.

## Design

- `GATE_LEDGER_PATH = REPO_ROOT / "docs" / "planning" / "gate-ledger.md"` — a new
  module constant in `run_retrieval_eval.py`, distinct from `ledger.DEFAULT_PATH`
  (the JSONL run-history ledger under `scripts/benchlib/runs/`, an unrelated concept
  that already had a `ledger_path` parameter name I had to avoid colliding with).
- `find_ledger_citations(rel_path, ledger_path=GATE_LEDGER_PATH) -> list[str]` — a
  **literal substring search** over the ledger's raw text, line by line, returning
  `"gate-ledger.md:<lineno>: <line>"` for every match. Not a markdown table parser.
- `_refuse_if_cited(out_path, ledger_path=GATE_LEDGER_PATH)` — no-ops if `out_path`
  doesn't exist yet (nothing to protect on a first write) or sits outside `REPO_ROOT`
  (a scratch `report_dir` a test passes cannot be named by a ledger that only ever
  cites repo-relative paths, so it's out of scope by construction). Otherwise computes
  `out_path`'s path relative to `REPO_ROOT` and calls `find_ledger_citations`; a
  non-empty result raises `RuntimeError` with every citing line and instructions
  (mint a differently-named report by hand, update the ledger's citation in the same
  commit — never overwrite).
- Wired into `run_eval` right before `out_path.write_text(...)`, so a refusal leaves
  no partial artifact — same discipline the existing F1 caveat-kind guard
  (`_assert_expected_caveats`) already uses a few lines above it.
- Added a `gate_ledger_path` parameter to `run_eval` (default `GATE_LEDGER_PATH`) so
  tests can point it at a scratch ledger file without touching the real
  `docs/planning/gate-ledger.md`.

### The brittleness question, and how it's handled

The brief calls out that a citation written in a form the parser doesn't recognize
reads as uncited — the unsafe direction — and asks how that's handled. Answer: it
isn't specially handled, it's accepted and documented, because the alternative (a real
markdown/table parser) buys robustness against a ledger-formatting style
`gate-ledger.md` does not actually use. I checked: every one of the 21 distinct
`docs/eval/...` and `backend/scripts/...` paths cited anywhere in the file (verified
below) appears as a literal path string, sometimes backticked, sometimes bare,
sometimes mid-sentence, sometimes in a table cell — but always as the exact
repo-relative string. A substring search catches all of those forms for free. What it
would miss is a citation written as a glob, a shell variable, an absolute path, or a
path relative to some other root — none of which the ledger has ever used. The
docstrings on both `find_ledger_citations` and `_refuse_if_cited` say this in the code
itself, including the explicit "this fails in the unsafe direction" framing, so a
future reader who changes the ledger's citation style knows to widen the check rather
than assume it still works.

## Ruling 4 — not overturned

`_refuse_if_cited` only ever fires on a path that (a) already exists on disk and
(b) is named in `gate-ledger.md`. A same-day re-run of a report nobody has cited yet
never satisfies (b), so it overwrites exactly as before — `report_path()` itself is
completely unchanged. Two of the new tests exist specifically to prove this
(`test_refuse_if_cited_allows_overwriting_an_uncited_same_date_report` and the
end-to-end `test_run_eval_still_overwrites_an_uncited_same_date_report`, which calls
`run_eval` twice against the same scratch date and confirms both calls land on the
same path and the second call's content is what's on disk).

## Verification — substituted, and why

The task's own Verify field is two live `./scripts/gate.sh --full` runs in one day,
which dispatches paid DeepSeek calls and would itself be the exact action this task
protects against (it would write `docs/eval/2026-08-07-retrieval-eval.md` twice,
and today that path is uncited so the run itself would be harmless to the *existing*
ledger, but the brief explicitly forbids doing this to avoid the cost and the
unnecessary live dispatch). Per the brief, I substituted a unit/integration-level
proof against a scratch `report_dir` and a scratch `gate-ledger.md`, using
`run_eval`'s existing stubbed-LLM DB-backed test harness (the same one the module's
own F1-trap test already uses) so the proof exercises the real composition, not a
hand-built lookalike.

**What the substitution covers:** that `_refuse_if_cited` fires (and leaves no
report, no JSONL ledger row) when the target path is both pre-existing and named in a
`gate-ledger.md`-shaped file; that it stays silent for an uncited target, including
through two same-day `run_eval` calls; and that the underlying `find_ledger_citations`
substring search correctly reports the citing line for several citation shapes
(backticked, table-row, repeated).

**What it does not cover:** an actual concurrent `./scripts/gate.sh --full` run
against the real `docs/planning/gate-ledger.md`, with the real DeepSeek/Ollama round
trip and the real cache. That's a deliberate scope cut per the brief, not an oversight
— the mechanism under test (string match against a file's text, path existence check)
has no dependency on live models or the real DB beyond what the existing test
fixtures already provide, so I judge the unit-level proof sufficient for this task's
claim.

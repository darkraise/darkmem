## What shipped

Two new modules in `backend/scripts/benchlib/`, their tests, and one generated
artifact:

- `resample_sheet.py` — renders `entailment/resample_blind.json`'s 93 shuffled
  rows into a fill-in-place worksheet (`entailment/resample_sheet.md`), carrying
  a verbatim excerpt of `LABELLING.md`'s three rule sections ("The three
  verdicts", "General decision procedure", "Edge rulings") the labeller needs.
  Also parses a completed sheet back into `{id: {verdict, rule}}` — the same
  file is generated, filled in, and handed back; there is no separate answer
  format to keep in sync.
- `resample_score.py` — compares a completed sheet against the real gold,
  computes `n` / `disagreements` / lists every mismatch by id with both
  verdicts, and writes the `resample` block onto `gold.json`'s top level that
  `judge_qualification._resample_reasons` requires.
- `entailment/resample_sheet.md` — the actual generated sheet, ready for the
  owner's sitting. Contains only premise/hypothesis/blank slots and the
  redacted rulebook; carries no verdict, stratum, or ordering information
  beyond what `resample_blind.json` already carries.
- `tests/test_resample_sheet.py`, `tests/test_resample_score.py` — 39 new
  tests, all against synthetic fixtures (`syn-*` / `s-*` ids), never the real
  gold's verdicts.

## The discipline, and one leak I found and closed

**No agent labels any pair.** Neither module reads a verdict from anywhere:
`resample_sheet.py` never opens `gold.json` at all (structurally proven, see
below); `resample_score.py` reads `gold.json` only to *compare against* the
owner's own typed-in verdicts, never to produce one.

**The structural proof.** `resample_sheet.py` cannot import
`benchlib.entailment_gold`, call `load_entailment_gold`, or name `gold.json`
outside its own docstring — enforced by an AST scan in
`test_resample_sheet.py` that walks the parsed tree (not a text search, per
the brief's recorded trap: a text search fires on the docstring explaining
the discipline too). I mutation-drilled this during review: temporarily added
`from benchlib import entailment_gold` plus a call to
`load_entailment_gold()` to the real file, confirmed both scan tests failed
with the exact violation named, then restored the file from a copy I'd made
beforehand (never `git checkout --`, per the brief's hygiene note) and
re-ran green. `git status` after the restore showed the file byte-identical
to before the drill.

**A real leak, found while building the sheet, not assumed away.** The first
generation of the sheet against the real files put pair id `eg-0016` on item
7 and `eg-0022` on item 6 — and the rulebook excerpt sitting directly above
them cited `eg-0016` as the window rule's `entailed` example and `eg-0022` as
the reversal rule's `contradicted` example. `LABELLING.md`'s rule text cites
specific pair ids as worked examples throughout, and the `contradicted`
stratum of this resample is a **full census** (55/55 live contradicted
pairs drawn) — so *any* contradicted-slice example the rulebook cites is
guaranteed to also be one of the 93 sheet items, printed under its own real
id a few lines below the citation that names its verdict. I caught this by
actually running the generator against the real files and grepping the
output before treating the sheet as done, not by inspection alone.

Fixed in `rulebook_excerpt()`: every parenthetical citing an example id
(`_EXAMPLE_ID_RE`, matching `(...eg-\d{4}...)` in any of the shapes
LABELLING.md uses — single id, comma list, `a..b` range) is stripped before
the excerpt is assembled; the rule prose itself is untouched. Verified against
the real generated sheet: 93 `eg-####` occurrences total, all exactly one per
item heading, zero inside the rulebook block. Locked by
`test_rulebook_excerpt_names_no_example_pair_id`,
`test_redact_example_ids_strips_every_cited_shape`, and an end-to-end
render test.

## Operator runbook

Everything below runs from `backend/`, using the project's own interpreter
and the `PYTHONPATH` recipe `resample_draw.py` already requires (it also
cannot run standalone without both `backend` and `backend/scripts` on the
path — verified, not a new requirement this task introduces).

### 1. Generate the sheet (already done for this sitting)

```
cd backend
PYTHONPATH="$(pwd):$(pwd)/scripts" .venv/bin/python -m benchlib.resample_sheet
```

Writes `scripts/benchlib/entailment/resample_sheet.md` — already committed in
this change, so this step is only needed again if `resample_blind.json` or
`LABELLING.md` change (it always regenerates from whatever is on disk right
now, deterministically: same input, same output).

### 2. Label

Open `resample_sheet.md`. It has 93 items, each with a premise, a hypothesis,
a blank `**Verdict:**` line and a blank `**Rule cited:**` line, preceded once
by the relevant `LABELLING.md` rule text (verdict definitions, the general
decision procedure, and the edge rulings — window rule, exclusive-slot rule,
reversal rule, etc.). Fill in `**Verdict:**` with exactly one of `entailed` /
`contradicted` / `unsupported`, and `**Rule cited:**` with which named rule
decided it, directly on the same line, for every item. Do not consult
`gold.json`, any other file in `entailment/`, or a prior labelling run.
**Save the same file** — there is nothing else to fill in or return.

### 3. Score it

```
cd backend
PYTHONPATH="$(pwd):$(pwd)/scripts" .venv/bin/python -m benchlib.resample_score \
  --sheet scripts/benchlib/entailment/resample_sheet.md \
  --performed-by "<your name or handle>"
```

`--date` defaults to today (UTC); pass `--date YYYY-MM-DD` to override. This:

1. Hashes the current `gold.json` and checks it against
   `resample_manifest.json`'s pinned `gold_sha256`. If the gold has moved
   since the draw, it refuses immediately and names both hashes — **the
   sample must be re-drawn** (a separate, out-of-scope step; do not hand-edit
   the manifest) before scoring can mean anything.
2. Checks the sheet's filled-in ids cover exactly the 93 drawn ids — a
   missing or stray id refuses with the exact id(s) named.
3. Checks every verdict is one of the three lawful words — a blank or
   mistyped verdict refuses naming the offending id.
4. Compares each verdict against the real gold, prints the disagreement
   count and the bar (`<= 1`), and writes every disagreement's id with both
   verdicts to `scripts/benchlib/entailment/resample_disagreements.json`.
5. Writes the `resample` block (`n`, `disagreements`, `seed`, `performed_by`,
   `date`) onto `gold.json`'s top level. Nothing else in `gold.json` changes.

### 4. What each outcome means

- **`disagreements <= 1`**: the resample passes. `gold.json` now carries the
  block `judge_qualification.gate_eligibility` requires, and (assuming the
  gold's other composition conditions — size, the `l2-fact` floor,
  no author-labelled pairs — already hold, which they do as of this gold)
  the resample stops being a refusal ground. T2.41's `--gate` run can proceed.
- **`disagreements > 1` (a miss)**: the bar failed. Do **not** re-run the
  scorer hoping for a better number — a second scoring of the same draw is
  refused without `--force`, and `--force` is for correcting a genuine bug in
  the comparison itself, not for re-labelling. Per `LABELLING.md`'s own Layer
  3 protocol: read `resample_disagreements.json`, classify each
  disagreement against the rules (was the recorded gold verdict wrong, or was
  the rulebook ambiguous on that pair's construction?), apply rule-then-pairs
  (fix `LABELLING.md` first if the rule was the problem, *then*
  retire-and-replace the affected pair(s)), and only then draw a **fresh
  seeded sample** with `resample_draw.py` against the now-changed
  `gold.json` (which mints a new `gold_sha256` and a new derived seed) and
  repeat this sitting once. Two consecutive failures stop the task (plan
  blocker B4) — that is `LABELLING.md`'s standing rule, not something this
  instrument adds.
- **A refused write (stale sha, coverage mismatch, or a `resample` block
  already present without `--force`)**: nothing was written — `gold.json` is
  confirmed unchanged by the scorer in exactly this case (tested). Read the
  error message; it names the specific mismatch. A genuine second sitting
  (post-correction, against a fresh draw) is the normal path, not `--force`;
  `--force` exists only to correct how a *previous* scoring run itself was
  computed, and if used, the old block stays visible forever under the new
  block's `supersedes` field rather than being overwritten silently.

### N1 — Important (new): no test locks the `scan_run_id` match, and it is the predicate that makes the read-back a read-back

`_VERDICT_READBACK`'s `payload ->> 'scan_run_id' = :run_id`
(`contradiction_scan.py:574`) is what distinguishes *this run's* write from any earlier
verdict on the same fact. I built the adversarial case the fixture shape misses: fact
scanned by run 1 (verdict row lands), sources change again, run 2's write swallowed.

- **Pristine code passes it** — `journal_failed=1`, watermark held. The fix is correct.
- **With the predicate stripped, my driver fails exactly as I2 originally described**:
  run 1's stale row satisfies the EXISTS, `landed` reads true, the dispute is counted,
  the watermark advances over a verdict the veto never received.
- **The shipped suite passes 109/17 against that same mutant.** Both new journal tests
  build the swallow on a fact with no prior verdict row, so the EXISTS is empty with or
  without the run-id match.

Re-scanning a fact whose sources changed again is the steady-state case, not the edge —
so a future "simplification" deleting the predicate (it reads redundant next to the
fact-id and type matches) silently resurrects I2 with the whole suite green. In this
epic a guard no test can defend is one refactor from decorative; this one's key
predicate is in exactly that state. **Fix shape:** one test — prior verdict row inside
the read-back window, then a swallowed write, asserting `journal_failed=1` and the held
watermark. The driver above is the template. No production-code change is needed.

## The fixer's own concern: the substring reference scan firing on prose

**Keep it.** Three grounds, one of them decisive:

1. The precedent that bit this repo — `test_verification_judge.py`'s quoted-token scan
   — is a **regex over raw file text** (`:379`) and fires on `#` comments. The new scan
   walks the **AST**, and comments are not in the AST: only docstrings and real string
   literals can trip it. The historical failure shape cannot recur here in its
   painful form, and `contradiction_scanned` is a far rarer token than `verification`.
2. The substring match is load-bearing, not zeal: an equality-only rule would miss the
   type embedded in a longer SQL string, which is the raw-INSERT case this scan exists
   for. Weakening the match to save prose would delete the guard's purpose.
3. The trip cost is a docstring reword or a conscious allowlist join in the guard's own
   file — cheap, visible, and forced through a diff the equality assertion makes
   deliberate.

One non-blocking refinement: the report claims the assertion message "says what to do";
it actually explains *why* the rule exists and leaves the remedy implicit. Adding
"reword the prose, or consciously join `_VERDICT_REFERENCE_ALLOWLIST`" to the message
would close the gap between a guard that fires and a guard that gets deleted. Recorded
as a deferred minor, not loop-extending.

## What changed and why

The rescope review's independent sweep added a row-width axis (fact ≈ 20, 44,
64, 300 characters) neither the original report nor the fix-round-1 correction
ran. At fact ≈ 44 and 300 characters — both still short for
`knowledge_triples`, whose real `fact` values are lifted sentences — a
selective probe under wholly default settings and fresh statistics chooses the
full-index-traversal `BitmapOr`, the plan the fix-round-1 text said the
planner "does not choose at all" once statistics are real. On the fix round's
own 20-character seed, disabling parallel workers still produced a Seq Scan at
every frequency, so the fix round's item-3 mechanism claim ("what Postgres
falls back to when it cannot spread the scan over parallel workers") was also
wrong, in the opposite direction.

Both defects are the same class N1 named: a checked conclusion in G-C's
evidence trail generalized past what was actually varied. The corrected text
replaces the single "always a Seq Scan" universal with the two-regime,
knife-edge account the rescope settled:

- A sufficiently common value (5%+ frequency) forces a literal heap Seq Scan
  at every row width measured — robust, and the original review's point.
- For selective probes at ~120k scale, the heap Seq Scan and the full-index
  traversal price within a few percent of each other, and the winner flips
  with row width and parallel-worker availability — measured both ways (the
  fix round's own narrow seed always chose the Seq Scan regardless of
  parallelism; the rescope's wider seeds chose the traversal under default
  settings). All three prior measurements on this task happened to sit on
  that knife-edge.
- Wider rows or bigger tables push the selective case toward the traversal,
  because heap pages grow with row width while the three-text-column index
  does not — so the two-regime framing is correct at realistic widths and
  asymptotically correct at scale.
- Statistics freshness is a precondition of measuring any of this honestly,
  not the cause of the crossover.

The shipped fix's justification is restated as unaffected: with the object
index restored, every point measured (every frequency, scale, width, and
parallel setting) returns to the `BitmapOr` on
`ix_knowledge_triples_live_object`.

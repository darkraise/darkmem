1. `?x=1;y=2` vs `?x=1&y=2` staying two — **correct**. No fetcher or browser

   what the committed pin asserts merges; `xn--nxasmq6b` → `βόλοσ` (the IDNA2003

## Why NOT ADDRESSED: the port is reattached before the host passes run

`_canonical_host` reattaches a non-default port to the host string at
`auto_research.py:303`, **before** the trailing-dot strip (`:305`), the IPv6 pass
(`:311`) and the IDNA pass (`:326`). Every one of those passes then either cannot
reach the host (`rstrip(".")` can't see a dot ahead of `:8443`; the IPv6 branch's
`endswith("]")` is false) or refuses the contaminated string (`idna.encode` raises
on the colon and the host is left verbatim). The original finding's item 2 was
literally an ordering bug — dot stripped before the port — and the fix moved the
ordering bug one step later rather than eliminating it. Six adversarial pairs, all
same-source, all split, each checked against the pre-fix module:

| Pair (both spellings, one source) | Pre-fix | Post-fix | Provenance bar |
|---|---|---|---|
| `https://bücher.example:8443/a` vs `https://xn--bcher-kva.example:8443/a` | **MERGE** | **SPLIT** | `str(httpx.URL(...))` emits the right-hand spelling — **regression, New Finding A** |
| `https://straße.example:8443/a` vs `https://xn--strae-oqa.example:8443/a` | split | split | httpx emits the right-hand spelling — residual, headline class |
| `https://example.test.:8443/a` vs `https://example.test:8443/a` | split | split | same argument as repaired item 2, `:443` → `:8443` |
| `https://[2001:db8::1]:8080/a` vs `https://[2001:db8:0:0:0:0:0:1]:8080/a` | split | split | same as the repaired IPv6 shape, port added |
| `https:/example.test/a` vs `https://example.test/a` | split | split | browser-normalised (same bar as the repaired zero-slash shape) |
| `https:///example.test/a` vs `https://example.test/a` | split | split | browser; httpx itself folds `:///` to `:/` |

Default-port composites all merge correctly (`straße.example.:443` ≡
`xn--strae-oqa.example`; `[2001:db8::1]:443` ≡ expanded, portless), which confirms
the cause: the repairs are correct on the bare host and are simply never reached
once a non-default port is glued on.

### New Finding A — Important: the fix regressed IDN hosts carrying a non-default port

Introduced by `500b8118`. Pre-fix, Python's lax IDNA2003 codec tolerated the
port-contaminated string and still punycoded the host, so
`https://bücher.example:8443/a` and the `https://xn--bcher-kva.example:8443/a` this
repo's httpx emits for it were **one origin**. Post-fix, the strict
`idna.encode(host, uts46=True)` raises `IDNAError` on the embedded colon, the
except clause keeps the host verbatim, and the pair is **two attributable
origins** — under the ladder, two same-kind origins ≥ 7 days apart promote at
N = 2, a promotion off a single page. This is the exact failure class the original
review graded at its highest bar, produced by the fix for it. Behind the disarmed
switch like everything here, so operationally inert today; the standing pre-arming
blocker in the v0.5 review covers it.

### The replacement sentence is falsified by the round's own boundary

`CHANGELOG.md:34`: *"the canonicalisation is merge-only against every input anyone
has attacked it with"*. The six pairs above are attacks in the exact families the
version review used, and they split — one of them only because of this round. The
CLAUDE.md reword ("aims to be merge-only … a tested property with named pins,
never a structural guarantee") and the docstring reword are honest and stay true
under these findings; the CHANGELOG lead sentence is the one place the round
restated an attack-closure claim, and it does not survive first contact.

### Item 2 — verified: the served tier cannot be inverted; the ranking still uses the true one

`composed_row_response` computes `tier=tier_for(row.labels.get("verification_status"))` —
a total function of the *served* rung, so the field carries zero bits beyond the label
beside it. Checked the full served vocabulary: `confirmed→4`, `corroborated→3` (only when
the gate is open), suppressed→2, `disputed→1`, memory labels carry no
`verification_status` key → `None` → `MEMORY_TIER 0`; no new raise path, since
`row_labels` output is always in `tier_for`'s vocabulary. Mutation drill (`tier=row.tier`):
**1 failed**, the named knowledge-doors test. The ranking half is pinned the other way by
`test_the_composed_row_still_ranks_on_the_rung_it_does_not_serve` (`row.tier == 3` on the
row whose label reads `candidate`), so a fix that gated the ranking too would fail.
The recompute-over-strip argument is sound: the field stays meaningful at every gate
state and the disagreement — which was the defect — becomes unrepresentable.

Note the tier drill is caught by the door test **only** (a number is not a
`verification_status` emission, so the scan is blind to it by construction). One point of
protection, but a mutation-tested one.

## The question, answered

**Can a serving path now reach a label whose evidence does not exist? No — on every
reachable path, measured, with the guard failing the build on the common shapes of a new
one.** Six doors drive it unfixtured; the producer applies the gate per `id_kind`; the
suppression marker survives every schema; minting the record lights every door with no
code change; and each of this round's seven mutations was caught by at least one named
test, five of them twice.

Three qualifications keep that answer honest, none of which reopens this round:
(a) the rung's *information* — not the label — is recoverable through D2's filter oracle;
(b) the article surface is protected only through `row_labels`, and D1's arm bypasses it —
safe today solely because no article writer exists;
(c) the emission scan does not see constructor-keyword or generic-copy emissions, which
is the exact shape of the next task's response models.

**Is it safe to build T2.28 on this gate? Yes, with two riders for its brief.** The
premise T2.28 needs — the claim lives in the badge, and the badge's producer is singular
and door-enforced — now holds where the review measured it false. The riders: T2.28's
brief must name the scan's constructor-keyword blind spot so its new serving surface is
written (and door-driven) as a `row_labels` consumer rather than trusted to a scan that
cannot see it; and the controller should triage D2 alongside, since minted-corroborated
facts are exactly what the oracle would enumerate.

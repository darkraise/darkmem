## T3.11 — per-tool adapter registry

### Spec compliance: ✅

- **Each adapter names the right file with the right marker syntax.** The four defaults match
  doc 15 §3.3's matrix verbatim (`CLAUDE.md`, `.cursor/rules/darkmem.mdc`, `AGENTS.md`,
  `.clinerules/darkmem.md`; MCP-config column likewise). The marker-syntax half is carried by the
  Markdown-suffix assertion plus `inject_block.py`'s `<!-- darkmem:begin/end -->` sentinels
  (verified in T3.09's module). No adapter→writer integration exists, but the write is
  client-side by design (T3.09 boundary) and the fill is T3.10's — the registry is the whole of
  this task's scope. The mapping is a `config` row merged over committed defaults, which is doc
  15 §3.3's stated requirement, and `scripts/connect.py` (T3.13) already consumes it.
- **Unknown tool refused with a message, not a best guess.** ✅ and verified beyond the shipped
  tests: trailing/leading whitespace, `CLAUDE-CODE`, a U+2010 hyphen homoglyph, and a zero-width
  space suffix all raise `UnknownTool`; the message names the known tools and the config key.
  There is no normalization step anywhere that could smuggle a near-miss through.
- **Refresh at session start only.** ✅ at the registry door — both the `cadence` argument and a
  config-declared `refresh: watch` are refused. Tree-level enforcement is the weak scan
  (finding T3.11-3).
- **Scope creep:** none. The module answers exactly the one question the doc assigns it.

### Task quality: Needs fixes

**T3.11-1 (Important) — malformed config fields fail silently, against the module's own
contract.** `backend/app/services/inject_adapters.py:181-193`. The docstring promises
"malformed entries degrade loudly and are dropped", and that holds for two shapes only (a
non-dict entry; a missing/empty `context_file` after merge). Three other shapes are silent,
demonstrated by driver:
  - a non-string field value — `{"claude-code": {"context_file": 123}}` — is filtered by the
    `isinstance(v, str)` comprehension at `:192` with **no log**; the shipped default survives
    and the adapter looks fully functional;
  - an unknown key — `{"claude-code": {"context_fil": "MOVED.md"}}` — is merged and ignored,
    no log;
  - a config row whose whole value is not a dict (a JSON array or string at the top level) is
    treated as absent at `:181`, no log.
  Concrete failure: the operator believes they moved a tool's context file (the exact scenario
  doc 15 §3.3 builds the config row for); blocks keep landing in the old file; no warning, no
  refusal — the silent failure the module's own docstring exists to forbid. By contrast, an
  override to `""` drops the shipped tool loudly (warning + `UnknownTool` at the door), which is
  defensible. Fix: warn on every discarded field/entry shape, symmetric with the two shapes that
  already warn.

**T3.11-2 (Important) — two documented invariants are unenforced at the config door.**
  - `Adapter`'s docstring (`inject_adapters.py:115-120`) states `context_file` "is never
    absolute". Driver: `{"evil": {"context_file": "/etc/passwd"}}` yields
    `Adapter(context_file='/etc/passwd')`. The hazard is real for any consumer that trusts the
    documented guarantee: in Python, `Path(workspace) / "/etc/passwd"` **is** `/etc/passwd` —
    a workspace escape. The test `test_the_path_is_project_relative_never_absolute` runs under
    per-test rollback with no config row, so it proves the property for the committed defaults
    only.
  - The Markdown-suffix assertion (attack: does it protect anything?) likewise binds the shipped
    set only. A config-added target (`{"docs": {"context_file": "context.rst"}}`) is accepted,
    and the un-parameterised HTML-comment markers would be written into it with no redden
    anywhere — the commit's claim that a foreign comment syntax "reddens here rather than
    writing a broken block" is true for a default added in code, false for the config door,
    which is the door the design advertises. (Mitigating: in a plain-text context file the
    sentinels still function as strip-and-rewrite bounds; a strict format like TOML/JSON would
    break. So the suffix facet alone would be Minor; the absolute-path facet is not.)
  Fix: validate config-supplied `context_file` in `get_adapters` (reject absolute paths at
  minimum, ideally warn on non-Markdown suffixes) or reword both documented guarantees to
  "defaults only".

**T3.11-3 (Minor) — the cadence scan is a tripwire, not a guard.**
`backend/tests/test_inject_adapters.py:407-430`. Measured reach with a synthetic file carrying
five scheduling shapes: it caught **1 of 5** — only `registry.register("inject_refresh", ...)`
with the literal (or an inject-named constant) in the call text. Missed: the repo's own
convention of registering via a key constant when the constant is innocuously named
(`CONTEXT_REFRESH_JOB_KEY = "inject_refresh"` — plausible naming for this feature; CLAUDE.md
itself records that constant-registered jobs are "precisely how this sentence went stale for
four landings"); scheduling verbs outside `{register, add_job, schedule}` (`scheduler.add`,
`asyncio.create_task(inject_refresh_loop())`); and wrapper functions
(`register_inject_job(...)`). Additionally `Path("app")` is cwd-relative: run from any directory
but `backend/`, `rglob` on the missing dir returns empty and the test **passes vacuously** —
the sibling scan `test_event_taxonomy_map.py` anchors on `Path(__file__).resolve().parents[2]`
and this one should too. It is still worth having (it catches the most likely regression shape,
a job honestly named inject), but the commit message's "a scan asserts nothing in the tree
schedules an inject" overstates it. Also a nit: `path.read_text()` is re-read per matching node.

## T3.12 — inject records journaled as events

### Spec compliance: ✅ with one clause ⚠️ (controller adjudication)

- **Each inject writes an event carrying the item ids and the budget used.** ✅ at the primitive:
  re-run verified the payload lands with the three separate id lists, served order preserved
  within each list, and `budget_tokens`/`tokens_used` both recorded; the exact-key allowlist and
  the per-value `UUID()` parse are real assertions against a DB-read payload, not fixtures. Note
  the clause is **vacuous at system level**: nothing calls `record_inject` (no producer;
  T3.10 owns the fill and is gated — plan-sequenced, the module says so honestly). Nothing yet
  enforces that every future inject routes through this writer; that obligation transfers to
  T3.10's review.
- **Records surface in the timeline and calendar.** Calendar: ✅, driven through the shipped
  `calendar_counts` reader (the real `ix_events_day` UTC bucket expression). Timeline: ⚠️ —
  see T3.12-2. The records demonstrably reach `list_events` (the activity feed's `/events`
  reader and the `/activity/day/$date` drill, which doc 13 §6.4's diagram explicitly says
  includes inject records). They can **never** reach the reader doc 13 §6.4 defines as "the
  timeline" — `object_timeline` / `GET /events/timeline` — because `record_inject` writes
  `object_id=None` and that reader's WHERE requires an equality match on it. Which reader the
  done-when means is the controller's call; as written, one reading is satisfied and tested,
  the other is unsatisfiable by construction and untested.
- **Scope creep:** the `injected_ids` helper was not asked for (and is wrong — T3.12-1). The
  frontend taxonomy change is *not* creep: I verified `test_event_taxonomy_map.py`'s one-hop
  resolver now sees `event_type=INJECT_EVENT` as a live emitter (`inject`/`inject_curbed` both
  resolve), so without the taxonomy edit that guard reddens — the edit was mandatory, and the
  exclusion (no sixth tab; timeline/calendar + Settings→Distribution per doc 13 §6.5) is the
  correct classification.

### Task quality: Needs fixes

**T3.12-1 (Important) — `injected_ids` returns the wrong served order.**
`backend/app/services/inject_journal.py:202-212`. The docstring says "Every id one inject
payload names, **in served order**", and the commit message says the sequence "records the
priority the budget actually spent". Doc 15 §3.4's fill order is **L2 facts → L3 articles →
L0 memory summaries**; the helper iterates `("memory_ids", "fact_ids", "article_ids")`.
Driver: for a payload served `['f1','a1','m1','m2']` the helper returns
`['m1','m2','f1','a1']` — memories promoted ahead of facts, the exact inversion of
truth-first. Any consumer reconstructing "the first N items the agent saw" gets a false answer
from the module's own reader. Fix: iterate `fact_ids, article_ids, memory_ids` and pin the
tuple where T3.10 can share it. On attack 7 generally: the three-list shape can only represent
a strictly layer-ordered fill — cross-layer interleaving is unrepresentable — which is fine
*because* §3.4's fill is strictly layered; but that makes the one place encoding the layer
order load-bearing, and it encodes it backwards. (Also fold in: the `list[UUID | str]` return
annotation is misleading — payload values are always `str`.)

**T3.12-2 (Important) — the by-object timeline can never show an inject, and the suite dodges
the reader its own docstring names.** `inject_journal.py:160/196` write `object_type="system"`,
`object_id=None`; `events.py:405-435` (`object_timeline`, backing `GET /events/timeline`)
requires a non-null `object_id` equality. So no object's history — including a memory's — can
ever render "this was injected into claude-code on T", even though doc 13 §6.4's diagram lists
`inject` among the transitions the timeline renders; the ids live only in payload arrays, the
same payload-key limitation `object_timeline` already documents for code-graph objects, except
here it is undocumented. The test module's docstring even says the timeline "keys on
`object_id`" and claims "this suite drives the shipped readers" — then drives two of the three
and never `object_timeline`. Precedent exists for the shape (`maintenance_run` is also
system/None), and a one-event-per-push record genuinely has no single object id, so the shape
may be the right call — but then the limitation must be stated at the writer and the done-when
adjudicated on the looser reading. Report, not softened: as shipped, "surface in the timeline"
is either false or untested depending on which reader is meant.

**T3.12-3 (Important) — both writers discard `record_event`'s return, foreclosing the caller's
T2.113 choice.** `inject_journal.py:156/191` — `record_event` returns whether the row landed
precisely because "that contract is right for most callers and wrong for a few"; here the
journal **is** the deliverable (the done-when's "each inject writes an event"; invariant 14's
"never a silent context swap"; doc 15 §7's honesty framing covers client-side write failure,
not journal failure). On a `False`, the push proceeds with no durable record and no caller can
ever know — `record_inject` returns `None`, so T3.10 cannot even choose to refuse or retry.
The module claims to be "fully functional the moment a caller exists"; for this contract it is
not. Fix is one line per function: return the bool (raising would be the ladder's stricter
contract and is a design call the controller/T3.10 can make; returning the signal is the
minimum).

**T3.12-4 (Minor) — stale guard docstring left behind.**
`backend/tests/test_event_taxonomy_map.py:14-16` still says inject/inject_curbed "are in this
state today: the vocabulary carries them, nothing calls `record_event` with them". False since
this commit — they are the guard's own worked example and it now misdescribes them, the exact
stale-claim class CLAUDE.md's invariant-23 notes exist to catch. T3.12 updated the frontend
file's comments but not this one.

**T3.12-5 (Minor) — the payload allowlist prevents new keys, not content through existing
keys.** `test_inject_events.py:308-328` pins the exact key set and UUID-parses the id lists —
a real guard against the writer growing a `content` field (I confirmed the assertion binds: the
payload is read back from the DB and the key set is exact). Residue, for the record: `tool` and
`context_file` are unconstrained strings a future caller could route prose through;
`budget_tokens`/`tokens_used` are unvalidated (`json.dumps(..., default=str)` will serialize
anything); and the `inject_curbed` payload has no shape test at all (`reason` is deliberate
free text — human-entered, small — but untested). None of this is reachable today (no caller);
recorded so T3.10's review checks the caller side.

**T3.12-6 (Minor) — the frontend-file assertion is weak on its own, but the strong guard holds
the property.** `test_inject_events.py:401-411` asserts `'"inject"' in <file text>` — currently
binds to the real `EVENT_TYPES_WITHOUT_TAB` entries (grep: the only quoted occurrences are the
Set lines), cannot be satisfied by `"inject_curbed"` for `"inject"` (quote-delimited), but
would be satisfied by a quoted mention in a comment and does not distinguish tab from
exclusion. Acceptable because `test_event_taxonomy_map.py` independently enforces
classification now that the emitters are live (verified by running its resolver directly).

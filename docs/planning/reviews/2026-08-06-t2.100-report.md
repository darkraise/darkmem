# T2.100 — A declaration that says the wrong thing

**Lane:** `feat/e2-lane-cc` (worktree `.worktrees/e2-lane-cc`)
**Date:** 2026-08-06
**Depends:** T2.99 (its AF1 is where this was found)
**Doc:** 08 §4.3, 12 §4 · **Gate:** standing

## What was wrong, and what was not

`claim_gates.ungated_status` defined wrapping a value as **a claim that the
value reaches no reader as a label**. The ladder's journal sites wrapped it.
`GET /api/v1/events` then served that payload verbatim, under the same
`require_auth` as the facts door, with `event_type` filterable — so for any
fact that has ever transitioned, the withheld rung was directly readable, with
none of the subtraction the two closed oracles needed.

**The exposure is ruled acceptable and this task did not close it.** No
filtering, redaction or gating was added to the events door. The ruling's three
reasons (amendment log, 2026-08-06) stand: G-C's own false-promotion audit
reads this journal, so narrowing the substrate to protect the gate would
degrade the evidence the gate is measured with; T2.59 settled the analogous
content-residue question the same way; and a journal row and a claim surface
are different speech acts.

What was fixed is the **declaration**. A false one is worse than an undeclared
site: an undeclared site trips the scan and gets looked at, a falsely declared
one is trusted by the scan and by the next reader.

## The split

`ungated_status` is gone. Two markers replace it, both calls rather than
comments — the scan reads the parsed tree, and that property is exactly why
prose can neither claim the exemption nor trip the guard:

| Marker | Claims | Checked by |
|---|---|---|
| `claim_gates.unserved_status` | the value reaches **no reader at all** | driving every door the site feeds and searching the whole body for the promoted rung |
| `claim_gates.journalled_status` | the value reaches a reader **as a record of a computation**, never as a claim | driving `GET /api/v1/events` and asserting the rung *is* there |

`claim_gates.STATUS_DECLARATIONS` binds the pair, and the scan reads its
admitted names from that binding rather than spelling them, so the module and
the guard cannot drift into different vocabularies.

`ungated_status`'s docstring no longer asserts something untrue of its own call
sites, because it no longer exists. `journalled_status`'s docstring carries the
ruling and the honest form of the M1 safety sentence: *no **claim surface**
serves an unbacked label; the audit journal records the ladder's own
transitions and an authenticated operator can read them.*

`ungated_mapping` was **not** split. Its docstring already stated two
disjuncts ("carries no verification status at all, or the copy is internal"),
neither of which is false at any of its six sites, and no site carrying it
lands in a journal payload — so a second mapping marker would state a
distinction nothing exercises. That is not left on trust: the journal-direction
guard below treats `ungated_mapping` inside a journal writer as an offence, so
the day a wholesale copy does reach `/events` the build fails rather than the
missing half being discovered by a reader.

## Per-site classification

Every site was decided on its own, by following the value to its consumer.

| Site | Marker | Why |
|---|---|---|

This is the row G-C's promotion-rate and false-promotion SQL reads, and `/events` serves it to an authenticated reader. A gated copy would record a movement that did not happen. |
| `knowledge_triples.KnowledgeTripleRepository.ratify` (×2, `before` / `after`) | `journalled` | Same writer, same reader, the human-ratification transition. |
| `human_adjudication.record_human_verdict` (×1) | `journalled` | The verdict payload's own `verification_status` — the rung the fact held when the human acted. Journalled and served on `/events?event_type=human_verdict`. |
| `human_adjudication.reject_fact` (×1, keyword into `record_human_verdict`) | `journalled` | The same value one hop before the journal writer. The hop does not change where it lands. |
| `human_adjudication.ratify_fact` (×1, keyword into `record_human_verdict`) | `journalled` | Ditto, on the ratification door. |
| `human_adjudication.reject_fact` (×1, returned dict) | `unserved` | The REST door answers **204 with no body** and discards this dict; it exists for an in-process caller's bookkeeping. Same source value as the row above, different destination — which is precisely the distinction the old single marker could not express. |
| `facts_channel._row_to_candidate` (×1) | `unserved` | A ranking input. Doc 12 lets the composition consume promoted rungs internally; the served label is built downstream by `fact_badge.row_labels`. The reranker receives only `_resolve_document_text`'s resolved text, not the row's keys, so the rung does not leave the process there either. |
| `layer_composition.fact_candidate` (×1) | `unserved` | `LayerCandidate.verification_status`, the ranking's copy. `ComposedRowResponse` carries no such field, and `tier` is derived from the *served* label. |
| `layer_composition.article_candidate` (×1) | `unserved` | Same, for the L3 channel that T3.02 will produce. |
| `layer_composition.compose` (×1) | `unserved` | `ComposedRow.verification_status` — the row still *ranks* on its true tier, and the wire schema does not carry the field. |

Nothing was bulk-migrated. The two sites in `reject_fact` read the **same**
column value into two variables and got different markers, which is the
clearest evidence the classification was done by destination rather than by
file.

The classification is pinned in `DECLARATION_INVENTORY`
(`tests/test_claim_serving_gates.py`) as `relpath → marker → qualname → count`,
so re-classifying a site is a visible diff and adding a declared site is an
argument someone makes there rather than a wrap reached for to quiet the
emission scan.

## How the scan distinguishes the two

Three arms, all in `tests/test_claim_serving_gates.py`:

1. **The emission scan is unchanged in reach and still fails the build on an
   undeclared emission.** It now admits both markers, drawn from
   `claim_gates.STATUS_DECLARATIONS`.
2. **`journal_bound_denials` is the new directional guard.** A value flowing
   into a `record_*` writer — inline in the call, or bound to a name a
   statement earlier, or written into that name afterwards — may not carry a
   declaration that denies a reader (`unserved_status` or `ungated_mapping`).
   This is the T2.100 defect stated as a property.
3. **`DECLARATION_INVENTORY`** pins which marker each site carries.

Reach, stated rather than implied: arm 2 is one hop within a module. A value
handed to an ordinary function that itself journals is invisible to it. What
covers that is the events door drive, which reads the payload rather than the
call.

### Drill 2b found a defect in the guard, which is why it is worth recording

The first version of `journal_bound_denials` collected tainted names from
`ast.Assign` only. The live journal site is
`payload: dict = {...}` — an **`AnnAssign`** — so the guard passed its own
parametrized self-test (whose snippet used a bare `payload = {...}`) while
being blind to the one shape in the tree. That is the same failure the honesty
scan's docstring records about its predecessor: *the self-test that proved the
guard "could fail" planted the single shape inside its own blind spot.*

Fixed by reading any simple statement (`Assign` / `AnnAssign` / `AugAssign` /
`Expr`) for a denial anywhere in its subtree and tainting every name it writes
through — target, subscript base, or method receiver. Compound statements are
deliberately excluded: reading a whole `def`'s subtree would taint every name
the function writes, including the row a journal call legitimately reads from
two statements away. Three shapes were added to `DENIAL_SHAPES` so the closed
blind spot stays closed: the annotated binding, `payload[...] = ...` after
construction, and `payload.update(...)`.

## Driving the door, not reading the call site

The done-when clause is *no site declares "reaches no reader" while a route
serves it — proven by driving the door*. Three unfixtured door drives, none of
which may take `cleared_record`:

- **`test_the_events_door_serves_the_journalled_rung_verbatim`** — a real
  `set_verification_status` transition, then `GET /api/v1/events?object_type=
  fact&event_type=verified`; asserts `payload.before = candidate` and
  `payload.after = corroborated`. This asserts the exposure rather than
  merely tolerating it: anyone "fixing" it by gating the events door has to
  delete this test to do it, which is the review that change deserves.
- **`test_the_rejection_journals_the_rung_and_returns_none_of_it`** — both
  halves of the split on one value in one call. The verdict payload carries
  `corroborated` to an authenticated reader; the response is 204 with
  `content == b""`.
- **`test_no_unserved_declaration_reaches_a_reader_at_any_door`** — REST facts
  list, REST fact detail, MCP `fact_get`, REST knowledge search, MCP
  `knowledge_search` and the chat context, each asserted to contain the string
  `corroborated` **nowhere in the body**. Deliberately stronger than the
  existing per-field assertions, which read one key and pass while the same
  value rides a second one — how `tier` served the withheld rung as a number
  for as long as it did.

Reach of that last drive, stated: it covers the badge-bearing composed path,
which is what every live door uses. The `compose(badges=None)` path — where
`_labels` is the served dict — is not reachable from a route today and is
covered separately by `test_a_composition_without_badges_serves_the_withheld_
rung_too`. Drill 5 was first run against `_labels` and passed, because
`_badge_labels` overwrites it on every live path; re-running it against
`_badge_labels` failed as expected. Recorded because the first result would
have read as a toothless drill if left unexplained.

## Concerns

- The events exposure remains, by ruling. It is now asserted by a test rather
  than merely known, which means the ruling is enforceable but also that
  reversing it is a deliberate multi-file act. That is the intended cost.
- `journal_bound_denials` is one hop. A future journal wrapper that is not
  named `record_*` and that takes a status through a second function would be
  invisible to it. The prefix convention is the whole basis of the rule and is
  stated at the constant.

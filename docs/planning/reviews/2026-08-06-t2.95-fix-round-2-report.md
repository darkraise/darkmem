## G1 — the scan now sees the shape T2.28 will write

### What changed

`_emissions` asked three questions and now asks five, and `ungated_label_emissions` asks a
second kind of question of the modules that serve the claim.

1. **Call keywords, every callee.** The keyword rule was scoped to `dict(...)`, so
   `SomeResponse(verification_status=row[...])` — how a FastAPI route builds its response,
   and what T2.28's serving surface will be — passed. It now fires on any call, with the
   producer's and the gate's own entry points (`row_labels`, `served_status`,
   `ungated_status`, in `GATE_ENTRY_POINTS`) admitted: a keyword handed to one of those is
   the raw rung going *into* the gate, which every serving path has to do and which is the
   opposite of an emission. That subsumes `.update(verification_status=...)`.
2. **`setdefault("verification_status", v)`**, which writes the entry positionally and so
   was invisible to both the keyword rule and the literal one.
3. **Wholesale mapping copies** — `dict(row)`, `{**row}`, `{k: row[k] for k in COLUMNS}` —
   in modules that serve the claim. These emit the label while naming no such string, so
   every key-based rule is blind to them by construction. The rule asks the same question
   the others do, where did the value come from, of the *mapping* rather than of the entry:
   a source this module built here (literal, comprehension, empty constructor), a
   producer-built `*labels` mapping, or another function's return value is accounted for;
   a parameter, a loop variable over a database result, or an attribute is not.
4. A literal `None` is admitted, because the absence of a status is not a status. The
   memory candidate says `verification_status=None` explicitly, and a memory's lifecycle
   `status` is a different vocabulary.

**Reach and blast radius, measured before choosing it.** A wholesale-copy rule applied to
every module under `app/` flags 233 sites; applied to every module that touches the fact
substrate, 37 across 12 modules — mostly parameter dicts and score maps, where a
declaration would be noise that dilutes the marker everywhere it matters. Applied to
modules that call the producer it flags 12, in 3 modules, all of them the claim surface
round 1 already owns. That is the version that shipped. **The trigger is not a file list:**
a module that serves the claim calls `row_labels`, that is the enforced design, so T2.28's
new surface is inside the rule the moment it is written correctly — and if it is written
*incorrectly*, without the producer, the keyword rules catch it the moment it names the key.

**Declaration sites.** Seven copies that legitimately reach no reader as a label now say so
with `claim_gates.ungated_mapping`, the same contract and the same call-not-comment
reasoning as `ungated_status`: the rerank documents and badge-derivation rows in
`layer_composition` (1249, 1303), its channel-status map (1456), the review queue's two SQL
row copies (337, 401), and the composed row's `dispute` / `grouping` blocks in
`schemas/knowledge` (278, 279). Four call keywords gained `ungated_status`: the layer
candidates and the composed row (`layer_composition` 462, 482, 963) and the human-verdict
journal arguments (`human_adjudication` 203, 292, whose payload entry was already
declared).

## G2 — the filter keys on the served status

### What changed

`facts_read.list_facts` takes `served_status` rather than `verification_status`, resolves it
through `claim_gates.raw_statuses_for_served`, and hands the resulting set to
`KnowledgeTripleRepository.list_live`, whose filter parameter is now
`verification_statuses: Collection[str] | None`. An empty set matches nothing, which is the
honest page: with the gate closed nothing is *served* as `corroborated`, so the result is no
rows rather than the rows whose label was withheld.

`raw_statuses_for_served` is written as the **preimage of `served_status`**, evaluated by
calling it, not as a table beside it — a table would be a second implementation of the gate
and the disagreement between filter and field is precisely the defect. Its completeness
argument is one sentence and is in the docstring: `served_status` rewrites only values in
`PROMOTED_STATUSES`, so anything serving as *X* is either *X* itself or a promoted status,
and those two sets are the whole domain to search.

The route's query parameter is unchanged (`?verification_status=`), so no wire contract
moved; only what the backend matches it against did.

**One pre-existing test was rescoped.** `test_facts_read_surface.py::test_verification_status_is_an_opt_in_filter`
filtered on `corroborated` with the gate closed and asserted the corroborated fact came
back — which is the oracle, asserted as a feature. Its subject is the filter being opt-in
rather than defaulted, so it now takes `cleared_promotion_record` and measures what it is
about. The suppressed-gate behaviour of the same door is asserted in the gate suite, twice,
unfixtured.

**One adjacent guard fired, correctly, and I did not weaken it.** The first spelling of the
filter was the house idiom `verification_status = ANY(CAST(:v AS text[]))`, which turned
`tests/honesty/test_human_only_confirmed.py::test_exactly_the_permitted_writers_touch_the_verification_axis`
red: that scan reads a bare `verification_status =` binding as a *write* to the column, and
deliberately so, because the one shipped writer builds its SET list as exactly such a
fragment. Rather than add `list_live` to a writers' allowlist or loosen the predicate in
another spec's guard, the membership test is spelled
`verification_status IN (SELECT unnest(CAST(:v AS text[])))`, which is not an assignment
shape in any reading. The constraint is recorded in a comment at the site because it is not
inferable from the code. See the adjacent finding below.

## Adjacent finding, reported not fixed

**The verification-axis writer scan classifies `verification_status = ANY(...)` as a
write.** `tests/honesty/test_human_only_confirmed.py::_sql_assigns_column` counts a binding
with no clause keyword as an assignment, error direction chosen so an unrecognised shape
lands on a human. That fail-safe is right, and the shape it caught here was a filter. The
hazard is the *next* person who meets it: the cheap-looking fix is to add their function to
`_PERMITTED_WRITERS`, which would be a real weakening of the human-only-`confirmed` spec to
accommodate a read. The sound narrowing is one clause — `= ANY(` and `= ALL(` are comparison
contexts that PostgreSQL rejects as a `SET` target, so they can never be a write — but that
guard belongs to the honesty spec, not to this lane, and I did not edit it. Recorded for its
owner.

## The question the brief asks

**Is the gate now strong enough that T2.28 can add a labelled surface without being able to
bypass it by accident? Yes — with one rider, which is a sentence in T2.28's brief rather
than a further round here.**

What holds, measured this round on top of round 1's six items: the response-model
constructor idiom — the exact shape T2.28's serving surface will take — now turns the build
red, demonstrated by a plant that the previous commit's scan passed green. `.update`,
`setdefault` and the wholesale copies that put a label on the wire without naming it are
covered inside every module that serves the claim, which T2.28's will be. The filter and the
field can no longer give two answers about the same row, because one is computed by
inverting the other, and both directions are driven at the live door. And the seventeen
shapes the re-review invented are now a checked table, so the next task inherits a stated
reach instead of an assumed one.

**The rider is shape 17.** A module that copies a fact row wholesale and *never calls the
producer* is invisible to every structural rule here — the copy rule is scoped to
producer-calling modules precisely so that the declaration marker stays meaningful, and a
module that serves the claim without ever asking the producer is the failure the whole task
forbids and the one thing no value-origin scan can see. Two things make that acceptable
rather than open: such a module cannot serve the badge (it has nowhere to get one), and it
would have to be a new surface with no door test — so **T2.28's acceptance must include a
door drive with the gate closed**, exactly as this suite's six are, and not rest on the scan
alone. That is the same rider the re-review put on round 1, narrowed from "the scan cannot
see constructor keywords" to "the scan cannot see a copy in a module that never calls the
producer" — which is a strictly smaller hole and one a door test closes.

Unchanged and still outstanding, all out of this round by the brief: the unbound record
(T2.40's schema, so the operative sentence remains "no promoted label without a *record*"),
`verification_judge`'s untouched `gate=` seam (T3.02/T3.23), the articles arm's raw `status`
(T3.02/T3.23), and the three ratified residues.

## Shape chosen

**Environment variable override with main-checkout fallback.** The script resolves the Python interpreter with this priority:
1. `PY` environment variable (if set by user)
2. Local `.venv/bin/python` in the worktree (if it exists)
3. Main checkout's `.venv/bin/python` (fallback when worktree has no local .venv)

The resolution is explicit and reported on stdout before any gates run — even before preflight checks — so lanes cannot silently test against the wrong tree's code.

## Implementation

### Interpreter resolution logic

```bash
# Resolve Python interpreter: allow env override, prefer local .venv, fall back to main checkout
if [ -z "${PY:-}" ]; then
    LOCAL_PY="$BACKEND/.venv/bin/python"
    if [ -x "$LOCAL_PY" ]; then
        PY="$LOCAL_PY"
    else
        # No local .venv; fall back to main checkout's interpreter.
        # Use git to robustly detect if we're in a worktree: git rev-parse --git-common-dir
        # returns the shared .git directory for both main checkout and worktrees.
        # In a worktree at /path/to/worktrees/<name>, it returns /path/to/.git,
        # so the main checkout is its parent.
        if GIT_COMMON_DIR="$(cd "$REPO_ROOT" && git rev-parse --git-common-dir 2>/dev/null)"; then
            # We have a git repository; use git-common-dir to find the main checkout
            MAIN_CHECKOUT="$(cd "$GIT_COMMON_DIR/.." && pwd -P)"
        else
            # Fall back to current directory if git fails
            MAIN_CHECKOUT="$REPO_ROOT"
        fi
        PY="$MAIN_CHECKOUT/backend/.venv/bin/python"
    fi
fi
```

### Worktree detection: design choice

**Why `git rev-parse --git-common-dir` instead of directory name matching:**

The original implementation checked if the parent directory was named `.worktrees` by convention. While this works for this repo's structure, `git rev-parse --git-common-dir` is more robust because:

1. **Layout-agnostic**: Works if a worktree is created anywhere (`git worktree add /tmp/feature` or `/mnt/external/work`), not just under `.worktrees/`
2. **No manual path string manipulation**: Returns the actual shared `.git` location; its parent is definitively the main checkout
3. **Already a dependency**: The gate script already calls `git` multiple times (e.g., checking freeze tag), so this adds no new dependency
4. **Graceful fallback**: If git fails, the script falls back to `REPO_ROOT` (which works if `.venv` exists locally)

A worktree created outside this repo's `.worktrees/` directory would fail the directory-name check and incorrectly resolve `MAIN_CHECKOUT` to itself, then fail the preflight `-x "$PY"` check with "backend venv missing". With the git-based check, it finds the correct main checkout regardless of location.

### Critical fix: reporting before preflight

The interpreter message prints **after line 108** (where the resolver finishes) and **before line 124** (the first preflight check). This ensures:
- In a worktree where `frontend/node_modules` is gitignored, the interpreter is still reported before the gate blocks
- A lane cannot run the gate and miss which Python it's testing against
- The gate's failure reason is clear: it blocks on a missing dependency, not on the interpreter

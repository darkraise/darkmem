## 4. Findings

**I1 (Important) — the live-call budget is understated by ~40%.**
`promotion/cache/` is gitignored and **absent on this machine** (verified), so the
first pass extracts all **849** captures live, not the "~+603" the plan (Step 4), the
commit message and the review brief state. The ~603 figure assumed the T2.129-era
cache of the original 246 captures still existed; the brief's own "the promotion
cache does not exist on this machine" premise contradicts its own count. This changes
the price of the owner's authorisation, not the verdict — but the authorisation
should be for ~849 seeded calls against `deepseek-v4-flash` (wave 1: 847, wave 2: 2),
with the second pass replaying from the then-written cache at ~0 live calls.

**I2 (Important) — a coverage claim the tests do not provide.** The progress row
states the fleet shape — "each new repo inside 40–90 imports, each leaving 19–21%
unclaimed, sharing a 17-package core" — is "all three asserted by test rather than
described". The committed test (`test_the_fleet_stays_inside_its_adjudicated_ceiling`)
asserts only ≤ 6 repos, ≤ 101 imports each, and a **non-empty** shared core. Nothing
asserts the 40–90 band or the ≥ 10%-unclaimed floor, both §0(a) adjudicated
conditions; a future edit claiming a new repo to 100% of its imports would pass every
test. The committed data does satisfy the shape (measured: 62–69 imports per new
repo; unclaimed 13/69 = 19%, 14/69 = 20%, 14/65 = **22%**, 13/65 = 20%, 12/62 = 19% —
so "19–21%" is also off by a point at the top), but this epic's own precedent is that
a false "a test catches this" sentence is load-bearing (`promotion_metrics`' mirrored
bar comment, T2.132). Fix is small: extend the ceiling test with the two bounds, and
correct the row to "19–22%".

**M1 (Minor) — the embedder merge screen is not reproducible from committed state.**
The "15 name pairs ≥ 0.85, four replaced" figures rest on an uncommitted offline
screen; no script or output is in the tree. Its *effects* are verifiable (the
replacements are in the data; the atlas guard condition holds), but the screen itself
cannot be re-run without re-deriving the method. Commit the screen script or its
output alongside Step 4's artifacts.

**M2 (Minor) — one growth capture brushes the no-replacement-language hygiene rule.**
`ts-pyjwt`: "…the banks that moved to token auth". No inverse pair, no second
technology named, k cannot move (§3.2's withdrawal is structural), worst case is a
stray extractor relation in `default`; recorded as drift against the commit's "No
growth capture carries replacement language", not as a hazard.

**M3 (Minor) — the review brief's "264 claims" framing.** The corpus adds 377 claims;
264 is the diversity arm alone. 264 diversity claims by themselves would *not* reach
the window (131 + 256 = 387 < 473); the committed corpus reaches it because the 113
`none` claims ride with them. Recorded so the arithmetic is not later quoted off the
brief instead of off the corpus.

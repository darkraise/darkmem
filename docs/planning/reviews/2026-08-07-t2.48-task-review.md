## 2. The nine attack lines, resolved

### 2.1 The scoping deviation (sha comparison instead of the persisted file set)

**Sound, honestly costed, and pre-authorized — but mis-tiered (finding I-2).**

- The brief itself listed "drop the scoping … say so as an amendment rather than quietly"
  as a candidate; the executor chose it and declared it. Proceeding was within the granted
  mandate; this was not a silent override.
- The reasoning holds where it aims: a changed-set persisted **through an event payload**
  does depend on `record_event`'s never-raise contract, and the healing backstop would be
  exactly this sha comparison. The report does not fully rebut the **durable-column**
  variant (`index_debt` is a column, not an event) — but that variant needs accumulation
  across runs, clear-only-after-success, and partial-batch semantics, and per finding 2.2
  the doc's literal scoping key is defective anyway, so the file-scoped design could not
  have been built as written without its own amendment. The sha design strictly dominates
  on self-healing and gives idempotency from the same stamp.
- Cost verified against the code: the candidate SELECT is bounded by total code-citation
  rows (`source_kind='code'` filter); per-HEAD-move work is that repo's citation count
  (doc sizes it 10–200) — one key-resolution statement per repo plus one small jsonb write
  per citation. The claim "an unchanged file's citation is re-resolved once per HEAD move
  instead of never" is the honest statement of the trade. One imprecision: report §2 calls
  the resolution "one indexed `(repo_id, key)` lookup"; the only index is
  `UNIQUE (repo_id, kind, key)`, so the probe uses the `repo_id` prefix and filters keys —
  bounded by the repo's node count for that statement. No consequence at Tier-C scale
  (finding M-4).
- Two-runs-between-ticks: correctly analyzed — one HEAD survives, resolution is against
  the graph as it stands, the intermediate set is irrelevant. Also checked: `code_pipeline`
  advances `last_indexed_commit` **only on full success** (`code_pipeline.py:290,363`), so
  a tick landing mid-re-index sees the old HEAD and selects nothing for that repo; there is
  no torn-graph false-stale window for freshly stamped citations.

### 2.2 The claim that doc 10 §6 is wrong — CONFIRMED, and it generalizes

Verified at the producer, not from the report: `fact_lift.py:875` (language basis:
`symbol_key=file_path`, a path) vs `fact_lift.py:895` (import basis:
`symbol_key=target_key`, a **module key**, `file_path=source_key` the witness file). Doc 10
§6's literal predicate — rows "whose `detail.symbol_key` falls in the run's changed/deleted
file set" — can therefore only ever match language citations; every import-basis citation
(`httpx`, `github.com/foo/bar`) is invisible to it, and a literal implementation re-verifies
the minority basis and reports success. This is **structural, not a fixture artifact**: the
two lines are unconditional, so the defect covers the entire import-basis population
regardless of ratio (my independent census: 5 of 7 citations import-basis on the committed
fixture; the majority-import shape generalizes since repos have more deps than languages).
`detail.file_path` is a path for both bases and is the field a future file-scoped
optimisation must match on (or union both keys). **This is a real design-corpus defect and
needs the doc-owner's edit** — see finding I-2 for the tiering.

## 3. Findings

### Important

**I-1 — `citation_stale` missing from the frontend event-taxonomy map.**
`frontend/src/features/activity/event-taxonomy.ts:13–28`. The new event type is absent from
`EVENT_TYPE_CATEGORY`, so `categoryOfEventType` returns null and the event appears only
under the feed's "all" tab — invisible under the verification tab where `verified` and
`contradiction_scanned` (its closest kin) both live. The map's own docstring reserves
unmapped status for types that fit no tab; this one fits cleanly. Exact repeat of the
`contradiction_scanned` miss a prior round flagged in this same file, and this task did
touch the frontend, so the map was in reach. One-line fix (`citation_stale:
"verification"`, matching the `contradiction_scanned` precedent — "code" is arguable, the
fixer picks one).

**I-2 — The design-corpus deviation and the doc defect are mis-tiered, and no amendment
log row exists anywhere.** Report §2 calls the cost-bound deviation "a Tier-1 amendment in
effect" and §6 labels the doc-10-§6 vacuity defect "Tier 1, recorded, not acted on". Under
runbook §5 both are Tier-3-shaped: "a design doc is wrong" is a named Tier-3 trigger, and
the shipped design abandons the doc's Decision-paragraph cost bound. The mitigation is
real — the brief pre-authorized exactly this deviation conditional on declaration, the
report is a complete write-up, and the lane-cannot-edit-canonical-docs constraint (report
C3) is genuine — so this is a **procedural** finding, not a code defect: the diff touches
no epic amendment log, and a Tier-1 label lets a corpus divergence slide through without
the Fable-tier ratification Tier 3 demands. Before G-C leans on this task, the controller
should (a) record the amendment at its true tier, (b) route the doc 10 §6 correction
(`detail.file_path`, not `detail.symbol_key`, is the file-set scoping field; and the cost
bound as amended) to the doc's owner. The code itself needs no change for this.

### Minor (recorded, never blocking; triage at final review)

**M-3 — Census numbers describe a fixture that is not the committed one.** Report §3's
first table row ("10 ordinary PyPI names → 12 citations (10 import, 2 language)") and the
committed docstring's "12 of 12 on this import set"
(`test_the_keyless_fraction_of_a_real_derivation_is_measured`) do not match the committed
fixture: it seeds **5** imports and produces **7** citations (5 import, 2 language —
measured independently by a scratch driver against the real producer; all 7 keyed, import
keys module names, language keys file paths). The substantive claims (fraction 1.0, both
bases key reliably, keyless is defensive) all verified true; the numbers are from a
development-time fixture. Fix the docstring and the report table, or restore the 10-import
fixture.

**M-4 — "one indexed `(repo_id, key)` lookup" overstates the index.** The only index is
`UNIQUE (repo_id, kind, key)` (`0001_baseline.py:820`); `_RESOLVE_KEYS` filters on
`repo_id` prefix + `key = ANY(...)`, so the statement is bounded by the repo's node count,
not its citation count. Harmless at Tier-C hourly scale; the report's cost framing should
not be quoted as "indexed (repo_id, key)".

**M-5 — The stale flag is served and typed but rendered nowhere.**
`fact-sources.tsx` never reads `FactSourceGroup.stale`; the visible-cause story currently
ends at the API boundary. The report's wording ("the frontend type carries the flag") is
honest about this. If no doc-13 surface task owns rendering it, one should — otherwise a
human auditing a downgraded badge sees a source list where the broken citation looks
identical to a live one.

**M-6 — The invariant-15 guard is enumerated, not exhaustive.**
`test_no_capture_or_retrieval_module_reaches_the_reverifier` scans a ten-file hot-path
list plus `app/api`; a hot-path module not on the list could import the re-verifier
unnoticed. The dream-family source scan does not cover this job (it is not a member).
Acceptable as shipped; note for whoever next generalizes the invariant-15 scans.

**M-7 — The `already_stale`-across-HEAD-moves branch is untested.** A citation broken at
sha B whose repo moves again to sha C while still broken takes the `already_stale` branch
(stamp advances, no second journal row, no second enqueue, `stale_at_sha` keeps B). The
code reads correct and the branch is what makes "one marking per break" hold across HEAD
moves, but no test pins it — `test_two_ticks…` reuses one HEAD.

## Verdict 1 — Spec compliance: ✅ (all three done-when clauses)

**1. "The hash covers verified facts only, proven by a test that churns
candidates" — ✅.** The gate recomputes through `all_verified_fact_ids`
(`article_synthesis.py:1321`), the same function that wrote the stored hash, so
the write basis and the read basis are one function, not two spellings.
`test_churning_candidates_never_move_the_hash` churns five candidates plus a
disputed fact and asserts no staleness. The test bites: removing the
`verification_status` filter from `_ALL_VERIFIED_IDS_SQL` fails exactly that
test (mutation drill, reproduced). The third spelling the brief flagged
(`articles_channel._LIVE_HASHES_SQL`) is pinned equivalent by T3.04's tests
(shared `SUPPORTING_BELIEF_PREDICATE` containment, the line-wise no-old-basis
scan, the canonical-predicate derivation test, and the hash-function equality
test in `test_articles_channel`). No drift found.

**2. "Debounce window is a `config` row" — ✅, with a caveat that becomes
Finding 1.** `debounce_hours` is a `FieldDescriptor` on
`ARTICLE_SYNTHESIS_CONFIG_SCHEMA` (`dream_jobs.py:521-523`), persisted in the
`config` row `job:article_synthesis`, validated by `set_config` (type +
min/max, unknown keys rejected), and forwarded by the runner
(`dream_jobs.py:570`). That is this repo's idiom for a job knob. The caveat:
the schema's own bounds admit values that silently disable the feature
(Finding 1), and no test covers the field or the forwarding (Finding 3).

**3. "Re-synthesis supersedes rather than mutating; lineage is preserved" —
✅.** Three statements in one transaction (`resynthesise_subject`,
`article_synthesis.py:1474-1485`): flip prior to `superseded`, insert the new
row, write `superseded_by`. The order is forced by `ux_knowledge_articles_live`
(partial unique index `WHERE status <> 'superseded'`, verified in
`0001_baseline.py:785`) and is correct against it; a mid-transaction failure
rolls all three back (per-article `try` in the runner; the session closes
uncommitted). `store_article`'s `LiveArticleExists` probe sees the in-transaction
flip, so the insert is legal. Tests pin the prior row's content surviving
verbatim, the pointer, the single live row, and the `superseded` journal row.
Mutation drill: deleting the `_POINT_SQL` call fails
`test_it_supersedes_the_prior_and_keeps_the_pointer` — the pointer is
test-guarded, which matters because `knowledge_articles` has no
`chk_superseded_has_pointer` to catch it at the constraint layer.

**Scope check.** Nothing built beyond the task: `SynthesisOutcome.visited` and

## Verdict 2 — Task quality: **Needs fixes**

Two Important findings (one code defect, one policy decision the controller/owner
should adjudicate), four Minors.

### Important

**F1. A debounce window above the anchor lookback silently disables
re-synthesis, forever, and the config schema invites exactly that.**
`_ANCHOR_LOOKBACK_DAYS = 90` (`article_synthesis.py:1252`) bounds the anchor
read; the `FieldDescriptor` allows `debounce_hours` up to **8760**
(`dream_jobs.py:523`). For any window above 2160 hours, `staleness_settled`
structurally cannot return True: whenever the anchor is visible inside the
lookback its age is at most 90 days, which is less than the window (→ False);
whenever it has aged out, the code writes a fresh anchor and returns False. The
module's own comment states the invariant ("it must exceed the debounce window
or the anchor would age out before it could mature") — the config bounds violate
it and nothing enforces or warns. **Reproduced with a driver** at
`debounce_hours=2400`: probes at +99, +101 and +250 days all return False and
the re-anchor rows accumulate. Failure mode: an operator who sets a quarterly or
annual quiet period gets articles labelled stale forever and never
re-synthesised, with no error anywhere — the `debounced` counter climbs, which
reads as the damping working. Fix options: cap `max` at ≤ 2160, or derive the
lookback as `max(90d, debounce_hours + slack)`, or refuse the config value with
a warning.

**F2. The unmeasured-supersession policy trades a measured article for an
unmeasured one on a single judge-outage tick, and the recorded rationale does
not cover that case.** (`resynthesise_subject`: only `HELD` holds;
`article_synthesis.py:1463-1472`, decision recorded in the tail row of
`E3-synthesis-and-reach.md`, Tier-2, implementer-recorded — **not**
owner-ratified.) The recorded argument — "with G-D open, holding on
`unmeasured` would freeze L3 at its first article forever" — is correct, but it
only reaches the case where the **standing article is itself unmeasured**:
with G-D open no article was ever promoted, so candidate replaces candidate and
nothing is lost. The rule as shipped is wider than the argument. When the
standing article is measured `corroborated` — or human-ratified `confirmed` —
one transient vendor outage or a de-qualified judge during the tick retires
measured prose for prose nothing measured: badge drops to
`candidate`/`review_state='open'`, and **there is no re-measure path** — the
coverage pass runs only at synthesis time, so the badge stays down after the
judge recovers, until the fact set happens to move again. The `confirmed`
sub-case is the sharpest form: the machine retires a human ratification on zero
evidence, where §4.4's sanction for superseding confirmed articles was written
assuming the re-synthesis passed §4.3.

What retrieval serves in the gap (verified): the subject does **not** vanish —
the channel's predicate is `status <> 'superseded'` with no `review_state`
filter, and composition rides `review_state` through as a label — so the harm
is bounded to the badge downgrade, the measured prose leaving the live set, and
the missing recovery path. The new article does land in the review queue
(`review_state='open'` → `list_open_articles`), so a human surface exists.

A strictly narrower rule delivers everything the rationale asks for:
**supersede on `unmeasured` only when the standing article is itself unmeasured
(status `candidate`); hold when it is `corroborated`/`confirmed`.** In the G-D
open world the behaviour is identical (no freeze); in the outage world a
measured article is never traded for an unmeasured one — the hold is a retry,
not a freeze, because staleness persists and the settled debounce retries every
tick until the judge answers. The only truly frozen case is a permanently
removed judge, where a measured, stale-labelled standing article is arguably
exactly what §4.4's "a subject never loses a good article to a bad
re-synthesis" wants kept. Plan-recorded, so this is the controller's/owner's
call — but the record should not stand as-is, because its justification proves
a narrower rule than the one shipped.

### Minor (recorded, non-blocking)

**F3. No test pins the `debounce_hours` config field or the runner's
forwarding.** The verify suite exercises the parameter only as a function
kwarg; `debounce_hours` appears nowhere in any test as a config key. Dropping
the `FieldDescriptor` or the `settings_.get` forwarding would leave the floor
green while done-when 2's property silently reverts to the constant. Related
test gap, same grade: `article_stale`'s presence in the frontend taxonomy is
covered by the cross-language guard (`test_event_taxonomy_map.py`), but the
frontend shape test's pin lists were not extended, so its *category*
(`consolidation`) is pinned by no test on either side.

**F4. `no_facts` counts as `refused`** (`run_article_resynthesis`,
`article_synthesis.py:1591-1594`). The outcome's documented meaning of
`refused` is "the model produced something unstorable"; a subject whose fact
set vanished never reaches the model. An operator diagnosing a tick sees
refusals with no model call behind them.

**F5. Three copies of the default 24.** `DEFAULT_DEBOUNCE_HOURS`
(`article_synthesis.py:1244`), `default=24` in the `FieldDescriptor`
(`dream_jobs.py:523`), and the dead literal fallback in
`settings_.get("debounce_hours", 24)` (`dream_jobs.py:570` — dead because
`default_config` always carries the key). Consistent with the file's existing
pattern for `hub_cap`/`length_budget_words`, hence Minor, but the constant and
the descriptor can drift silently.

**F6. A permanently-held subject retries at full price every tick, forever.**
Once settled, a stale subject whose re-draft measures `HELD` pays one synthesis
call plus a per-claim entailment pass per tick with no backoff and no cap — the
debounce cannot damp it (elapsed only grows), and the only stop is a fact-set
move or a human. Bounded per-tick (cap × claims), visible only as the `held`
counter. Adjacent to the escalated Tier-3 review-routing question; the ruling
there should name this cost.

**F7. Two sub-minor observations.** (a) The `superseded` journal payload's
`fact_set_hash` is the stale-check snapshot, which can differ from the hash
stored on the replacement if facts move between the two sessions — honest as
trigger provenance, but a reader comparing the journal to the row can see a
mismatch. (b) `_SUPERSEDE_SQL` is a blind UPDATE with no status guard; a future
concurrent human writer on the article axis (ratify) could be silently
overwritten mid-tick. No such writer exists today and the job lock serialises
the job's own runs, so this is a note for whoever builds article ratification.

## Attack surfaces from the brief, disposition

1. **Write vs read basis** — no divergence; one function on the gate, third
   spelling pinned by four T3.04 tests. Cleared.
2. **Debounce anchor** — the >90-days case is *not* the documented
   self-correcting delay when the window itself exceeds the lookback: that is
   Finding 1. Anchor loss (`record_event` → False) stalls one tick, is logged
   each tick, and heals when the journal does — matches T2.113's contract.
   The by-object read is indexed (`ix_events_object` on
   `(object_type, object_id, created_at)`) and the `created_at >=` bound
   enables runtime partition pruning. `now` vs DB clock: production passes
   `now=None` (wall clock) against transaction-start stamps — seconds of skew
   against an hours-scale window; not a defect at any call site.
3. **Unmeasured supersession** — Finding 2, with the serving gap verified
   rather than assumed.
4. **Supersession ordering** — correct and forced by the partial unique index;
   mid-transaction failure rolls back all three writes; pointer is
   test-guarded. Cleared.
5. **Layout** — verified against the scan's own mechanics:
   `dream_job_implementation_modules()` is deliberately one-hop
   (`test_dream_jobs.py:374-407`, a documented contract), so a second module
   imported by `dream_jobs` becomes a family body and a body importing
   `article_synthesis` fails the build. The alternative (a neutral third module
   for gather/draft/store) would refactor shipped code for layout alone;
   `_UMBRELLA_INFRASTRUCTURE` would be a misuse (staleness is family work, not
   shared infrastructure). The resolution is right. Cleared.

**Known open items** — framing verified: the Tier-3 escalation's claims about
`ux_knowledge_articles_live` and doc 13 §5.2 check out against the schema and
the corpus; T3.05 does ship the conservative half (a held draft leaves the
standing article untouched, drilled by mutation). The escalation's option
analysis is fair. One addition it should carry: Finding 6's retry bill.

### F2 (Important) — buffered captures read as "deleted": ADDRESSED

- The lookup (`research_rerun.py:182-190`) reads **`metadata->>'memory_id'`**,
  never `memory_buffer.id`. Verified three ways:
  - The model maps `metadata_` to the DB column `metadata`
    (`app/models/memory.py:118-120`), so the SQL names the right column.
  - **Conflation probe by execution**: a buffer row whose *own* id equals the
    journalled memory id but whose metadata carries a different id does **not**
    count as pending — the run refuses with `no_evidence`, proving the query
    never matches on the row id.
  - **Mutation drill**: rewriting the query to read `id::text` reds exactly
    `test_a_run_still_in_the_capture_buffer_is_not_called_deleted` — the
    committed test locks the doc 05 §2.2 distinction, because its fixture rows
    carry fresh row ids distinct from the metadata memory ids. Reverted.
- Refusal semantics verified by execution at the route: all-buffered run →
  **409** with a message naming the capture buffer, reason
  `not_yet_materialised`; partial (one live, one buffered-`error`) → **200**
  with `reprocessed=1, missing=1, pending=1` and reprocess receiving only the
  live id; buffer rows settled to `done` with the memories later deleted →
  `no_evidence`, correctly *not* pending (`status <> 'done'` is right: discard
  deletes the row — `buffer_monitor.py:256-277` — so pending/claimed/error are
  exactly the not-yet-materialised states and there is no fifth status,
  `memory_buffer_status_check` enforcing it).
- `pending ⊆ missing` holds by construction (the query is constrained to the
  journalled ids and `- live_ids` is applied), so the UI's `missing - pending`
  can never render a negative.
- UI split verified: vitest file passes (13/13), and a mutant rendering plain
  `missing` as "no longer exist" reds exactly the new buffer-split test.
  Reverted.

## Adjacent finding the fix deliberately did not take

`MemoryBuffer`'s model docstring ("that same id becomes the ``memories`` row's
id at flush", `app/models/memory.py:95-97`) is **confirmed stale prose, not
live behaviour**: `enqueue` mints two distinct ids (`memory_buffer.py:90-105`),
and the flush creates the memories row from `buffered_memory_id(row)` — the
metadata id — at `buffer_flush.py:554` / `:572`, never from `row.id`.
`buffered_memory_id` raises if the metadata key is absent, so no path falls
back to the row id. **Not merge-blocking**: the two authoritative statements
(doc 05 §2.2 and `enqueue`'s docstring) are correct and adjacent; but this is
precisely the conflation F2's fix warns against, sitting on the model itself —
worth a one-line amendment in a later round.

## Deferred minors (recorded, not looped on)

1. **No committed test pins the route's status mapping.** The conformance table
   pins only the 200; "503"/"409" appear in no test assertion. The mapping was
   verified by execution in this review only — a future edit flipping the 409
   back to 404, or dropping the `RerunUnavailable` handler (making the
   pipeline-less case a 500), reds nothing committed. The semantics are pinned
   at the service layer, so this is coverage, not correctness.
2. **`wrong_event_type`'s reason value is asserted by no test** (typo degrades
   safely to 404).
3. **Per-file tripwire's two remaining evadable shapes** (keyword-form
   `import_module`, `from app.services import auto_research`) — caught by the
   blanket scan, measured above; noted so nobody reads the per-file belt as
   complete on its own.
4. **`_buffered_research_ids` does not constrain `source`** the way
   `_live_research_ids` does. Consequence is bounded to a wrong refusal message
   in a hand-written-row id-collision scenario; noting for symmetry only.
5. **The listing surface still under-tells the buffered state**: a fully
   buffered run lists `live=0`, so the button renders disabled "Nothing to
   re-derive" and the 409's honest message is unreachable from the UI (the
   request is never sent). Not the false "deleted"/"no longer exist" statement
   the finding was about — the outcome line and the wire are now honest — but
   an operator watching a run stuck in buffer `error` learns that from the
   buffer triage surface, not here.

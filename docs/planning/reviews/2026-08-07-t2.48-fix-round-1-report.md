## M-5 — the stale flag is served and typed but rendered nowhere (judgment)

**Not this task's — it belongs to T2.86, which already exists and is still open.**

`FactSourceGroup.stale` reaches the frontend as a typed field, but
`sourceGroupsToFlatSources` (`frontend/src/features/knowledge/components/fact-sources.tsx:27-37`)
flattens `FactSourceGroup[]` into `FactSource[]` and drops `stale` in the flattening — it
carries only `origin_key`, `kind`, `ref`, `detail`, `at`. So even a caller that wanted to
render it today has nothing to render from; the gap is not "a badge nobody added" but "a
field nobody threads through."

`FactSourcesGroups` (the component that owns this flattened list) is used from exactly one
place: `frontend/src/features/knowledge/components/fact-detail.tsx` — the component
`docs/planning/tasks/E2-truth-core.md`'s **T2.86 — "The fact detail route on live data"**
(depends on T2.36a, T2.36; doc 13 §5.1) exists to wire to live data. T2.86 is still open (all
six Done-when boxes unchecked) and its clause 2 is "every field the page displays is one the
door actually serves; anything it cannot serve is removed from the page rather than rendered
empty or faked" — exactly the discipline that governs whether `stale` gets a visible badge.
T2.86 predates T2.48 (minted 2026-08-04, T2.48 landed `stale` 2026-08-07), so its text does
not name the field, but its scope already covers it: it is the task that decides, per field,
what this exact page renders.

There is a real precedent for this call in the epic's own amendment log
(`E2-truth-core.md:2676`, 2026-08-04): a UI-rendering gap discovered adjacent to a landing
task was explicitly *not* folded into that task's fix round — "wiring the page is a task, not
a fix" — and was minted as T2.86 itself. The same reasoning applies here in reverse: the task
that would do this rendering already exists, so nothing new needs to be minted. No code
change made for this finding.

## M-6 — the invariant-15 guard was enumerated, not exhaustive (judgment: generalized now)

**Judgment: generalize now**, not defer. The fix was cheap because the codebase already
carries a proven pattern for exactly this shape —
`tests/test_supersession_blocker.py::test_no_app_code_outside_the_ladder_reaches_the_blocker`
scans the whole `app/` tree against an explicit allowlist of legitimate callers, rather than
guessing which files count as "hot path." Reusing that pattern here removes the enumeration
risk entirely for about the same line count as the list it replaced, so deferring it would
have meant leaving a known gap in place for free.

**Change.** `test_no_capture_or_retrieval_module_reaches_the_reverifier` now walks every
`.py` file under `app/` (with the same `len(paths) > 100` sanity floor
`test_supersession_blocker.py` uses, so a broken glob path fails loud instead of passing
vacuously) and flags any file containing the string `citation_reverify` that is not in a
three-file allowlist: the module's own file, `app/services/job_runners.py` (the runner
factory that wraps it for the job registry), and `app/main.py` (the registration call). Those
three are the only files in the real tree that reference it today (`grep -rl
"citation_reverify\|reverify_citations\|CITATION_REVERIFY" app/`).

**Mutation drills, two, to prove the generalization closes a real gap rather than just
re-proving what the old list already caught:**

1. Appended a bogus `citation_reverify` reference to `app/services/pipeline.py` (in the old
   enumerated list). Result: the guard failed, offender `app/services/pipeline.py` — parity
   with the old behaviour confirmed.
2. Appended the same to `app/services/access_stats.py` — a file **not** on the old
   ten-file list. Result: the guard failed, offender `app/services/access_stats.py` — this is
   the gap the old guard structurally could not see, now closed. Both mutations reverted from
   pre-mutation `cp` backups; `git status` clean after each.

**New in-suite negative control**, `test_the_reverifier_guard_rejects_a_forbidden_reference`,
mirrors the blocker's own control: builds a throwaway tree with one forbidden reference in a
non-allowlisted file and one in an allowlisted file, and asserts the scan reports exactly the
first. Proven every run rather than trusted from the two manual drills above.

Full test file re-run after this change: **28 passed** (26 original + the M-7 test + this
negative control).

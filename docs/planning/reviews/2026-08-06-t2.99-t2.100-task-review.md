### Task quality: **Needs fixes**

- **Important 1 — the journalled rung's reader set is wider than every statement of
  it, measured.** The `verified` journal payload is served on two *claim surfaces*,
  not only on `/events`:
  - `GET /api/v1/knowledge/facts/{id}` serves the full event payloads in `ladder`
    (`facts_read.py:204–212` → `events.object_timeline`, `_EVENT_COLUMNS` includes
    `payload`, `FactDetailResponse.ladder: list[EventLogEntry]` passes it verbatim);
  - `GET /api/v1/review-queue/facts` serves it in `evidence`
    (`review_queue.py:340,370` → `verified_evidence.latest_verified_evidence`,
    `ReviewQueueFactItem.evidence: dict`).

  I drove both with a production-shaped fact (transitioned via
  `set_verification_status`): each body carries
  `payload.after.verification_status: "corroborated"` beside a served label of
  `candidate` + `label_suppressed`. The ruling, the `journalled_status` docstring,
  the report's classification table, and the door drives all name `/events` as the
  reader. Consequences: (a) the honest M1 sentence as now written into
  `claim_gates.journalled_status` — *"no claim surface serves an unbacked label; the
  audit journal records the ladder's own transitions and an authenticated operator
  can read them"* — is incomplete: two claim surfaces embed those records; (b) the
  ruling's enforceability ("reversing it is a deliberate multi-file act") holds only
  at the events door — the two embeddings can be gated *or* widened with no test
  noticing; (c) this is the task's own defect class one level up: a declaration
  whose stated reach is narrower than its measured readers. **Partially
  plan-mandated:** the ruling was made on AF1's facts, which named only `/events`;
  whether the ruling extends to the embeddings (the classification "record of a
  computation, never a claim" remains *true* at all three doors) is the
  controller's to adjudicate. The fix that is unambiguously this lane's: correct
  the docstring's reach sentence and pin the two embeddings in whichever direction
  the ruling lands.
- **Important 2 — the whole-body door drive asserts a fixture property as a door
  property.** `test_no_unserved_declaration_reaches_a_reader_at_any_door`
  (`test_claim_serving_gates.py:1454–1503`) claims "the promoted rung appears
  **nowhere** in what these doors serve." Measured false at the REST fact detail —
  one of its own listed doors — for any fact that transitioned the production way;
  it passes only because `_promoted_fact` writes the rung by direct UPDATE and never
  journals. The unserved-site guarantee it means to hold is real, but the blanket
  string assertion misleads the next reader about door behaviour and fails
  spuriously the day any fixture in its path becomes production-shaped. Narrow the
  assertion to the fields the unserved sites feed, or make the fixture
  production-shaped and scope the check — either way the test should say what is
  actually true of the doors.
- **Minor 3 — `journal_bound_denials` reach.** (a) A tuple-target binding
  (`payload, extra = {…unserved…}, None` then journalled) evades the taint while
  sitting *inside* the docstring's claimed reach ("every name it writes through —
  target, subscript base, or method receiver"): tuple elements are targets it never
  walks. (b) Taint does not propagate through a second name — `inner = {…unserved…}`;

  undisclosed (the disclosed blind spot is only the cross-function hop). (c) The
  report's "what covers that is the events door drive" is wrong in direction: the

  catch a falsely-*unserved* value inside a journal payload. What actually forces

- **Minor 4 — the ruling's "authenticated operator" qualifier is unasserted.** No

## The two judgement calls the dispatch asked for

**1. Vacuous drills.** I checked every drill in both reports against the code the
live path executes. No *other* drill has the disclosed drill-5 shape (a mutation to
`_labels`, which `_badge_labels` overwrites on every live path); T2.99's four and
T2.100's remaining five all mutate live code or the guard's own subject, and the
two I reproduced failed exactly as recorded. The nearest relative is not a drill but
an assertion: the whole-body door drive (Important 2) is kept true by fixture shape
rather than by door behaviour — the same family of illusory strength, reached by a
different mechanism, found by driving the door with a production-shaped row.

**2. Does the events-door test assert the ruling as ruled?** For the door the
ruling names, yes, and well: it drives a real transition, asserts the rung verbatim
on `/events`, and its docstring carries the intent — so reversing the ruling at
that door is a deliberate act, exactly as intended. But it is **weaker than the
ruling in one respect and narrower than reality in another**. Weaker: the ruling's
sentence includes "under the same `require_auth` as the facts door", and nothing
asserts the auth (Minor 4) — the test cannot distinguish "an authenticated operator
can read them" from "anyone can". Narrower: the ruling and the test both fix
`/events` as *the* reader, and the measured reader set is three doors wide
(Important 1) — so the "deliberate multi-file act" property protects the substrate
door only, while the two claim-surface embeddings of the same payload sit outside
both the ruling's text and the test's reach, un-pinned in either direction. It does
not assert anything materially stronger than ruled.

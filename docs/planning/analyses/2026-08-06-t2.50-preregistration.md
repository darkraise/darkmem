## The activation bar

The standing gate (gate-ledger.md, "Ranking-arm activation") is the bar: *"a
retrieval-eval delta that is positive with its latency/cost twin."* Operationalised,
before looking at anything new — an arm activates at weight `w` only if, at that `w`:

1. **Aggregate ΔMRR > 0 and aggregate Δhit@10 ≥ 0** over the live pairs. A negative
   aggregate is not positive under any reading; a capability-slice gain purchased with
   an aggregate loss is a trade the gate's text does not admit.
2. **Any slice gain claimed as the arm's rationale survives mechanism attribution.**
   A multi-hop hit@K flip counts as evidence only if the flipped pair's consequence
   memory receives *query-conditioned* support consistent with the arm's stated
   entity-linking semantics. A query-independent list that happens to contain B is
   perturbation, the exact shape the `w_importance` entry already documented
   (+0.1429 multi-hop hit with ΔMRR −0.7745, ruled not-a-win).
3. **The twin is affordable and honestly attributed**: on-leg end_to_end p95 within
   2× the off-leg p95, and the token/artifact cost stated — a "zero LLM calls" twin
   is a statement about the read path, not a statement that the arm is free.

**Per-slice sub-verdict** ("does either arm clear on any slice?"): a slice is cleared
only by slice ΔMRR > 0 **and** slice Δhit@10 ≥ 0 **and** rule 2. A cleared slice does
not activate the arm (the gate is per-arm, on the aggregate); it is recorded as a
finding.

**Anti-bar-shopping rule**: magnitude probes below are diagnostic. No magnitude scan
result activates an arm by itself; a surprise bar-clearing number at a probed
magnitude would require a pre-registered confirmation run *plus* rule-2 attribution
before any activation, because scanning magnitudes and picking the winner is the
tune-against-gold loop the harness exists to prevent.

**Community injection** is scored on answer-quality/groundedness over a reasoning
gold set, never MRR (doc 17 §2). If no such measurement exists, the verdict is
"unmeasured", recorded as a result — not a fold-in to the MRR verdict.

## Entity-linking semantics (T0.06a obligation), stated from shipped code

- **`w_ppr` links by name-embedding.** The snapshot builds synonymy KNN edges over
  per-entity name embeddings inside itself — threshold 0.8, top-k 5
  (`app/services/ppr_snapshot.py:63-64`, `_synonymy_sql` :176-201, applied
  :350-384). Two same-named entity rows of different `entity_type` embed identically
  (the entity-embedding cache keys on `(name_lower, fingerprint)`), so cosine 1.0 ≥
  0.8 and the edge exists subject only to top-k. **SLICES.md ceiling that applies:
  14/14** (name/name-embedding linking), not 6/14. To be confirmed against the built
  snapshot (M3), not left as argument.
- **`w_dual` does not link entities at all.** The channel ranks *relation-text
  embeddings* against the query vector and resolves each matched relation to its
  asserting memories via `entity_relations.memory_ids`
  (`app/services/hybrid_search.py:325-400`). Node identity plays no role; B is
  reachable whenever B itself asserts a relation whose embedded text sits near the
  query — reach through relation phrasing, not traversal through a bridge. Both
  SLICES.md ceilings are therefore inapplicable in their own terms; the effective
  ceiling is 14/14, and a multi-hop flip read off this arm measures semantic
  proximity of B's relation texts to the query.

## The structural hypothesis, stated with its discriminating measurement

From code arithmetic (not yet measured): the ablation runs at
`retrieval_limit = 94`, `fusion_fetch_depth(94) = 300`, and the semantic channel is
a pure `ORDER BY distance LIMIT` with no threshold — so the semantic list is the
whole 94-row corpus for every query. `_ppr_search` seeds from **all** semantic rows
(`hybrid_search.py:452-487`), and `seed_vertices_for_memories` over the whole corpus
selects **every vertex** (`ppr_snapshot.py:464-482`: every node maps to ≥1 eligible
memory by construction). PPR reset uniformly over all vertices is ordinary
PageRank: **the hypothesis is that the PPR arm's ranked list is query-independent at
this protocol — one constant global-popularity list fused into all 102 queries.**
This is the precise pathology the module's own docstring forbids for the empty-seed
case ("a global-popularity list fused into every query is a different signal wearing
this one's name"), arriving from the full-seed end.

- **Discriminating measurement (M2):** compute the arm's ranked list for several
  distinct gold queries under the on-leg configuration and compare.
- **If identical** across queries: every multi-hop flip is constant-list injection,
  not traversal; rule 2 fails for all of them; the temporal collapse is the same
  constant list displacing gold siblings; and no magnitude can clear the bar because
  every weight injects the same query-independent list, scaled. Further `w_ppr`
  magnitude probes are then refused (anti-bar-shopping; nothing left to learn).
- **If not identical**: the arm is query-conditioned after all; then run M3's
  per-pair mass attribution for rg-0104/0105 (does B receive mass through an hv-27
  bridge edge for that query's seeds?) and a 0.1 diagnostic leg to separate the
  temporal collapse's structure from its magnitude.

# Brief — T0.19, no lane worktree can run the merge gate

**Task:** T0.19 · `Haiku 4.5` · `high` · `Size: S` · Doc 17 §9 · Gate: none (harness integrity)
**Depends:** T0.16 — landed. **Contract:** `docs/planning/agent-runbook.md`.
**Baseline:** `CLAUDE.md`. **Branch:** `feat/e2-lane-ci` off `feat/e2-truth-core`,
worktree `.worktrees/e2-lane-ci`.

## The gap in one sentence

`scripts/gate.sh:21` hard-codes `PY="$BACKEND/.venv/bin/python"`, and `backend/.venv/`
is gitignored, so `git worktree add` never populates it — **no lane worktree can run
the merge gate at all.**

## Why this matters more than it looks

The gate is the only command that runs the alembic single-revision assertion, the
backend floor, the frontend trio, the benchlib harness suite and the F1 bench
*together*. A lane running `pytest -q` alone gets a green floor over an unchecked
harness — `pyproject.toml`'s `testpaths = ["tests"]` means plain pytest does not
collect `scripts/benchlib/tests`, which is a trap that has caught lanes twice.

Every lane in this epic has been unable to self-check before handing work back. That
is not hypothetical: in the round that just closed (2026-08-07), a lane reported
`./scripts/gate.sh` "preflight-fails in this lane worktree — no `.venv`, per the
runbook's hygiene note" and fell back to running the single-revision assertion by
hand. It got the right answer, but by reimplementing a slice of the gate rather than
running it.

## What ships

Make the gate runnable from a lane worktree. The task states the two acceptable
shapes and either is fine:

- `PY` overridable by environment variable, with the current hard-coded path as its
  default; or
- the script resolves an interpreter when the local `.venv` is absent.

**The second clause is the one with teeth: the resolution must be explicit and
reported.** The script says which interpreter it chose, on stdout, every run. A lane
that silently gates against the *main checkout's* code while believing it gated
against its own is worse off than a lane that cannot run the gate — it gets a green
result that means nothing. Print the resolved path before the first gate runs.

## What to be careful about

- **Resolving an interpreter is not the same as resolving the code under test.** The
  runbook's §8 rule for pytest is to run the main checkout's interpreter *from the
  lane's own `backend/` directory*, so imports resolve against the lane's code. Your
  resolution must preserve that property, and the report should say how you verified
  it — running the gate in a lane worktree with a deliberately broken file in the
  lane (and only the lane) should fail.
- **Do not vendor or create a `.venv` in the worktree.** That is a much bigger change
  and it is not what the task asks for.
- **Keep the process hygiene intact.** The script runs each gate in its own process
  group and reaps the tree on failure (`STARTED_PGIDS`, `cleanup`). Do not disturb
  that while touching the interpreter resolution.
- **`GATE BLOCKED` (exit 2) means a missing toolchain, not a red gate.** If your
  resolution fails to find any interpreter, that is a blocked gate, not a failed one —
  match the existing convention rather than inventing a third exit code.
- The bench cache (`scripts/extraction_bench/.cache/`) is also gitignored and also
  absent in a fresh worktree, so `--algo-only` exits non-zero on uncached content.
  That is a **separate** problem and is **not yours** — note it in the report if the
  gate still cannot complete in a worktree for that reason, so whoever owns it has the
  evidence.

## Done when

- [ ] A lane worktree can run `./scripts/gate.sh` — `PY` overridable, or resolved when
      the local `.venv` is absent
- [ ] The resolution is explicit and reported: the script says which interpreter it
      chose, so a lane cannot silently gate against the wrong tree's code
- [ ] Verified by actually running it from a lane worktree, with the output in the
      report — not by reading the script

## Hygiene

`TEST_DATABASE_URL` → `darkmem_test_ci`, `BENCH_DATABASE_URL` → `darkmem_bench_ci`
(both exist). Run commands in the **foreground** with an explicit timeout, one at a
time; never background a run and hand control back — three lanes stalled that way in
the last round. Commit before any mutation drill and restore from your own file copy,
never `git checkout --`. Never stage with `git add -A`.

**Verify.** Run `./scripts/gate.sh` from `.worktrees/e2-lane-ci` and record what
happens verbatim, including which interpreter it reported. A full green gate is not
required for this task to be done — what is required is that the gate *runs* and says
what it resolved. If it then fails on the bench cache, that is the separate problem
above; report it with its output.

**Finish with a report** at `docs/planning/reviews/2026-08-07-t0.19-report.md` naming
the shape you chose, the verbatim run output, how you verified the lane's own code is
what gets tested, and anything the plan got wrong.

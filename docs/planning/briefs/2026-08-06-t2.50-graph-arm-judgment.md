## Your deliverable

The activation verdict for `w_ppr`, `w_dual`, and community injection, recorded in
`gate-ledger.md`'s arm activation log, plus the tracker note. **An arm that does not clear
stays at zero and that outcome is recorded as a result** — a "no" is a finding, not a
failure, and this task's Done-when says so explicitly.

## The three things this task is bound by

1. **Community injection is scored on answer-quality / groundedness, never MRR** (doc 17
   §2). It augments context rather than ranking. If no reasoning-gold measurement exists
   for it, say so and record it as unmeasured rather than folding it into the MRR verdict.
2. **The T0.06a amendment (2026-07-27) binds you.** State the arm's entity-linking
   semantics *before* reading any multi-hop verdict off that slice.
   `backend/scripts/benchlib/retrieval/SLICES.md` records two achievable ceilings — 6/14
   under strict node-identity traversal, 14/14 if the arm links by name or name-embedding —
   and which applies is a property of the arm, not of the gold. The blocker review argues
   PPR's semantics is decided in shipped code (synonymy KNN over name embeddings at
   threshold 0.8, so name-linking, ceiling 14/14) and that all observed flips are name-only
   bridges. **Verify that independently.** It also notes one free snapshot inspection would
   settle traversal-vs-reshuffle and deliberately left it to you.
3. **Every activation number carries its twin** (latency + token cost). Both runs report
   no live LLM calls attributed; say what that means for a cost verdict rather than
   treating a zero as free.

## Questions the evidence must answer, not you by assertion

- Is a −0.26 / −0.19 aggregate MRR cost with a multi-hop hit@K gain a *trade* worth making
  at any weight, or is the probe magnitude itself the finding? Note `LIST_PROBE_WEIGHT` is
  0.3 with a stated rationale; you may probe other magnitudes.
- Temporal collapses on both arms and scales with weight (0.65 → 0.26 → 0.00 mrr). Is that
  structural or magnitude-amplified? The blocker review says structurally real; test it.
- Does either arm clear on **any** slice under a bar stated before you look? State the bar
  first, in writing, then measure. Doing it the other way round is the tune-against-gold
  loop the harness exists to prevent.

## Running things

Re-running the ablation is free on a warm cache (both prior runs attributed zero live
calls). `cd backend && DEEPSEEK_API_KEY=... python scripts/benchlib/run_retrieval_eval.py
--arm w_ppr [--weight X]`. The key is in `CLAUDE.md`. Embeddings go to the LAN Ollama
host, which is reachable.

**Do not change ranking code.** If a measurement requires a code change, that is a finding
to report, not a change to make — you would then be judging your own edit.

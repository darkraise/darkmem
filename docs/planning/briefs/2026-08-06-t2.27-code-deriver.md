## Why this is startable even though G-C is open

G-C's stated consequence is that "the code-deriver lane stays closed", and the reason it
gives is that *"the deriver mints facts born `corroborated`"*. That is **T2.28's** act, not
this task's. This one writes Layer-1 assertions only — `entities` / `entity_relations` rows
tagged with a repo id — and asserts nothing at the ladder's second rung. The controller
re-pointed the gate edge onto the promotion on 2026-08-06 under the plan-wide rule that a
gate blocks what it certifies, not what merely precedes it. **Do not lift anything into
`knowledge_triples`.** If you find yourself writing a fact row you have crossed into T2.28.

**Internal modules are not dependencies.** The pipeline already resolves internal imports
(`_resolved_import_map`, `build_import_map`); an import that resolves to a file in this
repo is not an external dependency and must not become a `tool` entity. Where you draw
that line is the single highest-leverage judgement in this task — say in your report how
you drew it and what it excludes.

## The three Done-when clauses, and what makes each non-vacuous

- [ ] **Imports only; no LLM call anywhere in the path.** Prove it structurally, not by
      inspection. This repo's idiom for that is an AST/source scan that fails the build
      when a module reaches a forbidden surface — `verification_judge`'s single-door scan
      and `dream_jobs`' `_ALLOWED_DREAM_JOB_LINES` are the two live examples. Note the
      trap recorded on 2026-08-06: `tests/test_verification_judge.py`'s scan matches the
      module name as **text**, so it fires on prose in comments too. Write yours against
      the parsed tree, not against line text, and say which you chose.
- [ ] **Existing graph sweeps stay byte-identical in behaviour with `repo_ids[]`
      populated.** This is the clause with teeth and it is the one a passing test can
      fake. The sweeps (`prune_orphan_entities` and the per-memory strip in
      `graph.py:517-598`) were reviewed and frozen *while every array was empty*, so their
      `NOT EXISTS (live repo)` predicates were vacuously true and have **never executed
      against a non-empty array**. You are their first real exercise. What must hold: an
      entity asserted by a live repo survives a sweep that would otherwise delete it; an
      entity asserted only by a *dead* repo does not; and a relation whose endpoint the
      sweep spares for repo reasons keeps its edge. "Byte-identical" is about the
      behaviour on rows the amendment does not touch — do not read it as "no observable
      change", which would make the amendment pointless.
- [ ] **Re-derivation is idempotent per repo.** Two identical runs leave byte-identical
      rows *and* a changed import set produces a different one — an idempotence test that
      passes because the second run is a no-op over an empty derivation proves nothing.
      Re-index the same repo N times and show the repo id appears **once** in each
      `repo_ids[]`, not N times.

## Invariants that bind you

- **Invariant 8, amended (strip-before-rewrite).** The strip and the write are one atomic
  replace, exactly as Phase 5 does it inside savepoint B. A failed strip must fail the
  write, never be swallowed and written over.
- **The never-join invariant is structural.** No statement may read a `code_graph_nodes`
  row and an `entities` row together. The crossing is application-level and
  one-direction: read the code graph, then write the memory-side graph. Doc 10 §2 is
  explicit that this is what keeps the bridge sound.
- **Lowercase entity names on disk**, original casing in `properties.display_name`. The
  supersession detector and the `technologies` denorm both assume it.
- **Closed taxonomy.** Every type goes through `normalize_entity_type` /
  `normalize_relation_type`. A free-form value is silently rewritten.
- **asyncpg CASTs** on every raw-SQL param whose type Postgres cannot infer —
  `CAST(:id AS uuid)`, and specifically for the `uuid[]` array operations here.

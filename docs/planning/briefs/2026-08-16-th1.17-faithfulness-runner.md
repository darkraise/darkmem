## What the task is

The plumbing behind TH1.10's verify, built by Sonnet so the Fable gate task only
designs the bar and reads the number. TH1.01 (`94bdcaeb`, `fdb8c0f7`, done)
already committed the metric definition and the bars, **before any build**, in
`docs/superpowers/specs/2026-08-15-faithfulness-metric-and-bar-design.md` and
`app/services/faithfulness_bars.py`. Read both.

**Done when:** the runner scores span-support coverage against block-span
entailment gold, reports per-slice, and emits its cost twin.

**Verify.** `cd backend && python scripts/benchlib/run_faithfulness_gate.py`

## Import the bars; never restate them

This is the task's own headline instruction and it is not stylistic. The role's
two gate bars live in `app/services/faithfulness_bars.py` and deliberately sit
*outside* `BAR_METRICS` until this task and TH1.09 wire the role. Wiring means
importing `FAITHFULNESS_BAR_DEFAULTS`, **not** copying its numbers.

A second declaration of a bar is the drift shape this repo has already paid for
twice: `RRF_K`, which needed two AST scans to close, and G-C's mirrored bar
constant, which rendered a verdict the predicate had not reached. TH1.01's review
graded the prose-only version of this instruction **Important** on exactly that
history.

So: **if you find yourself typing `0.95` or `0.90` in this runner, import
instead** — and add the restatement scan that makes the next person unable to.
The scan checks the *binding*, not the literal, the way the two `RRF_K` scans do;
renaming the value must not evade it. That scan is part of the deliverable, and
it gets a mutation drill like every other guard.

## Things you may not do

- **You may not author or modify any gold set.** There are five —
  `extraction_bench/gold.json` and `gold_heldout.json`, and `benchlib`'s
  `retrieval/`, `entailment/` and `contradiction/` sets. TH1.01 deliberately
  authored **zero** claim/span pairs; the block-span entailment gold this runner
  scores against does not exist yet, and creating it is the one act the loop may
  never take. Build the runner so it is exercised by a **fixture** gold you
  create under `tests/`, clearly not a gold set, and so it reports honestly when
  the real gold is absent rather than scoring an empty set as a pass.
- **You may not move a bar in either direction**, or add a licence row to make
  something pass. All four shipped verification defaults are floors; the same
  discipline governs the faithfulness bars, including their `conservative`
  direction field. TH1.01's review already found one `loosens` implementation
  that hardcoded `<` while the type carried a `conservative` field — check the
  shipped one still consults the field.
- **You may not spend a measurement attempt** or run the G-C evidence run.
- An **absent** gold, an unreadable bar row, or a missing qualification must fail
  **closed** and say so in words. A run with nothing to score must not render
  like a clean pass — that is the failure `BarReport` was built to close in
  T2.128, where a clamped run's report body was byte-identical to an unclamped
  one.

## The cost twin

"Emits its cost twin" means latency and tokens, and it is a live hazard here: a
recent report in this repo printed its token columns as **0 unconditionally** and
the adversarial review caught it. If a number cannot be measured, print that it
could not, never a zero.

## Your lane

- **Database: `darkmem_test_5`.** Export before any pytest run:
  `export TEST_DATABASE_URL=postgresql+asyncpg://darkmem:darkmem@localhost:5433/darkmem_test_5`
  Three other lanes are running concurrently. `conftest` drops the schema at
  session start, so using any other database produces failures indistinguishable
  from a real regression and corrupts someone else's run.
- **`pyproject.toml` sets `testpaths = ["tests"]`, so plain `pytest -q` does NOT
  collect `scripts/benchlib/tests`.** Run the benchlib suite explicitly, or the
  harness can break while the floor stays green. `./scripts/gate.sh` runs both.
- **Check your base first.** Worktrees here have been created up to 2026 commits
  stale and without `.venv`, `node_modules` or the F1 cache. Run `git log -1` and
  if you are not on `9ab1aded` or a descendant,
  `git reset --hard feat/m1-measurement` before doing anything.
- Bound every command with an explicit timeout. An unbounded filesystem search
  ran 1h48m in this repo.
- Never detect processes with `pgrep -f` on a pattern your own command line
  contains — it self-matches. Read `/proc/<pid>/cwd`.
- Never `git add -A`. A shared-tree `git add -A` once swept 1,110 lines of
  another task's source into an unrelated docs commit. Add paths explicitly.

## The standard this repo holds

This task **feeds a gate claim**, so it takes an adversarial Fable-tier review
before it may read `done`, and it will get one. Write for that reader.

- **Every guard gets a mutation drill.** Break the guard, watch the test go red,
  restore it. A guard that cannot be shown to fail is decorative and gets
  **deleted**, not shipped for comfort.
- **Prefer tests that count work over tests that count rows.**
- Record the **real** verification output, never "should pass".
- Do not mark work done with a failing check.
- Assume your own work is wrong in the way described above: three consecutive
  hand-written repairs to one function in this repo each introduced the failure
  class they were closing.

## The contradiction

Doc 08 §9 says a dated fact "gets its belief window **pre-closed at that date**", which
reads as writing a future `invalid_at` at population time. Doc 08 §3.1's state machine says
`invalid_at` means *a newer belief arrived* (`open --> window_closed`) and routes a stated
expiry down the other edge entirely (`open --> expired`, i.e. `expired_at`). They cannot
both hold.

The literal §9 reading is not merely ambiguous, it is destructive, and the escalation
measured why: `backend/migrations/versions/0001_baseline.py` makes **four** indexes partial
on `expired_at IS NULL AND invalid_at IS NULL` — the unique `ux_knowledge_triples_open`
plus doc 07 §2's three fact-channel retrieval indexes. A future `invalid_at` written today
therefore (a) drops the fact out of the retrieval channel immediately, years before its
stated expiry, and (b) frees the unique slot, letting a second currently-open belief exist
on the same `triple_key`. Both failures are silent.

Note `as_of` already implements the correct half-open window (`valid_at <= t < invalid_at`),
so the *model* is right; it is the shipped "currently open" predicate that assumes
`invalid_at` is only ever set in the past.

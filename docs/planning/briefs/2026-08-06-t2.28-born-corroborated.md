the ladder's second rung — and serving that badge over an unproven ladder is the exact harm
the gate names. The 2026-08-06 M1 split allows the build because **T2.95 gates the label,

That gate was refuted on the day it shipped and has been through two repair rounds since.
It now holds where it matters to you, and this was verified by drill rather than argued:

**One rider, and it changes your acceptance.** A module that copies a fact row wholesale
and never calls the producer is invisible to every structural rule. That scoping is

## What ships

Consolidation lifts a corroborated Layer-1 assertion — the `repo_ids[]`-tagged entities and
relations T2.27's deriver mints — into a Layer-2 `knowledge_triples` fact that is **born
`corroborated`**, because the parse *is* the verification. It carries a `fact_sources` row
of:

- `source_kind='code'`
- `origin_key = repo_id` — **one origin per repo regardless of commit count.** This is the
  truth-critical rule (doc 10 §6, spec §2.1): re-derivation refreshes and never multiplies
  corroboration. It is the same one-document-one-origin shape `document_id` uses.
- `detail = {commit_sha, basis, file_path, symbol_key}` — addressed by **owner-qualified
  names and commit shas, never the churning bigint node ids.** A node id is meaningless
  after a re-index; a `symbol_key` plus a sha is stable and re-resolvable. This is
  invariant 9's id-normalisation spirit applied to code keys, and T2.48's citation
  re-verifier consumes exactly this shape — get it wrong and that task inherits a
  provenance it cannot resolve.

`app/services/fact_lift.py` is the module to read first: it already writes memory-kind
sources (`MEMORY_SOURCE_KIND`, `_lift_one`), and its `COUNT(DISTINCT origin_key)`
discipline plus its `sources_changed` emit are the shapes you extend rather than parallel.

## Done when (verbatim), and what makes each non-vacuous

- [ ] **A repo indexed 100 times still counts as one origin, proven by test.** Not "the
      code passes the same `origin_key`" — actually re-derive N times and count
      `DISTINCT origin_key` on the resulting `fact_sources`. A test that re-derives twice
      over an unchanged import set may be observing a no-op; change the imports between
      runs so the derivation genuinely re-executes and the origin count still reads one.
- [ ] **Born-corroborated is the only exception to the ladder, and it is documented as
      such.** The exception is narrow and structural: promotion normally counts distinct
      origins, and this path skips that count. Make the exception impossible to widen by
      accident — one code path, named, with a test that a memory-kind source can never
      take it.
- [ ] **Withdrawal (repo removed) demotes the derived facts.** `strip_repo_assertions`
      removes the repo from `repo_ids[]`; when that was the fact's **sole** source,
      consolidation **invalidates** it — closes `invalid_at`, never deletes the row
      (invalidate-not-delete, doc 08). A fact still asserted by a live memory or another
      live repo survives the withdrawal, and that case needs its own test.

## Invariants that bind you

- **Derived rows are never a `fact_sources` origin** (doc 08 §4.1, structural exclusion). A
  Layer-2 fact or Layer-3 article can never inflate the count of a fact it cites.
- **Invalidate-not-delete.** Withdrawal closes a window; it never removes a row.
- **Invariant 15.** Lifting is Tier-C. Nothing here may be reachable from capture or
  retrieval, and a source scan fails the build if it is.
- **Never-join.** Read the code graph, write the memory-side vault, one direction, no
  statement touching both.
- **asyncpg CASTs** on every raw-SQL param Postgres cannot infer.
- **No schema migration.** `0001_baseline.py` has had two owners today already; if you
  conclude you need a change, stop and report.

## The gate, concretely

Without `promotion_metrics_record.json` being `gate_eligible`, a fact whose stored status is
`corroborated` serves as `candidate` on every door, carries **no badge**, and carries
`label_suppressed` so a suppressed label and an earned `candidate` do not read alike. Your
tests must cover both states — gate closed, and gate open via the opt-in
`cleared_promotion_record` fixture. **The fixture is opt-in and must never become
autouse**; that is what left the original leak untested. And the facts-list status filter
now keys on the *served* status, so with the gate closed your born-`corroborated` rows must
not be reachable by filtering for `corroborated` — assert that, because those rows are
exactly what made the filter oracle worth closing.

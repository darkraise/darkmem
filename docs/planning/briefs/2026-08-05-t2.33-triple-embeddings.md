## The two invariants that bound this writer

Doc 08 §5.3 and doc 04 §5.3/§13 are explicit, and both failure modes are silent:

1. **It groups facts for counting only.** It **never merges rows and never rewrites
   `triple_key`.** A writer that merges is not a faster shortlist, it is data loss with no
   error.
2. **`names_distinct` is carried into the grouping.** This is the same guard Phase-4 entity
   dedup carries: names differing by a discriminating token (numbers, dates, versions,
   month names) must not group despite high cosine similarity. Without it the writer
   confidently groups `postgres 14` with `postgres 15`.

And the partition rule from `CLAUDE.md`, which this writer sits directly on top of:
**never name a child table directly — always go through `child_table(parent, fingerprint)`,
and never join across fingerprints.** Resolve the fingerprint the way live read paths do;
`llm_fingerprint()` returns the `model|0` sentinel under a legal config, and three separate
tasks (T2.68, T2.83, and T2.12's F3) have already been minted off that trap.

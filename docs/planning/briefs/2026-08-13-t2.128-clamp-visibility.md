## What the defect was

T2.127 landed a per-bar clamp on G-C's six bars. It is correct: the verdict is
computed against the committed bar whether or not an operator's `config` row tried
to move it. It was also **invisible**. The clamp announced itself only through
`logging.warning`, no runner configures a handler, and `run_gc_evidence.py` printed
no bar block at all — so a clamped run's report body was byte-identical to an
unclamped one. The report is what gets pasted into `gate-ledger.md`; stderr is not.

So the artifact could not distinguish three materially different situations: an
operator's row was refused, an operator's row was honoured, or no row was ever
written. This is not a claim that the clamp failed. It is a claim that the trace
the ruling promised was not in the place a reviewer reads.

## What was done

Resolution returns a `BarReport` (per bar: committed, effective, `requested`,
`clamp`, `licence_bound`). `resolve_promotion_bars` is derived from it rather than
computed alongside it, so the numbers a verdict uses and the numbers printed cannot
become two resolutions that merely agree today. `render_bar_report` prints the
block; `run_gc_evidence.py` prints it immediately before the pre-stated verdicts.

Three provenance states are rendered in words: *no config row*, *honoured* (a free
tightening, or a loosening inside a licence, naming the bound), *CLAMPED* (naming
what was missing — the licence, or the licence's own bound). A run with no rows at
all says so explicitly, because "silent" must not render the same as "clean". The
`promotion_journal_completeness_bar` footnote says in the artifact what the module
docstring says in the source: it is read by no predicate, so its clamp is
prophylactic and not a live protection.

The judge side (`run_judge_qualification.py`) reads no database, so it has no
resolution to report. It is answered by disclosure instead: its bars block now
states that no `verification_bar_licences` row was consulted and nothing there
could have been clamped or licensed.

## Where the review should push hardest

- **The derivation claim.** `resolve_promotion_bars` now goes through
  `resolve_promotion_bar_report`. The iteration order changed from `rows.items()`
  to `PROMOTION_BARS.items()`. Does any behaviour depend on the old order — in
  particular, which unreadable row raises first when a caller writes two?
- **`_clamp_to_conservative` now returns a 3-tuple.** Every warning message is
  supposed to be unchanged; the existing suite asserts several by substring. Is any
  message subtly different, and is any caller left reading the tuple as a float?
- **Whether the rendered text can lie.** The provenance sentence is derived from
  `(requested, clamp, licence_bound)`. Is there a reachable combination where the
  sentence asserts something the resolution did not do — most suspiciously the
  `Conservative.NEITHER` bar, where "moves the bar its own conservative way" would
  be a false sentence if it were reachable.
- **Whether the new test actually pins the property.** The load-bearing assertion
  is that a clamped render differs from a clean one. A test that would pass against
  the pre-T2.128 code, or that compares two strings that differ for an unrelated
  reason, proves nothing.

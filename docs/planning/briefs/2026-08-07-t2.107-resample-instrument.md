# Brief — T2.107, the resample sitting's instrument

**Task:** T2.107 · `Sonnet 5` · `high` · `Size: S` · Doc 17 §6, §11 · Gate: G-D
**Contract:** `docs/planning/agent-runbook.md`. **Baseline:** `CLAUDE.md`.
**Branch:** `feat/e2-lane-ct` off `feat/e2-truth-core`, worktree `.worktrees/e2-lane-ct`.

## Why this task exists and what it must not do

T2.54's Layer-3 blind resample is the last outstanding clause on the entailment gold set.
It blocks G-D (T2.41), and T2.40's run established it blocks G-C's false-promotion audit
too — both numerator arms dead-end on the unqualified judge. The owner is doing the
sitting; **this task builds the instrument so that sitting is one session rather than a
project.**

**The resample is the first accuracy measurement this gold receives from outside the
family that labelled it.** `judge_qualification.py:148-163` says so plainly: the two
earlier blind passes were Claude-family agents labelling work Claude-family agents
authored, and pass B "added ~zero bits and diverged identically to pass A".

**Therefore: no agent labels any pair — not in the sheet, not in the scorer, not in the
tests.** An agent supplying either side of the comparison destroys the only thing the
measurement has. Test fixtures use synthetic pairs; never the real gold's verdicts.

## What already exists — read it before writing anything

`backend/scripts/benchlib/resample_draw.py` is well built and its module docstring
explains its own discipline. It has already:

- Drawn n = 93, stratified: full census of `contradicted` (55 of 55), proportional
  `unsupported` (17 of 85) and `entailed` (21 of 101).
- **Derived** the seed from the gold file's own SHA-256 rather than choosing one —
  "a seed someone picks is a seed someone can re-pick until the sample looks kind".
- Deliberately recorded **no ids** in the manifest, because `{id: stratum}` would publish
  each drawn pair's verdict class.
- Emitted a **shuffled** blind export at `entailment/resample_blind.json` carrying only
  `id`, `premise`, `hypothesis` — shuffled because strata in order would hand a labeller
  the class boundaries even without ids.

`entailment/resample_manifest.json` records `n`, `bar_max_disagreements: 1`,
`gold_sha256`, `seed`, the strata, and `ids_recorded: false` / `labels_recorded: false`.

## What is missing: the return path

`judge_qualification.py`'s `_resample_reasons` requires `gold_doc["resample"]` to be a
dict carrying `n` (≥ 93), `disagreements` (≤ 1), `seed`, `performed_by` and `date`.
**Nothing computes or writes that block.** So today the owner can label 93 pairs and have
no supported way to score them.

## What ships

**1. A readable sheet**, generated **from `resample_blind.json`** — 93 items in the
export's existing shuffled order, each with premise, hypothesis, and the `LABELLING.md`
rule references a labeller needs to decide it, plus a slot for one verdict of
`entailed` / `contradicted` / `unsupported`.

It must leak nothing the export does not already leak: no stratum, no ordering signal, no
neighbouring-item hint, no count-per-verdict summary. Pick a format that is genuinely
faster to work through than the raw JSON and easy to return — the owner is making 93
judgments in one sitting, so the format is doing real work.

**2. A scorer** that takes the completed verdicts and writes the `resample` block.

## The clauses with teeth

- [ ] **The sheet is generated from `resample_blind.json`, never from `gold.json` —
      proven structurally.** An import or a read of the gold from the sheet generator is
      the failure; make a future edit unable to reach the labels rather than merely not
      reaching them today. The repo's idiom for this is an AST/source scan that fails the
      build (`test_code_deriver.py`'s roster scan and the invariant-15 reachability scan
      are the live examples). The recorded trap: a scan matching a module name as **text**
      also fires on prose in comments — write yours against the parsed tree.
- [ ] **The scorer refuses when `gold.json`'s SHA-256 no longer matches the manifest's
      `gold_sha256`.** The draw is pinned to one gold version; scoring a stale draw
      certifies nothing. Fail loudly with what changed.
- [ ] **It writes `n`, `disagreements`, `seed` (from the manifest, never recomputed from a
      changed gold), `performed_by` and `date`, and the real
      `judge_qualification` lock accepts the block** — test against the actual lock
      function, not a mock of it.
- [ ] **A re-run cannot improve the number.** One sitting, recorded once per draw; a
      second sitting means a new draw against a new gold SHA. Decide how you enforce it —
      refusing when a `resample` block already exists is the obvious route, and it needs an
      explicit override path for a genuine correction, which must be visible in the record
      rather than silent. State your choice.
- [ ] **Disagreeing items are reported by id with both verdicts.** A miss is the
      instrument's most useful output: it localises where the rulebook is underspecified,
      and the owner needs to see exactly which pairs and how they differed. A scorer that
      prints only a count wastes the sitting's most informative result.

## Scope boundaries

- **Do not modify `gold.json`'s pairs, labels, or `resample_blind.json`.** You add a
  `resample` block through the scorer; you never touch a verdict.
- **Do not re-draw the sample.** The draw is done and pinned.
- **Do not change the bar** (`RESAMPLE_N = 93`, `RESAMPLE_MAX_DISAGREEMENTS = 1`) or the
  duplication between `resample_draw` and `judge_qualification` — the suite asserts they
  agree deliberately, one being the draw and the other the lock.
- **No schema change, no app code.** This is `backend/scripts/benchlib/`.

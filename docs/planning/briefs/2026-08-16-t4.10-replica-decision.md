## One live finding from today that post-dates the audit

T4.05's review surfaced a systemic hole the audit does not carry:
`make_repo_sync_runner` (`app/services/job_runners.py:44-52`) **never reads
`repo.status`**, so a poll tick during any in-flight index enters `CodePipeline.run`
concurrently, and one failure disables `auto_sync` for that repo
(`repo_manager.py:294`). It is a single-process hazard already; N workers multiply
it. The suggested close is a compare-and-swap status claim inside `run()` so every
door inherits it. **Assess whether it changes your decision**; it is not yours to
fix.

## What the task is

First writer to the block partition template, which landed **inert** in T0.13.
The template already exists — `app/services/embedder_registry.py` carries
`block_embeddings` in both its template table and its index list, and
`0001_baseline.py` references it. **You are not changing the schema.** The
baseline is a single shared mutable file that serialises through one owner per
epic; if you conclude a schema change is genuinely required, stop and report
rather than editing it.

Your predecessors: TH1.02 landed `documents`/`blocks` and the content-hash gate,
TH1.03 the parser stack, TH1.04 the block tree and strip-before-rewrite. Read
`app/repositories/documents.py` and `app/services/document_ingest.py` — the
latter's module docstring names TH1.05 as the owner of this partition.

**Done when:**
- Register-before-insert is honoured. `_register_fingerprint` must be called
  before **any** insert into a partition; this is not advisory, it is what makes
  the child table exist.
- Naming goes through `child_table(parent, fingerprint)` **only**. Application
  code never names a child table directly.
- No cross-fingerprint comparison (invariant 2). A query joining across
  fingerprints is a bug — cross-fingerprint cosine distance has no definition.
  Prove the absence, do not assert it.

## Two hazards this epic has already paid for

1. **`file_document` owns no savepoint** — TH1.04 found it and deliberately did
   not flip the default, so the foot-gun is still live for any direct caller. On
   a failed parse the document keeps the **new** `content_hash` while the strip
   has already deleted the old blocks, and the next re-file short-circuits over
   an empty tree with nothing reporting it. If your writer calls into that path,
   do not inherit the hazard silently — the durable close is the owner's, but
   your own module must not be the next victim.
2. `_span_literal` accepts `end == start`, storing an **empty** range whose
   bounds read NULL — a block retrievable while its citation anchor resolves to
   nothing. Known, surfaced for the owner, not yours to fix. Do not build on the
   assumption that a stored span is non-empty.

## The standard this repo holds

- **Every guard gets a mutation drill.** Break the guard, watch the test go red,
  restore it. A guard that cannot be shown to fail is decorative and gets
  **deleted**, not shipped for comfort. TH1.03 deleted one of its own on exactly
  this rule; TH1.04 killed 20 of 20 mutants.
- **Prefer tests that count work over tests that count rows.** TH1.02 proved
  "zero work" with five independent witnesses — the parse callable never
  invoked, one statement issued and it a SELECT, block ids unchanged, `ctid`
  unmoved, no second journal row.
- Asserting `updated_at` unchanged **can never fail** — `touch_updated_at` stamps
  transaction-start time. TH1.02's implementer caught this in its own test before
  shipping. Do not reintroduce it.
- Record the **real** verification output, never "should pass".
- Do not mark work done with a failing check.

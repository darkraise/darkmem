## The constraint that decides the fix

**The production invariant is intact.** `embedder_registry.register` always creates
the full partition set. This is purely a test fixture violating that invariant — so
**hardening `delete_code_chunks_by_repo` would be treating the symptom, and the
task forbids it.** The repository method is behaving correctly by trusting an
invariant that production upholds.

The fix belongs to `test_memory_dream.py` (T2.12's suite). Either the committing
teardown removes the `embedders` rows and their partitions, or `seed_partition`
seeds all four child tables — your call, argued.

The floor is green today because no test of the crashing shape exists yet. TH1.06
is the next task likely to write one, which is why this is worth closing now
rather than when it bites.

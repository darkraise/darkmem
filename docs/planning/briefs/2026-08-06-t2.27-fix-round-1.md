## The five Important findings

- **I1 — the LLM-free guard misses relative imports.** `from .pipeline import
  ProcessingPipeline` passes both guards, because the closure builder skips every
  `level > 0` import, so an intermediate module that reaches the LLM never enters the
  scanned set. The absolute spelling of the same reach *is* caught, which is what makes
  this a hole rather than a design.
- **I2 — the HTTP-client scan split created a hole.** `importlib.import_module("httpx")`
  at module level passes: the literal route was dropped for clients, and the loader-call
  route resolves only relative names. Your predecessor dropped the literal route wholesale
  to stop `"openai"` in `_TYPE_OVERRIDES` tripping it; the reviewer names the narrower fix
  — `exempt_node_ids` on the `_TYPE_OVERRIDES` dict node — which keeps the route and
  exempts the one datum. **A guard's negative control must prove both directions**; the
  shipped one proves only the false-positive direction.
- **I3 — one sweep predicate has no behavioral test.** `delete_by_memory_id`'s *relation*
  repo-predicate (`graph.py:521-524`) is guarded only by the `== 6` string count. The
  reviewer weakened it to the copy-paste `rp.id = ANY(entity_relations.memory_ids)` and
  **all 60 tests still passed**, while a relation asserted by both a memory and a live
  repo was silently deleted when its last memory was stripped. The SQL is correct; the
  test is missing. That row-class is a normal state this task creates through its own
  `ON CONFLICT` append, so it is not a hypothetical.
- **I4 — every repo→language edge is `DEPENDS_ON`.** Doc 10 §6 and the brief both fix it
  as `repo —USES→ language`. The report reads the doc as leaving the split open; it does
  not, for the language case. Fix the edge, not the doc.
- **I5 — the import parser is Python/JS-shaped and the indexer is not.** Verified against
  the shipped functions: Rust mints a `tool` literally named
  `use std::collections::hashmap;`, Go mints `fmt` and `encoding`, Java mints `com` and
  `java`, C# mints `system` — and `code_parser.py` indexes all of those languages and
  writes their import edges. **These are wrong facts in the one direction a
  fact-originating bridge forbids.** Your predecessor's own stated principle — a missing
  fact is cheaper than a wrong one — is the right one, and it was applied to the suffix
  rule but not here.

  **Recommendation, which you may overturn with a reason:** do not write six import
  parsers. Restrict derivation to the languages whose import shape the deriver actually
  understands, skip the rest **explicitly and visibly** (a named set, a test that fails
  when a new language is indexed without being classified, and a count of what was
  skipped), and let a later task widen it. A deriver that silently mints garbage for four
  languages is worse than one that openly covers two.

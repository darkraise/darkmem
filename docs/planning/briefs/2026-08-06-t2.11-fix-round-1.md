## I1 — the verdict bit is trusted, and nothing pins its writer (Important)

The invariant-15 architecture is sound and the reviewer confirmed it independently:
`contradiction_scan` joined the forbidden set automatically through the umbrella-import
derivation, `test_dream_jobs.py` is untouched, `_ALLOWED_VETO_FILES` is untouched, and
importing the scan from `hybrid_search.py` fails the build immediately. The re-validation
genuinely re-checks liveness, project, window overlap and both witness sides against live
rows.

**What it does not re-check is the verdict itself.** Any `contradiction_scanned` row is
trusted for that bit, and no scan pins who may write one — the suite's own `_record_verdict`
helper demonstrates a single bare `record_event` call disputing a fact with **no judge
anywhere in the path**. That is the heuristic back door the whole indirection exists to
prevent.

The reviewer names the fix: **a per-event-type emitter scan**. `contradiction_scanned` may
be emitted from exactly the scan module, and the build fails when any other module emits
it. This repo has the idiom already — the veto file allowlist and the single-door judge
scan are both this shape. Write it against the parsed tree, not line text, and give it a
negative control that proves both directions.

## I2 — a swallowed journal write is counted as a success (Important)

`record_event` degrades loudly but never raises into its caller. So when the journal write
fails, the dispute is counted in `disputes_recorded`, the watermark advances, and `misses`
reads zero — **the job's sole output silently dropped, reported as clean.** That is exactly
the failure the third Done-when clause ("misses are counted, not hidden") exists to
prevent, arriving through the one path the clause did not consider.

**The in-repo precedent is `dream_undo`**, which counts its own `undone` rows back and
raises when short, for the same reason: an action that could not be journalled did not
happen. Adopt that shape here — count the rows back, and treat a shortfall as a miss (or a
failure), never as a recorded dispute.

## I3 — a manufactured dispute is permanent. **Ruled: accept and document honestly.**

Once the ladder applies a scan dispute, doc 08 §5.3's own restriction to servable facts
*not already disputed* means no later scan pass can re-adjudicate that fact. So a judge
false positive whose guards keep holding is a **permanent** manufactured dispute, and the
only exits are guard-lapse or human ratification.

**This is plan-mandated and stays.** The exclusion is what stops the scan re-paying LLM
cost on facts it has already ruled on, a disputed fact is served labelled with **both
sides** rather than dropped or hidden (doc 08 §6, invariant 14), and human ratification is
a designed exit rather than an accident. The precision-first asymmetry already accepts a
bounded false-positive rate behind a 0.95 bar.

**What is not acceptable is the docstring.** The detector currently says a later clean
pass ends the dispute; the reviewer established that only operates in the pre-application
race window. Correct it to say what actually happens, name the two real exits, and say
that permanence is a consequence of the doc's exclusion rather than an oversight. A
comment that describes a recovery path the code does not have is worse than no comment —
the next reader budgets for self-healing that will not arrive.

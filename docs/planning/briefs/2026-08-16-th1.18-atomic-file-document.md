# TH1.18 — Make `file_document` atomic by default

`Model: Opus 5` · `Effort: high` · `Size: S` · `Doc: 16 §3` · `Gate: —`

## The defect

`file_document` owns no savepoint. On the failure path the document row keeps the
**new** `content_hash` while the strip has already deleted the old blocks and the
replacement never landed — so the next re-file short-circuits on a gate that agrees
with a tree nobody wrote. The blocks are gone permanently and nothing reports it.

The hash move is the worse half: block loss alone would at least be re-fileable.
TH1.03's drill proved the block loss; TH1.04 pinned the hash move with
`test_without_the_savepoint_the_same_failure_destroys_both` (blocks empty, hash
moved, replay returning `UNCHANGED` over an empty tree).

TH1.04 guarded only the module it owned, so **the foot-gun is live for any other
direct caller — and EH1 is adding callers now.** TH1.05 landed
`block_embeddings.py` this session; TH1.06 is next.

## The shape, which is the whole reason this is a task and not a one-liner

**Flip the default; TH1.03's naive helper opts out explicitly.**

That helper is a standing regression drill: it runs the identical three-document
scenario with no SAVEPOINT and asserts the blocks come back empty, committed
permanently so the isolation property cannot silently regress. Making atomicity
unconditional would **delete that drill**, which is why the opt-out is part of the
owner's ruling rather than a concession to it.

The opt-out must be reachable only from the test helper, and a test must prove the
production path cannot take it. A private keyword the helper passes, a separate
internal entry point — your call on mechanism, but "reachable only from tests" has
to be a proven property, not a naming convention.

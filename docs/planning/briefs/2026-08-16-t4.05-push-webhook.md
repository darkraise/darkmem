# T4.05 — Push webhook receiver

`Model: Sonnet 5` · `Effort: high` · `Size: M` · `Doc: 10 §5, 15 §9` · `Gate: demand-gated`
Epic: `docs/planning/tasks/E4-hardening-and-scale.md` (§ T4.05) — read it first.

## What the task is

Replace periodic change-gated `repo_sync` polling **for the pushed repo only**,
reusing the identical change-gated `CodePipeline.run`. **Never a second indexing
path.** That phrase is the task, not a caveat on it: MCP's `code_search` and
`code_blast_radius` once held parallel implementations of the same thing and had
already diverged before T1.42c collapsed them.

T4.01 (`7ec957ba`, done) is why this task's entry condition is met — the
webhook's "externally reachable authenticated receiver" now has a credential to
authenticate against. Read `app/services/code_pipeline.py` and the `repo_sync`
job before designing anything.

**Done when:**
- The webhook calls the same pipeline entry point as polling, **proven by test**
  — not by inspection, and not by a test that merely asserts both succeed.
- Signature verification happens **before any work**. Not before the write:
  before the work.
- Polling remains for repos without a webhook, and the two **never double-index**.
- An unchanged HEAD short-circuits exactly as polling does.

## What the indexing path already guarantees, and must keep guaranteeing

An unchanged HEAD sha short-circuits unless `full=true` **or the repo carries
outstanding index debt**. That debt is real state: an incremental run re-traces
the callers of every changed file, capped at `DEPENDENT_RETRACE_CAP` (500), and
the callers past the cap are **persisted to `repositories.index_debt`, never
dropped** — dropping them leaves a graph that is quietly wrong, with no error and
no symptom but missing callers. A webhook path that short-circuits on the sha
alone and forgets the debt drain reintroduces exactly that silence. Both the
deferral and the drain journal a `repo_indexed` `events` row.

  `export TEST_DATABASE_URL=postgresql+asyncpg://darkmem:darkmem@localhost:5433/darkmem_test_4`

- Bound every command with an explicit timeout. An unbounded filesystem search
  ran 1h48m in this repo.
- Never detect processes with `pgrep -f` on a pattern your own command line
  contains — it self-matches. Read `/proc/<pid>/cwd`.
- Never `git add -A`. A shared-tree `git add -A` once swept 1,110 lines of
  another task's source into an unrelated docs commit. Add paths explicitly.

## The standard this repo holds

- **Every guard gets a mutation drill.** Break the guard, watch the test go red,
  restore it. A guard that cannot be shown to fail is decorative and gets
  **deleted**, not shipped for comfort. Signature verification is the guard this
  task most needs drilled: a receiver that accepts a bad signature in some
  reachable branch is the whole failure mode.
- **Prefer tests that count work over tests that count rows.** "Never
  double-index" and "short-circuits on unchanged HEAD" are both work claims —
  count pipeline invocations, not resulting rows.
- Asserting `updated_at` unchanged **can never fail** — `touch_updated_at` stamps
  transaction-start time, so it compares equal inside one test transaction
  whether or not the row was rewritten.
- Record the **real** verification output, never "should pass".
- Do not mark work done with a failing check.

## Task P0.2 — Commit delete-deadlock fix

**Files:**
- `backend/app/services/memory.py:86-99` — `delete_memory` commits the parent transaction before calling `pipeline.delete_memory`.

**Commit:**
```
fix(memory): commit parent tx before pipeline cleanup to avoid delete deadlock

DELETE /memories/{id} used to flush the row deletion on the request session
and then open a fresh session via pipeline.delete_memory to clean the
embeddings and graph. The parent still held CASCADE row locks, so the fresh
session blocked on the embedding row, and the parent was waiting for the
pipeline call to return. Two-session deadlock that filled the connection pool
and locked the API. Commit the parent session before dispatching cleanup.

Refs: docs/e2e/runs/2026-04-10-run.md Phase 4
```

## Task P1.3 — Fix RAG retrieval miss on "summarize recent decisions"

**Problem:** Asking the chat "Summarize recent decisions" answers "Recent memories do not contain specific information about recent decisions", even though the DB has two memories tagged `project/decisions` and typed `decision`. The semantic search finds unrelated tech memories (circuit breakers, Raft, etc.) instead.

**Root cause:** `pipeline.semantic_search` is purely vector + keyword RRF with no type/tag-awareness. The query "decisions" has low cosine similarity to the actual decision memories because their content is about pgvector and Docker Compose, not about the word "decisions" itself. A BM25 pass on the word "decisions" also doesn't match any content body — it's only in the tag taxonomy.

**Fix approach:** Inside `MemoryService.reason`, detect query terms that match **memory type** or **tag** values and boost rows that carry those labels. Specifically, add a light type/tag-aware retrieval pass that runs in parallel with the semantic path and is merged via RRF.

**Files:**
- `backend/app/services/memory.py:191-260` (`reason` method)
- `backend/app/repositories/relational.py` — add a helper `search_by_terms` or reuse `search_by_tags` with a relaxed query.

**Concrete changes:**

1. **Detect type/tag hints in the question.**
```python
# in MemoryService.reason, after getting the question
type_hints: list[str] = []
tag_hints: list[str] = []
q_lower = question.lower()
KNOWN_TYPES = ("fact", "decision", "problem", "preference", "reference", "architecture", "milestone")
for t in KNOWN_TYPES:
    # match "decision" and "decisions", etc.
    if t in q_lower or f"{t}s" in q_lower:
        type_hints.append(t)
# loose tag hint: if the question says "decisions", also look for tag prefix project/decisions
# (same loop can populate tag_hints)
```

2. **Add a second retrieval pass** that pulls memories matching `type_hints` OR `tag_hints` and merges them with the semantic results.
```python
# fetch type/tag matches via the existing memory_repo
if type_hints or tag_hints:
    type_tag_results = []
    for mt in type_hints:
        rows = await self.memory_repo.search_by_tags(
            memory_type=mt, limit=limit,
        )
        type_tag_results.extend(rows)
    for tg in tag_hints:
        rows = await self.memory_repo.search_by_tags(
            tags_any=[tg], limit=limit,
        )
        type_tag_results.extend(rows)
    # dedupe, rerank: put type/tag hits at the front
    seen: set[UUID] = set()
    for m in type_tag_results:
        if m.id not in seen:
            seen.add(m.id)
            # prepend as top-ranked sources
            sources.insert(0, {
                "memory_id": str(m.id),
                "content": m.content[:200],
                "score": 1.0,
                "tags": [t.name for t in m.tags],
            })
            context_parts.insert(0, f"[0] {m.content}")
```

3. **Write a test** before implementing:
```python
# tests/backend/services/test_memory_reason_decisions.py
async def test_reason_finds_decision_memories_for_decisions_query(session):
    svc = MemoryService(session, pipeline=...)
    # ... create two memories with memory_type="decision", content about pgvector and docker

    assert len(result["sources"]) >= 2
    contents = " ".join(s["content"] for s in result["sources"]).lower()
    assert "pgvector" in contents or "docker compose" in contents
```

- [ ] Run it — expected to fail with 0 sources.
- [ ] Implement steps 1 and 2 in `reason`.
- [ ] Re-run the test — expected to pass.
- [ ] Re-run the chat in the UI with `Summarize recent decisions` — expected to cite the two decision memories.

## Task P4.1 — Swallow the initial `/auth/me` 401 console error

**Problem:** The auth probe on page load always logs a red `401 Unauthorized` in the browser devtools even though it's expected behavior.

**Fix:** Catch the 401 in a dedicated auth-probe function and return `{ authenticated: false }` instead of throwing.

```ts
export async function checkAuth(): Promise<boolean> {
  try {
    const r = await fetch("/api/v1/auth/me", { credentials: "include" })
    if (r.status === 401) return false  // expected, don't log
    if (!r.ok) return false
    return true
  } catch {
    return false
  }
}
```

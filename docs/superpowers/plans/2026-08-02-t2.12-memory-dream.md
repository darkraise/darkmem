### 1.6 `memory_crossrefs` is not a usable similarity source, and the brief was right to ask

Three independent defects, all measured:

1. **No fingerprint column.** `0001_baseline.py:324-333` — the table is
   `(memory_id, related_memory_id, score)` and nothing more. Rows written before an
   embedder rotation and rows written after it sit in one table with no way to tell them
   apart, and a cross-fingerprint cosine has no defined meaning (invariant 2). A pass that
   read this table as a similarity source would be comparing scores from two different
   metric spaces.
2. **Not project-scoped.** `app/services/pipeline.py:796` calls
   `find_similar_memories(...)`, which at `app/repositories/vector.py:475-486` calls
   `search(vector, fingerprint, limit=top_k+1)` with **no `MemoryFilter`** — and
   `MemoryFilter`'s own docstring (`vector.py:29-31`) says `None` means "no scoping at
   all … the crossref probe wants every candidate regardless of lifecycle". So crossrefs
   legitimately cross projects and lifecycle states. Supersession never crosses the
   project boundary (doc 08 §2.1 rule 1), so a dedup arm seeded from crossrefs would
   propose pairs the primitive must refuse with `cross_project`.
3. **Threshold and staleness.** `min_score=0.4` is a *related-memories UI* threshold, not
   a near-duplicate one, and the rows are written once at ingest and only rewritten when
   *that* memory is reprocessed — so a memory's crossrefs never learn about neighbours
   captured after it.

**Decision: do not read `memory_crossrefs`.** D3 generates pairs from a fresh,
fingerprint-pinned, project-scoped ANN probe.

## 3. Design decisions, made executable

### D1 — Module layout, the LLM handle, and invariant 15

**One job-body module: `app/services/memory_dream.py`.** `dream_jobs.py` imports exactly
that one name from it, so invariant 15's derived forbidden set gains exactly one module
and the guard covers the whole body. Splitting the judge into a second module would put
the prompt, the parser and the LLM call **outside** the scan's derived set — legal, but it
would mean the guard covers less of T2.12 than a reader would assume, and this corpus
treats an overclaimed guard as worse than the gap it hides (`tests/test_supersede_primitive.py:1016-1023`).
The pure helpers (`build_pair_messages`, `parse_pair_verdict`, `build_refine_messages`,
`parse_refine`) are functions in that one module, unit-testable without a session.

**The relations repository is separate** (`app/repositories/memory_relations.py`) and is
**not** imported by `dream_jobs.py`, so it stays outside the forbidden set. That is
correct rather than a loophole: T2.16 and T2.17 must be able to import it, and a
repository is not a job body. Stated here so a reviewer does not read it as scan evasion.

**The LLM handle.** `register_dream_jobs(registry)` today receives only the registry
(`app/main.py:362`), and `app.state.llm` is swapped on a config save
(`app/api/routes/config.py:100`), so closing over an instance goes stale.

- **(a) Recommended — widen the umbrella's signature to
  `register_dream_jobs(registry, llm_provider)`** where `main.py` passes
  `lambda: getattr(app.state, "llm", None)`. A provider callable rather than the FastAPI
  app, so the umbrella stays framework-free and a test can pass a stub in one line. Costs
  two edits outside the new module: `main.py`'s call site, and the exact-line set at
  `tests/test_dream_jobs.py:290-296`. Both are small, both are in the same commit, and
  **T2.11 and T2.53 need the same handle**, so paying it once here is cheaper than three
  times.
- **(b) Fallback — build a per-run orchestrator** from
  `get_llm_config(session)` (`app/services/config.py:48`) inside the runner, closed in a
  `finally`. Zero edits outside the new module. Rejected as the default because it mints a
  second way to obtain an orchestrator, and a per-tick client discards the connection
  pool.

If the controller wants zero shared-file edits this round, (b) is a one-function swap and
nothing else in the plan changes.

**When the provider yields `None`** (Postgres-only mode, `main.py:141-143`), the two LLM arms
are skipped, the run reports `skipped_reason="llm_unavailable"`, and **nothing is written
and nothing is deleted** — the same discipline `memory_community_detection.py:33-37` applies
to a missing clustering library, and for the same reason: a pass that computed nothing must
not write a result or destroy a previous one.

### D2 — The three actions: detector, writes, payload, inverse

This is the table the brief asks for. "Inverse" is what T2.13 will execute; every one is a
status, pointer, or field restore, never a resurrection.

| | **A1 — Subsumption** | **A2 — Near-duplicate** | **A3 — Refine** |
|---|---|---|---|
| **Doc** | 08 §5.4, §2.2 | 08 §5.4, §5.5, §6 | 08 §5.4, §7 |
| **Detector** | A pair `(older, newer)` from D3's ANN probe, direction fixed by `successor_is_newer` (D4), that the `reasoning`-purpose judge labels **`subsumes`** | The same pair, judged **`duplicate`** | A memory whose `metadata.dream.refine.content_sha` ≠ `sha256(content)`, visited on the rotating cursor |
| **Writes** | `supersede(session, memory_id=older, superseded_by=newer)` — one `UPDATE`, the primitive's | One `memory_relations` upsert: `(source=newer, target=older, rel_type=ELABORATES or RELATES_TO, project, properties)` (D8) | `UPDATE memories SET summary=…` and/or `set_tags(...)`, both through the **write allowlist** (D7); plus the `metadata.dream.refine` marker in the same statement |
| **My event payload** (`consolidated` / `memory`, D9) | `{action:"subsume", before:{status,superseded_by}, after:{status,superseded_by}, pair:{older,newer}, detector:"dedup", verdict, score}` | `{action:"associate", before:{edge:null \| existing properties}, after:{edge:{source,target,rel_type,properties}}, created:bool}` | `{action:"refine", before:{summary,tags,metadata_dream}, after:{summary,tags,metadata_dream}, fields:[…]}` |
| **Exact inverse** | `UPDATE memories SET status=before.status, superseded_by=before.superseded_by` **in one statement** (the CHECK forbids the two-statement form) | If `created` is true, `DELETE` that one `memory_relations` row; if false, restore `properties` to `before.edge`. **Never** touch the endpoints | `SET summary=before.summary`, `set_tags(before.tags)`, `metadata.dream = before.metadata_dream` |
| **Why the inverse is total** | Only `status` and `superseded_by` moved; both are in `before` | The edge is a whole row I created, or a `properties` blob I overwrote; endpoints self-heal via the composite FK | Only allowlisted derived fields moved; `content` is provably untouched (D7) |

**Nothing in any inverse needs `content`.** That is the whole reason `refine` may not
touch it: an action whose inverse needs the original content is an action T2.13 cannot
undo, because `content` is not journalled anywhere and must not be (journal payloads
outlive their memory — CLAUDE.md, "Journal payloads may carry content previews", an
unresolved Tier-3 retention question I must not enlarge).

**A2's direction.** The edge is written `source=newer, target=older`. `ELABORATES` when
the judge says the newer adds detail; `RELATES_TO` otherwise. Both go through
`normalize_memory_relation_type` (`taxonomy.py:315`) — I never store a raw string — and the
writer refuses `is_projected_memory_relation_type` outright, because `SUPERSEDES` must
stay the projected pointer.

### D3 — Pair candidate generation: fingerprint-pinned, project-scoped, cursor-bounded

Not `memory_crossrefs` (§1.6). Instead, per run:

1. Resolve the **active** fingerprint once, from the same orchestrator the judge will use
   (`llm.llm_fingerprint()`, `llm.py:104`). Every probe in the run uses that one value.
   A rotation between runs simply means the next run works in the new partition; a
   rotation *within* a run is impossible because the value is read once.
2. Take a rotating slice of `batch_size` seed memories, ordered by `(created_at, id)` past
   a persisted cursor, scoped `status='active' AND is_archived=false AND (expires_at IS
   NULL OR expires_at > now())` — the same eligibility predicate
   `memory_community_detection.py:163-169` uses, so two consolidation passes do not
   disagree about which memories exist.
3. For each seed, one ANN probe against `memory_embeddings__<slug>` via
   `PostgresVectorRepository.search(vector, fingerprint, limit=pair_candidates,
   filters=MemoryFilter(project=<seed's project>, statuses=("active",)))`. **The
   `MemoryFilter` is not optional**: without it the probe crosses projects and the
   primitive would refuse every such pair with `cross_project`, turning a design error
   into a silent refusal count.
4. Keep candidates with `score >= near_duplicate_threshold_pct / 100`.
5. **Canonicalise the pair** as `(older, newer)` by `successor_is_newer`, and **dedup
   pairs by the unordered id set** — A's probe finding B and B's probe finding A is one
   pair, and judging it twice would double the LLM cost and could produce two contradictory
   verdicts in one cycle.
6. Cap the surviving pairs at `judge_fanout` per run.

A seed whose embedding row is absent from the active partition (never re-embedded after a
rotation) yields no probe and is counted as `pairs_skipped_no_vector` — not an error, and
explicitly **not** a reason to reach into another fingerprint's partition.

### D4 — The direction rule, and what dreaming does with a `successor_not_newer` refusal

**The direction is never the model's to choose.** The judge is asked one question about an
already-ordered pair — *does the NEWER memory subsume or correct the OLDER one?* — and I
fix `(older, newer)` with `successor_is_newer` (`supersede.py:193`), the **same predicate**
the primitive re-evaluates. Asking the model which direction to supersede would let a
plausible-sounding wrong answer produce exactly the mutual flip the amendment exists to
block.

Consequently `successor_not_newer` is **unreachable on the happy path by construction**,
and that changes what the refusal *means* when it does arrive:

| Refusal | Meaning | What dreaming does |
|---|---|---|
| `successor_not_newer` | My ordering and the primitive's disagreed — a genuine defect signal, or the row moved between D3 and the write | Count it in `refused_not_newer`, **log a WARNING**, journal nothing (no transition happened), continue with the next pair. **Never swap the endpoints and retry** — a retry in the other direction is precisely the write the ruling forbids, and it would supersede a newer memory with an older one, invisible to T2.60's blocker |
| `already_superseded` | The older memory was already superseded — by the fast path, or by an earlier action *this same cycle* when two pairs shared it | Ordinary. Count `refused_already_superseded`, journal nothing, continue. This is the expected steady state, not an anomaly |
| `terminal` | The older memory is `deprecated` | Ordinary. Count, journal nothing, continue |
| `cross_project` | A design error in D3's filter | Count, log a WARNING. If this is ever non-zero, `MemoryFilter` was dropped |
| `self_reference` | Pair dedup failed | Count, log a WARNING. Unreachable while step 5 of D3 stands |
| `not_found` | The candidate or the successor was deleted between phases | Ordinary under concurrency. Count, continue |

**"It is not an error, it is the ruling working"** — and the honest form of that is: the
refusal is reported, never swallowed, and never worked around. The run outcome carries
every count, and Step 7's assertion is that `refused_not_newer` is **zero** across the
whole test suite, so the day it is not, a test says so.

**A second-order consequence D3 must respect.** Same-batch memories share one server-side
`created_at`, so the `id` tie-break is what orders them. `successor_is_newer` normalises
both ids through `UUID(str(...))` (`supersede.py:227-233`); my ordering must call that
function rather than re-spell the comparison, or a `str` vs `UUID` compare would order by
text and disagree with the primitive on exactly the same-timestamp pairs the tie-break
exists for.

### D5 — The status bridge arm is deferred (ruled 2026-08-02), and what T2.12 does instead

**Ruled by the controller, who verified §1.7's claims independently rather than taking
them: T2.12 ships dedup-driven subsumption only.** The bridge-driven arm is deferred to a
follow-up task blocked on a fact-invalidation producer. The reasoning, recorded here so
this is a decision rather than a compliance:

- **Doc 08 §2.2 names two callers, and only one is mine.** "dedup finds a near-identical
  newer memory that strictly subsumes an older one, **or** the status bridge decides a
  memory's every live fact is now invalidated." T2.12's own task text describes
  subsumption from dreaming and never mentions the bridge, so the arm was never clearly
  T2.12's to begin with.
- **An arm that cannot fire on real data is worse than no arm.** Its only exercise would
  be a hand-built fixture, and a green test over a path nothing reaches reads as coverage
  on a gate surface while covering nothing.
- **Not fabricating a pairing was the right call and stays the rule.** Substituting the
  invalidated fact's own id for the invalidating one would let guard 1 nominate, as "the
  memory that replaced this one", another memory asserting the very same discredited
  fact — a wrong write, not a conservative one. Whoever builds the arm inherits this
  constraint.

**What T2.12 therefore does with `apply_status_bridge`: nothing.** It calls `supersede()`
directly, on a pair whose direction it fixed itself (D4). The bridge, its two guards, the
ruled evaluation order and `BridgeDecision` are all untouched — T2.45's work is
**built-but-unspent**, not defective, and this plan says so in §9.1's amendment row so a
later reader does not mistake an unspent path for a broken one.

**What the follow-up task inherits from this section**, so its author does not re-derive
it: the drain is `events WHERE event_type='invalidated' AND object_type='fact'` past a
**`(created_at, id)` tuple** watermark with the commit-skew margin
`verification_recompute.py:279-283, 434-460` established (a bare `created_at >` watermark

the decision was `no_change`.

**Which producer actually unblocks it.** Not T2.34 alone. T2.34 pre-closes a fact's belief
window when its *own stated expiry* passes, which makes `close_window` reachable and
`invalidated` events real — but a window closed by its own expiry has **no replacing
triple**, so it still supplies no `invalidating_fact_id`. The arm needs a producer of a
*replacement*: a stale-on-arrival pass over a temporally-qualified Layer 1, or a
contradiction-driven invalidation that names the winning fact. Stated precisely so the
follow-up is not scheduled behind the wrong dependency.

### D6 — Transaction and batching shape, given the primitive opens nothing

Three phases, and the ordering is the safety argument — the shape
`memory_community_detection.py:8-29` established and its review hardened over three passes.

**Phase R — read.** One session. Load the cursor/watermark state, the seed slice, the seed
vectors, the ANN candidates, and the refine work set. Read-only, so it takes no row locks.
**`await session.commit()` before Phase C**, for the reason stated at
`memory_community_detection.py:269-276`: the LLM fan-out can run for minutes and a pooled
connection must not sit `idle in transaction` pinning `xmin` for that long.

**Phase C — compute, with no transaction open.** Every LLM call lives here: the pair
judgments and the refine rewrites, fanned out under an `asyncio.Semaphore` bounded by
`llm_concurrency`, each seeded with `_content_seed(...)` so a replay is reproducible
(CLAUDE.md, "Reproducibility"). Every fallible step — the provider being `None`, a
timeout, a truncation, an unparseable body — is here, where it holds no transaction and
touches no row. A per-item failure produces no action for that item and is counted; it
never aborts the phase.

**Phase W — write, in bounded batches.** A fresh session per write batch of
`write_batch` actions. Per action:

- `async with session.begin_nested():` — **the savepoint the primitive does not open**
  (T2.45 A2, `supersede.py:50-52`).
- `SET LOCAL lock_timeout = '5000ms'` immediately inside it, verbatim in intent from
  `verification_recompute.py:357-394`, so a wedged row lock becomes an ordinary per-item
  failure instead of consuming the whole tick's `max_run_seconds` and voiding every action
  the tick had already taken. That module's docstring is precise about `SET LOCAL`
  reverting on rollback but **not** on release; the same reasoning applies unchanged here
  because every action re-issues it.
- **Re-read the target row(s) under `FOR UPDATE` and re-validate the precondition.**
  Phase C computed on a snapshot; between R and W a capture could have superseded the
  memory, a delete could have removed it, or a re-extraction could have changed its
  `content`. The re-validation is: status still `active`; `sha256(content)` still equal to
  the value Phase C judged. A mismatch is a **skip**, counted as `stale_skipped`, never a
  write. Without this the refine arm can clobber a concurrent edit, and the subsume arm
  can act on a pair one of whose halves no longer exists.
- Apply the action. Journal from the same session.
- On any exception: the savepoint rolls back, the item is counted in `failed`, the loop
  continues. One poisonous item settles alone.

`await session.commit()` once per batch, **with the cursor/watermark advance in that same
transaction**, so a crash re-does at most one batch. Re-doing a batch is safe because every
action is idempotent on replay: `supersede()` is monotonic and returns
`already_superseded`; the edge write is an upsert; refine is suppressed by its
`content_sha` marker (D7).

**Journalling from a session that survives a rollback.** A batch that aborts wholesale
journals its abort from a *fresh* session, the fix
`memory_community_detection.py:423-429` records: a journal row written inside the aborted
transaction goes with it, which is how a run that skipped work ends up looking like a run
that never reached it.

### D7 — Refine's write allowlist: the structural guard behind "cannot touch `content`"

"Cannot" has to be structural, not a test's opinion. Three layers, each independently
sufficient to fail the build:

1. **A module-level allowlist** `_REFINABLE_COLUMNS = ("summary",)` plus the tag arm
   routed through `set_tags`. The `UPDATE` statement is **built from that tuple**, not
   hand-written, and the builder raises `ValueError` on any key outside it. A model that
   returns `{"content": "..."}` therefore cannot reach a column even if the parser were
   sloppy — but the parser also discards unknown keys, so it is refused twice.
2. **The parser returns a closed shape.** `parse_refine` returns a frozen dataclass with
   exactly `summary: str | None` and `tags: tuple[str, ...] | None`. There is no field on
   it that could carry content.
3. **An AST scan over `app/services/memory_dream.py`**, in the style of
   `tests/test_supersede_primitive.py:1365-1397`: no string constant matching
   `UPDATE\s+memories` that also mentions `content`; no `ast.Attribute` assignment whose
   `attr` is `content`; no `setattr(_, "content", _)`; and no `.values(...)` call carrying
   a `content` keyword or a literal dict with a `"content"` key — the same four write
   shapes `_PointerWriteVisitor` enumerates, with its blind spots stated rather than
   implied (a bound-parameter column name is not visible to it).

**The marker write.** `metadata.dream.refine = {"content_sha": …, "at": …,
"summary_sha": …}` rides the **same** `UPDATE` as the summary, in one statement, so a
marker can never record a refine that did not land. `metadata` is JSONB and the param
carries `CAST(:meta AS jsonb)` (invariant 10 — asyncpg cannot infer it).

**Re-run suppression, and why it is keyed on `content_sha` alone.** A memory is refined
only when `content_sha` differs from the marker. Deliberately **not** also when the current
summary differs from `summary_sha`: if T2.13's undo restores the prior summary, a
summary-keyed rule would see a mismatch and re-apply the refine on the next cycle —
silently undoing the undo. Keying on the input alone means an undone refine stays undone
until the memory's content genuinely changes. **This is a hard constraint on T2.13** and is
recorded in §9.2.

**`updated_at` is not restorable.** Every `UPDATE memories` fires `touch_updated_at`
(`0001_baseline.py:205-206`), including T2.13's inverse. So a refine and its undo both move
`updated_at`, and doc 08 §7's "every inverse is a status/pointer/timestamp restore" does
**not** extend to this timestamp. Stated, not smoothed away; §9.2 hands it to T2.13.

### D8 — The near-duplicate edge and the hygiene marker

**One upsert**, no strip:

```
INSERT INTO memory_relations (id, source_memory_id, target_memory_id, rel_type, project, properties)
VALUES (…)
ON CONFLICT (source_memory_id, target_memory_id, rel_type) DO UPDATE SET properties = …
RETURNING (xmax = 0) AS created
```

- `(xmax = 0)` distinguishes insert from update, which is exactly the `created` bit D2's
  inverse needs. Without it, undo cannot tell "delete the row I made" from "restore the
  properties I overwrote", and would delete an edge another pass owns.
- Every param carries a CAST — `CAST(:id AS uuid)`, `CAST(:props AS jsonb)` (invariant 10).
- **No strip-before-rewrite.** The upsert is already idempotent, and stripping is T2.17's
  discipline over the *whole* associative layer. A T2.12 strip scoped to "my edges" would
  be a second, differently-scoped strip that T2.17 then has to reconcile.
- The project on the row is the **pair's** project (both endpoints share it by D3's
  filter); the composite FK makes a mismatch unwritable rather than merely wrong.

**`properties` shape** — one namespaced block, so a sibling pass's keys never collide:

```json
{"dream": {"pass": "near_duplicate", "kind": "duplicate_candidate",
           "hygiene_state": "open", "score": 0.94, "verdict": "duplicate",
           "detected_at": "…"}}
```

`properties.dream.pass` is the discriminator that lets **T2.16** derive its own edges
without either pass wiping the other, and `hygiene_state` is the marker **T2.23** turns
into a queue. I write no queue table, no route, no service — §9.3 names the exact keys so
T2.23 accepts or renames them in one place.

**Why the edge is the right anchor for the hygiene item.** Doc 08 §6 makes the hygiene
queue a `status + partial index` over items including "candidate duplicates (from §5.4)",
and §5.4 says the pair gets an associative edge. The edge *is* the pair, is project-scoped
by construction, and self-heals when either endpoint is deleted (composite FK `ON DELETE
CASCADE`). Any separate item table would be a second representation of the same pair that
could drift from it.

**Undo of an edge is not permanent, by design.** The next cycle may re-derive it. Doc 08
§7 already bounds this — "an action stays undoable until a newer consolidation change
rewrites the same object" — so re-derivation is inside the design, not a defect. But
T2.13 must not promise otherwise; §9.2.

### D9 — Journalling: one uniform stream, and why it does not widen the vocabulary

**Every dream action writes exactly one `record_event(event_type="consolidated",
object_type="memory", object_id=<the memory the action changed>, project=…, payload=…)`.**

- `consolidated` and `memory` are both already in the closed vocabularies
  (`events.py:60, 79`), so **no taxonomy-first amendment is needed**. Doc 08 §5's sequence
  diagram names "refined" as an emission (`docs/design/08-...md:303`), but that is the
  diagram's prose for the action, not a claim about `EVENT_TYPES` — and `consolidated` +
  `payload.action = "refine"` carries strictly more information than a bare event type
  would. Recorded as an observation in §9.4 rather than acted on; widening a closed
  vocabulary for a synonym would be the wrong trade.
- Every payload carries `{"action": …, "before": {…}, "after": {…}, "cycle_id": …}`.
  `cycle_id` is a per-run UUID minted in Phase R, which is what lets **T2.13 group a
  cycle** without joining on timestamps.
- **One row per real transition, never one per no-op.** Skips, refusals and
  `no_change` decisions are counted in the run outcome and logged; they write nothing
  (`supersede.py:288-292`'s rule, applied to my writer).
- **The subsume action's own event is in addition to the primitive's `superseded` row.**
  That is deliberate: the primitive's payload hardcodes `"reason": "status_bridge"`
  (F1, `supersede.py:302`), which is false for a dedup-driven subsumption, and I may not
  change it. So the digest reads *my* uniform stream — where `detector` is `"dedup"` or
  `"status_bridge"` truthfully — and T2.13 is told in §9.2 not to trust the primitive's
  `reason` key.
- `record_event` "degrades loudly but never raises into its caller"
  (CLAUDE.md), so a journal failure cannot undo the transition it describes.

proves nothing. Every negative below is proven the corpus's way — a **differential arm**
(the same fixture builder, one flipped bit, asserting the opposite outcome) plus, where the

**The shared fixture.** Project `p`. Memory **OLD** (`created_at` T0) and memory **NEW**

project `q`, content identical to OLD. A `_StubLLM` in the shape of
`tests/test_verification_judge.py:13-25` returns a scripted verdict per pair and records
every call.

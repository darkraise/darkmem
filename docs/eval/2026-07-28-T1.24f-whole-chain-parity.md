## 6. The prompt-in-disguise audit (ruling 4)

Question: does any pass added or changed by T1.24b–e re-implement a rule the post-strip
prompt (`f59a62d1`) still carries, so the same behaviour is enforced twice and F1 cannot
separate the enforcers? Inventory of every T1.24b–e change to the pass chain, from the
commits themselves:

| Change (task) | Nearest surviving prompt rule | Verdict |
|---|---|---|
| `_NOISE_NAMES += "source"` (T1.24b, `b2dac64`) | rule 2 (generic nouns; does not enumerate `source`) | **Not a disguise.** The bare `source` stem is produced by `_normalize_names`' own suffix strip of "Kafka source connector" — a chain-created artifact the prompt cannot reach, since the model never emitted the bare stem. |
| `_URL_ABSOLUTE_PATTERN` + `www` (T1.24b, `2a743e4`) | none — no surviving rule names URLs | **Not a disguise.** Single enforcement, pass-only. |
| `never use X` negation-verb fix (T1.24b, `11dabed`) | rule 10 (negation cues; kept as partial) | **Not a disguise, but a double-enforcement overlap.** The fix widens the deterministic twin of a kept rule. On this corpus the model already obeys rule 10, so `filter_negation_only` ablates to bit-identical — the pass's contribution is unmeasurable exactly *because* the prompt enforces the same behaviour first. Attribution between the two is impossible by F1. |
| `_rescue_relation_endpoints` (T1.24c, `2d93e43`) | rule 7b (named app surfaces must be extracted; kept as partial) | **Not a disguise — a measured backstop.** The pass and rule 7b are deliberately coupled (`test_every_artifact_head_noun_is_stated_by_the_system_prompt` pins the 21 head nouns into the prompt). **Verdict: no pass added by T1.24b–e is a prompt instruction in disguise.** The prompt
remains minimal in the doc 06 §4 sense — T1.17's audit stripped everything fully
subsumed, and nothing T1.24b–e added re-created a strippable rule. The structural caveat
stands and is now measured rather than argued: wherever a kept rule has a partial pass
twin (rules 2a, 4, 7b, 10, 16a), an ablation zero on the pass is the *expected* result
when the model obeys the rule, so F1 can neither credit nor indict either enforcer — one
more reason the "unmeasurable ≠ zero" distinction is load-bearing. The six pass gaps the
T1.17 audit handed to T1.24b–e (18 missing builtins in `_NOISE_NAMES`, config/CSS tokens,
`CAUSES` synthesis, soft-dependency downgrade, article-phrase rewrite, non-ISO dates)
remain **open** — none of the T1.24b–e commits closed them — so the corresponding prompt
rules stay unstrippable under the ratified policy.

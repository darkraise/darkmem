It nonetheless returned findings that change how this number must be read.

1. THE RATE HAS ALMOST NO REJECTION POWER, AND THIS BELONGS BESIDE IT.
   A system whose true false-promotion rate sits exactly AT the failing bar
   (0.01) passes this audit 56% of the time at n=149 -- P(X<=1 | n=149, p=0.01)
   = 0.5604, verified independently. The exact 95% interval for 1/149 runs to
   an upper bound of ~0.037, roughly 3.7x the bar. "Decidable" is a protocol
   term (n >= 20); it is not a claim that the audit decided anything about the
   system. The harness's own line `false-promotion audit: decidable=True
   clears=True` sits ~40 lines above these caveats and is the quotable hazard.

2. THE DEMONSTRATED STATE CANNOT ARISE THROUGH ANY CAPTURE DOOR.
   `MemoryCreate` carries no `created_at`; production `memories.created_at` is
   the ingest stamp, and `detect_supersessions` anchors its window at ingest
   wall-clock. So three same-claim captures 2-5 days apart CANNOT all survive
   `active` in production -- each ingest retires the previous, which is exactly
   what pass 1 showed. The pass-2 state exists only because the harness
   backdates rows attribute-side. The nearest production analogues are
   different shapes: re-assertions genuinely >= 90 days apart, or a Phase-5
   re-extraction more than 90 days after capture emitting REPLACES edges the
   original ingest missed. Neither is what was demonstrated. Read "operable"
   as instrument-operability only.

3. THE PROMOTION-RATE BUCKETS CONFIRM DESIGN, NOT BEHAVIOUR.
   Every bucket reads 1.000 because the corpus was authored to promote.

4. A HARNESS PREDICATE DID MOVE, AND IT COSTS SOMETHING THE OWNER RULING WANTED.
   See the ledger's G-C subsection: `validate_arming_design`'s new window clause
   makes the supersession-blocked hold structurally unreachable in the arming
   groups for every admissible future corpus. Pass 1 was the first measured
   window in which that hold fired (twice). The owner ruling of 2026-08-13 made
   `blocked = 0` reachable via "a veto OR a supersession-blocked hold"; this
   repair delivers the veto arm and forfeits the other.

5. NO NON-AUTHOR HAS EXERCISED THE LIVE PATH.
   The cache memoises embed/embed_batch/chat_completion on content plus purpose
   config, so pass 2 would have succeeded with both vendors dark. Every model
   output behind this graph -- including the REPLACES edges the arming rides on

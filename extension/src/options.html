darkmem capture

Only http://localhost:8000 works today. The manifest grants this extension network access to that one origin, so a LAN address saves fine and then fails on every capture — the browser blocks the request before darkmem sees it. Reaching a LAN instance means widening host_permissions in the manifest and reloading the extension, which is a deliberate re-grant rather than a setting: a capture extension that could post anywhere is a different trust posture from one that cannot.

Auto-capture (off by default)

Normally darkmem captures only what you select and click. Auto-capture sends every new turn of an AI chat on ChatGPT, Claude.ai and Gemini as it appears, without asking each time. Turning it on asks the browser for permission to read those three sites; until you grant it, this extension has no access to them at all and the switch cannot take effect. Turning it off removes that permission again. While it is on, the toolbar icon carries a REC badge, so the mode is never silent.

Existing messages are not sent — opting in captures the conversation from that point on, not the one you already had. Auto-captured turns carry this install's origin_key exactly as clicked captures do, so a talkative chat cannot make darkmem count one browser as many witnesses.

This install's origin_key is …. It is minted once and never changes: darkmem counts distinct origins to decide whether a claim is corroborated, so a key that changed per session would let this browser agree with itself.
